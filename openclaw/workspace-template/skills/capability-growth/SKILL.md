# 能力生长

这不是第二个规划器。先查现有工具和技能；明确缺口、预期减少的人工步骤、验收和权限，然后复用当前 Workboard 卡片及任务会话。研究方向必须由用户或已有任务目标支持。

## 选择最少改动

- 已有 MCP/CLI：直接使用供应商原生能力，不另写一套业务 API。CLI 可配工作区 Skill。
- 可复用步骤：直接创建/修改受管工作区 Skill，保留说明、依赖和测试，验证发现及实际执行。`skill_workshop` 仅是可选提案工具，不是必经审批。不要覆盖系统或第三方技能。
- 缺少代码：派生当前卡片的有界 Codex 子任务，独立目录/分支实现和测试，保留源码、依赖、测试命令和撤回方式。
- 新模型：修改私有 runtime selection 与原生 provider 配置，不迁移知识库/任务。主控和编程子任务分别选模型。
- 实时监听：MCP 能调用不等于已摄入事件。需要新的持续来源时，按仓库来源契约实现增量、身份和去重，不能在主控里添加厂商分支。

## MCP 接入步骤

让受管 Codex 子任务在仓库根目录使用 `scripts/manage-mcp-capability.mjs`。先读 `docs/operations/capability-growth.md`，不要凭记忆拼参数。

1. 建立候选 JSON，包含 `name`、当前 `taskId`、`purpose`、精确 `tools` 列表和原生 `server` 定义。环境变量引用代替密钥，禁止通配授权。
2. `prepare` 不连接。检查真实服务来源、启动命令、依赖和访问范围。
3. `probe --trust-server` 会运行服务器代码或连接端点，不是安全沙箱；仅对获准服务执行。使用隔离 OpenClaw 配置，不读取正式知识库/卡片/聊天，也不复制 OAuth 文件。
4. `publish` 默认安装为禁用。需要启用时，必须先取得用户对具体工具和范围的授权，并传入对应 Evidence 引用；这个参数是审计引用，不是授权签发器。不能自己制造授权证据。禁止借新工具绕过已有消息 HITL。
5. 发布仅证明配置写入。读取正式 Gateway 新轮次工具清单，再做只读/沙箱业务验收；不要仅凭工具列表宣称业务成功。需要真实发送/写入时走原有授权。
6. 回执写回原卡；失败保留准确错误和下一步，必要时 `rollback`。遇到并发编辑或过期探测重新准备，不强行覆盖。

## Skill 与核心自修改

已授权的本地 Skill 开发和测试不需要再申请通用权限。仅当主动采用 Skill Workshop 时，遵守它自身的提案发布约束。新 Skill 发布后还需加入主控的原生 `skills` 清单，验证新轮次可见及实际执行；模板重应用会保留额外技能。不要以工具列表代替业务验收。

核心源码优化是普通受管工程任务：提出可复现问题，独立改动、测试和审查，按部署授权切换；运行中的 Agent 不能直接改自己的授权、主控规则或发布保护。不要启用另一套后台自主 Skill 整理 cron。

结果可复用时通过现有知识差量流程保存做法、证据和检索位置，不把整段安装日志塞入图谱或下一轮提示。
