## 1. 契约用途

用户结束任务必须区分“确认完成”和“终止任务”，共用确认界面且均可选填说明。完成表示用户确认目标已完成；终止表示不再执行，不生成成功证明，也不删除历史。当前原生 Workboard 无取消状态，终止沿既有操作记录保存明确决定、原卡保留带操作编号的评论并归档，桌面据此显示“已终止”；不得向原生状态或会被丢弃的任意 metadata 字段写入伪造状态。重复提交复用操作编号，不能重复录入知识证据或反转终态。

关闭同步成功后，取消该任务的待复查、条件监听、提醒、未发送草稿和待绑定执行，不影响其他任务、已发出的动作或知识维护队列。已接受的明确关闭决定阻止后续新增执行/跟进和迟到结果恢复任务，读原文、保留结果证据和知识维护仍可进行。正在执行的停止走原生精确 session/run 接口，按关闭时的可信绑定及持久回执复查身份，不以整个会话或任意新 run 代替原执行。卡片已结束与执行已停止分别显示；停止请求、无活动投影和原生合成终态不等于底层清理完成，失败或缺少证明必须显示待确认/未确认并保留原因，不能误报停止。

完成/终止及其选填说明沿既有人工操作链路仅生成一份 Evidence，进入统一知识维护队列；不直接写入可信事实，不把任务状态同步当作知识复核完成。维护可记录结论、原因及相关事实修订，也可判定无长期事实；终止不自动否定已有技术事实。原文、任务归属和操作回执必须可追溯。实现与验收边界见任务完成与终止。

2026-10-29有限采纳范围为已验证的后台/桌面修复包及数据库初始化失败连接清理，详见三项收尾记录。候选应用、Git提交、插件安装和实际宿主加载分别留证；不包含全文索引v5迁移、历史时间语义、长资料消费版本迁移或未完全通过的知识组合实验。

旧图谱补全不得接管已有维护复核或有效租约。知识工具须明确当前Evidence关联和原任务可投递前提，但可投递不等于获授权或业务相关。查询裁剪后的指引必须只引用实际返回入口，输出预算以真实SDK序列化文本为准，不为保留超大入口无故丢弃其他可用短入口。

Workboard评论和证明写入后须按完整内容及身份读回，别人引用操作标记不算原成果仍在。操作最终失败与原任务所有者通知沿既有事务保存，不增第二份任务权威；桌面和只读插件从原操作记录投影回执。迟到详情结果不得覆盖新卡或重新打开的同一卡，刷新不覆盖用户输入。复核显示以规范review_status/outcome为准，完成复核不等于事实可信。

数据库初始化创建连接后，如在交付store之前失败，必须关闭该连接并保留原错误；清理本身失败须保留两个错误，不静默丢失诊断。正常成功后由store持有连接。本约束不承诺全部初始化步骤的跨事务回滚，不改变schema、索引版本或正常初始化顺序。

Gateway监督器的状态文件与诊断日志不是控制权威：状态采用同目录临时文件替换，文件占用或访问被拒时保留告警，不因诊断IO失败退出监督循环。日志失败不保证补写；状态可能暂时保留旧值，健康与进程身份仍须单独核对。此约束不放宽健康阈值、人工禁用、单实例锁、任务/知识持久写入或版本校验。正式采纳及重启后的只读验证见监督器诊断IO部署。

同一事实去重后请求取代自身时，仍拒绝自我取代，但仅有 `self_supersession` 问题的请求返回 `retain_existing_fact`，不新建待人工冲突；既存修订争议不能由重复输入消除。真实跨主体、范围、声明或缺失目标的拒绝不变。旧批次元数据中的已缺失 Evidence 不计入可交付集合；完整来源表仍是权威，不根据预览元数据绕过成员和租约校验。生产数据修复须单独核对，不能用代码修复宣称历史记录已修复。2026-10-26 的部署与记忆核查另见对应评估报告；持久来源登记和工具就绪候选不在本次采纳范围。

历史录音重识别必须保持录音身份、原始时间和音频哈希，按转写版本保存旧原文、人工身份/文字修订和声纹样本；不将重新编号的说话人直接继承为旧身份。当前转写指针和新版 Evidence 在同一事务切换，以独立版本标签防止旧页面误写；推理期间出现人工标注变更时拒绝自动切换。MOSS 输出是待核对的观察，新旧范围关系用 retranscribes 追溯，不当作已确认知识或人工纠正。空结果、部分结果和处理失败分别保存与报告，不把队列耗尽说成全量识别成功。标注页以录音为入口，按时间展示全部人物；单句或当前录音内单个声音组可独立保存，其他人物允许保持未知。详见历史 MOSS 重识别与多人标注。

声纹模板须能独立分页查看、按人物/来源录音查找并按样本ID精确移除，包括旧转写保留的模板。界面按读到的样本版本检查后删除；样本已变更须刷新再选择，已移除的重试不修改其他样本。界面与CLI共用模板操作实现，原CLI显式ID操作保留。删除模板仅影响后续匹配候选，不等于撤销历史人物断言，不修改音频、转写、Evidence、知识或任务，也不生成虚假的身份纠正事件；后者继续通过已有标注纠正链路。来源试听沿既有有界音频读取，不因旧声音组不在当前转写中而失去原录音入口。本条为源码契约，正式窗口加载与部署另行验收。

人员与声纹管理使用同一人物入口：点击人物直接展示其样本，按人物ID筛选而非姓名匹配；同名和无样本人物不能回退为其他人的结果。全部样本、人员切换、来源试听与精确移除仍共用既有样本接口，不增加人物或模板的第二份权威。管理窗口不切换正在标注的录音，不覆盖未保存的人物选择与登记勾选；窄窗同样保留人物入口。本项为用户新增界面请求，不恢复已结束的持续优化目标。

语音人工复核的试听与声纹登记必须独立：未知或多人声音允许播放完整原录音及选定文字段，并支持定位、暂停与继续；不能以声纹样本的短试听限制截断复核上下文。读取和IPC传输保持有界，通过准确采样偏移续播，不一次展开长录音。试听不新增标注、样本、事实或任务。已有逐段标注只覆盖已存在的段落边界，不能宣称能自动拆分段内换人或重叠说话；混合段未拆分前保持身份未确认，不当作单人样本。相关验收与尚未闭环的手机接收回执、双端接管分开记录，见录音链路与试听复核。

2026-10-24收口决定见正式候选与实验归档。正式检索保留精确定位、词法/图谱入口及Agent自主回源；本轮未采纳的向量融合、候选多样性和正文共享呈现实现在独立实验分支保留，不进入main运行入口。通用调查、知识维护及任务回归工具仍保留，不能因拆除实验而丢失验证能力。源码合并、正式安装、数据修复和后台生效分别验收。

新信息默认要求可靠交付与实际读取，由Agent决定继续、调整或重新规划，不要求每次变化立即中断已执行的工具或旧方案。主控工具边界同轮读取与编程子执行器同会话续轮读取须分别报告，不能把排队说成已读，也不能把未读取时继续旧动作说成Agent读后选择。明确取消仍走现有取消语义；所有者、执行身份、版本和迟到结果保护不变。历史即时采用判据和负结果保留，但不再作为普通新信息处理的默认发布阻断项。

连续信息验收必须分别保留原始发生时间、实验或渠道到达时间、源会话路由、任务/知识维护实际读取和后续决定的依据。后到内容不能预先装入初始上下文，旧Evidence重新通知不算新原文到达；分批读取按原ID、来源会话及准确正文范围核验，不能把分页误判为未读，也不能借其他会话的读取回执证明当前消费者已读。采用与否仍须审核实际后续任务结果和知识引用，工具成功或机械范围覆盖不代替语义正确。实验暂停必须在宿主保护时限内有效释放，过期标记不得证明任务仍处于该工具边界；此暂停只用于因果测量，不增加生产超时或强制中止规则。真实多人员、真实跨渠道与合成通道测试分别报告，缺原始材料时不得更换来源标签充数。见连续信息验证。

任务增量的批量ACK只消费处理回执，不恢复早期行动方案。同一批事件均已获得applied检查点、拥有相同任务所有者/绑定/观测执行且仍在有效租约内时，允许其连续版本一起覆盖到当前检查点；不能要求每一条都等于最后版本而迫使重复处理。缺失中间回执、批外独立新决定、错任务/身份/绑定或不相关执行变化不得借批量ACK绕过。最新单条也拒绝显式过期或无效的租约时间；原无到期字段记录不在本轮迁移。当前执行可以是检查点观测的原执行，也可以是该applied检查点明确安排、随后实际绑定的精确codex_run，不认可任意新run。检查和知识库内消费同事务，分页原文覆盖、原生续轮凭证、outbox及迟到结果保护不变；该事务不声明跨Workboard数据库的并发快照隔离。

本文件定义 Shadow Agent 长期演进时不得破坏的产品边界、架构责任、数据权属、主动工作方式、安全边界和验收规则。它解决的是“项目规模扩大后仍然是同一个系统”，不是某一次实现的说明书。

长期委托与能力扩展按 [ADR-0036](decisions/0036-delegation-and-native-capability-growth.md) 执行：主控模型与编程执行器独立配置；原生 MCP/CLI/Skill 保留应用语义，统一证据、授权和结果回执。扩展不得自行扩大权限或直接改运行中的核心；不得为能力接入另建任务库或规划主控。长期目标复用现有卡片和稳定会话，是否推进由主控结合证据与价值决定，不以固定复查周期代替判断。能力连接、配置安装、运行时可见、业务验收是不同证据等级，未通过的阶段不得宣称成功。

行动方案属于现有任务检查点的有界、可修订判断，不是新的任务权威或授权来源。检查点携带可复用结果时，必须和知识差量原子保存，失败整体回滚；知识可信度仍由既有维护流程派生。常驻提示不得因为新架构而突破 20,000 字符；详细工作步骤按 Skill 渐进读取，不加载全部任务方案。

既有本机 Skill 可经用户授权通过 OpenClaw 原生 `skills.load.extraDirs` 及主控可见名单直接引用，不要求为使用而复制或重新通过 Workshop 创作。引用保留原目录和相对资源，不能把加载可见等同于业务执行通过，也不扩大外部写入、设备操作或凭据访问授权。当前接入与刷新证明见 本机 Codex Skills 引用；新编写或修改的候选仍遵循原有能力发布流程。

运行时边界按 [ADR-0038](decisions/0038-owned-policy-and-task-boundaries.md) 执行。身份、行为、记忆与推进语义由 Shadow Agent 定义；OpenClaw 保留会话、工具、模型和原生执行设施。`shadow-policy` 替换框架主提示，按可信会话角色提供规则，不以用户消息决定角色；活动工作区 SOUL/IDENTITY/USER 不参与主策略注入。通用协作规则固定来自代码库 `COLLABORATION.md`，不读取运行目录中的个人偏好文件。Workshop 是可选工具，已授权本地 Skill 开发/验证不强制走提案发布。原生工具协议和受保护外部动作的授权不因提示替换而取消。

可发布的 AGENTS、协作约定及策略模板必须保持用户无关，不写入开发者个人姓名、组织、职责、项目或业务背景。个人事实、偏好与职责变化走各用户私有 Evidence/知识图谱，按当前问题检索，而不是固定注入完整档案；检索资料不自动获得指令或授权效力。系统身份说明不应声称当轮使用了未调用的知识检索，不将本项目选择的架构分工说成其他产品的能力上限。知识维护会话只可确认自己租用的增量，不能因此取得业务卡片控制权。

知识维护权限验收应覆盖领取、知识复核和增量确认的完整工具链，不以角色守卫单测或模型终答替代持久状态读回；上游模型 429 与权限拒绝分别记录。真实队列恢复证明见 知识维护增量确认恢复验收。

同一来源、身份及正文的重复录入不得覆盖已有维护摘要、检索提示和复核详情，包括 reviewIdentity、reviewVersion、理由及事实引用；已完成或待补充的复核结果均须保留。来源标题或显式 projectKey 确有变化时，同步 Evidence 与检索入口的对应字段，不重置复核，也不据此迁移已有事实的语义作用域。来源采集的重复投递不是重新复核指令，显式知识复核继续通过原维护入口；真正的新正文仍正常进入维护队列。重开/重放验收须在应用初始化前只读核对持久数据，区分空闲服务重开、处理中断恢复、常驻自动唤醒与正式部署，不用启动修库或再次模型复核掩盖数据丢失。

自动唤醒的隔离验收须由现有 daemon 自行路由、租用和启动维护会话，测试驱动仅负责输入、观察及停止。逐条对应 Evidence、change seq、会话、租约、实际 run 与终态，不能借上一轮成功回执证明当前轮完成；知识语义、引用与复核另行读回。启动积压、运行中兜底轮询和渠道即时通知分别证明，不把轮询成功写成实时送达。实验配置、采集根、输出/临时目录、原生凭据存储须独立；停止或某个清理步骤失败仍须尝试其余清理并显式报告失败。这是验证约束，不新增生产任务状态或强停机制。当前证据见 G1自动唤醒节点。

非规范性验证状态：截至 2026-10-22，知识底座尚有来源复核状态错配、读写规则不一致和原文件定位缺口，详见 知识图谱底座实测。常规回归通过不构成这些边界已满足的证明；本条记录验证发现，不改变既有契约，也不表示已完成修复。

逐包进度见 知识可靠性、降噪与混合检索实施计划及首批实现验证。源码修复、隔离验证、正式库修复及部署分别登记，不因测试通过而自动授权生产迁移。

非规范性检索实验状态：已实现独立的本地嵌入/词法/RRF 对照探针，见语义检索首轮结果。当前只证明实体入口召回有收益，并发现等权融合退化；没有接入正式查询或改变事实可信、职责和任务状态。旧夜间执行已结束，2026-10-23新授权按每小时执行单继续验证，不以实验代码存在宣称正式架构已经采用向量检索。

H1路标投影实验仅派生检索索引：来源必须沿显式关联、保留Evidence/原件位置，并区分未取代历史和当前分支事实。标题命中不能提升可信状态或证明部署；新增线索与原语义摘要保留可追溯边界。词法/向量比较须使用相同投影、固定题目/模型并保留部分召回退化，不以总Hit改善替代回源和回答验收。当前没有正式索引同步、迁移或摘要回填，见同条件回归。

**检索服务与任务调查的完成边界**

搜索模块提供精确依据或可继续调查的入口，不承诺自然问句首轮100%召回。精确ID/SHA/路径不得由相似对象替代；较宽入口须有可解析定位及相关范围。图谱不必预存所有源码/提交细节，Agent沿仓库、文档或会话入口补查是正常工作，不因索引未命中直接认定资料不存在。

Agent按任务需要自主改写查询、展开关系、查文件/Git、读取必要原文或提出澄清；不为此增加前置规划模型、固定次数或领域关键词流程。只提供候选/建议并不等于完成，只有获取足够且适用的证据、形成所需答案/产物，才满足相应验收；明确交付的任务还需核对原卡及执行结果。正确说明缺口单列，不充当已完成正向任务。

验收分别记录首轮命中、入口采用、补查路径、证据充分性、答案/任务结果及整轮成本；索引未给精确位置但Agent成功查明可计任务成功，不能回填成首轮命中。原文只需读取支持判断的必要部分，不以全文读完或工具成功替代语义核验。正确版本、时间、范围、证据追溯和已有权限边界不因接受宽入口而放松。

用户输入去重与机器复查聚合是两种行为：前者须有相同任务和操作身份，不能仅因文字相同就隐藏独立输入；后者按可核验的实质变化折叠展示，保留审计原件，不以摘要措辞相同作为充分条件。不能为降噪另建任务真相源或要求模型复制一套完整业务状态。任务会话默认采用进展投影：仅聚合既有检查点明确声明无变化、同一任务/执行绑定且连续的复查，人工输入、失败、真实进展、未知格式或后续动作变化均保留。分页/刷新按原事件身份合并；聚合项可按精确事件 ID 展开原件，不能充当新的事实来源。当前已接入源码视图并通过四卡真实历史回放；不等于全历史、安装包或生产部署验收。

按 [ADR-0039](decisions/0039-personalization-boundary.md)，认知初始化不得隐式选择开发者档案：团队资料导入要求显式来源、本人身份和稳定档案标识；工作简况导入要求显式文件与现存证据，默认 dry-run；标记为示例的文件不得原样写库。部署路径来自本机配置或 PATH，不固化开发者盘符。既有私有证据及 Git 档案不会因此被删除；公开发行必须另行筛选制品，不等于公开本仓库。

同一私有 Agent 的会话可见性为 `agent`，不是 `all`，也不代表混合上下文。任务会话可按需读相关卡片和历史，只能更新自己绑定的卡片、续写其当前受管执行；用户自己的 Codex 会话仍只读。该规则由工具入口及 checkpoint 的可信 runtime ctx 校验落实，不仅靠模型传入的 sessionKey。系统级本机高权限仍不是对恶意代码的操作系统沙箱。

checkpoint 使用单调版本、当前 owner generation 和执行快照。版本变化时保留迟到结果的 Evidence/学习，但不覆盖新进展，不以 evidence-only 回执 ACK 当前事件。终态不接活动 continuation，迟到 outbox 绑定必须再次核对版本和当前执行；执行绑定不顺带改变业务状态。Workboard 不迁库、不双写。本轮不宣称跨库写入有原子 CAS，极窄竞争窗口保留为明确限制。

必需策略未加载或被覆盖时必须在模型调用前报 `SHADOW_POLICY_NOT_APPLIED`，由可靠事件/回执恢复，不退回框架人格、不误报为缺少用户授权。OpenClaw 的 prompt hook 原本 fail-open，故保留版本与结构校验的窄运行时补丁；升级不匹配应停止启动并重新验证。旧会话在下一安全轮次接收新规则，不重置业务 ID、不批量删历史、不通过变更 Context Engine fingerprint 强制重放历史。在途运行不因这次更新被强杀，部署证明须单列。

第三方 MCP 的连接、工具目录、配置投影和账号业务读取必须分别验收；桌面 Codex 的 MCP 配置不自动等于主控已接入。工具普通文本中的 HTTP 错误及空正文不得被当作成功证据。验收须覆盖工具发现后的标准客户端调用及带编号的目标详情，不能只测列表；外部工具 Schema 与真实输出不一致时在该应用接入边界修正，不让主控绕过协议校验。授权窗口须区分登录失败与本机保存/权限失败，不得因后处理异常要求用户反复输入密码。已授权的精确只读工具可配置免逐次审批，但不得因此放开其他写操作；鉴权恢复并通过目标读取后，在原卡片和稳定会话继续。禅道部署与故障证明见 禅道 MCP 接入。

主控供应商切换使用原生鉴权和独立运行配置，不建立第二套记忆库。共享 Evidence、知识图谱、任务卡和来源游标，不等于共享模型缓存、原生执行线程或保证推理效果相同。已有活动执行先取得检查点，不强行改绑；切换验收必须包括真实模型调用、工具续聊和原库查询，配置校验不得冒充运行成功。API Key 不进入源码、Git 或进程参数，失败保持或回退到已验证配置。DeepSeek 接入步骤见 主控模型切换。

系统级本机权限按 [ADR-0037](decisions/0037-system-wide-local-access.md) 执行：用户已授予 Agent 在当前 Windows 身份下跨项目的文件读写、目录发现和命令执行权限，不再要求按项目或模型后端分别配置。OpenClaw 全局工具/执行策略是配置来源；执行器权限自动派生，模型选择不得改变授权。主控及新子运行必须通过真实文件与命令测试验证权限继承；历史子会话保留的受限清单不算新策略生效，需在原卡片上保留执行历史并新建执行轮次。不得把缺工具误报成缺目录、缺业务信息或要求用户重复授权。

系统高权限不等于 Windows 管理员权限、第三方账号授权或对任意业务动作的委托。飞书 HITL、用户 Codex 会话只读监督和任务归属规则保持；任意本机命令可触达当前用户资源，故 HITL 仅是受控出站链路的保证，不是对高权限进程不可绕过的隔离沙箱。不得读取无关秘密或自行取消用户设置的业务确认。安装配置、运行工具可见和实际执行成功是不同验收层级。

来源摄入必须在后台实际身份和启动环境下验收；交互命令成功不能替代后台成功。停止操作必须允许后台已经退出的空进程集合，重复停止不能因空集合而报错或遗留禁用标记。相关实现与未完成部署项见 [ADR-0035](decisions/0035-intake-and-review-recovery.md)。

后台补授权必须使用正式服务同一 Windows 用户和启动环境，经官方 OAuth 流程完成；不得复制明文令牌、扩大无关权限或更改人工审核发送策略。登录后必须验证个人身份及真实只读业务请求，具体操作见 [后台授权验收](operations/feishu-background-auth.md)。
参数错误、网络失败和鉴权失败必须分别诊断，不因业务请求参数错误要求用户反复登录。历史补采未到末页时，即使健康状态已恢复，也不得宣称覆盖完整或全部业务任务已处理。

文中的“必须”“不得”“应当”“可以”具有规范含义：

- **必须/不得**：架构不变量。违反时不得合入或部署，除非先修订本契约。
- **应当**：默认要求。偏离时必须在设计决定中说明理由、范围和退出条件。
- **可以**：允许的实现选择，不构成长期承诺。

发生冲突时，优先级从高到低为：

1. 用户对当前操作给出的最新明确指令。
2. 本项目契约。
3. 已批准且未被取代的架构决定记录。
4. `ARCHITECTURE.md` 和领域设计文档。
5. 运维文档、插件说明和运行工作区提示词。
6. README、代码注释、历史文档和运行快照。

架构决定不得暗中覆盖本契约。需要改变契约时，必须先升级契约版本并说明迁移方案。

## 2. 产品定义

Shadow Agent 是一个本机优先、证据驱动、能够主动巡查工作的长期工作代理系统。它持续理解用户的职责、项目、任务、决定、文档和执行证据，在不制造忙碌、不越过授权边界的前提下发现并推进真实工作。

系统必须具备以下长期能力：

1. 增量收集 Codex 会话、项目文件、Git、人工输入和已授权外部来源。
2. 把原始材料保存为可追溯证据，并生成可检索、可修订的长期知识。
3. 维护用户长期工作简况，但不把简况变成第二个任务列表。
4. 从真实未完成任务和新增变化中选择最重要、最临近明确截止时间的事项。
5. 使用 OpenClaw 主动唤醒和调度，必要时调用 Codex 完成推理、编程和验证。
6. 通过 Workboard 保存唯一任务状态，通过宠物界面展示并接收人工反馈。
7. 对外部写入、审批、提交、部署、设备控制等动作执行明确授权策略。
8. 对直接消息、群聊中明确提及、审批/任务变化等外部事件及时响应，并持续跟踪同一会话和任务。
9. 保存显式提醒和有明确来源的截止时间，在到期时通过宠物和主控进行可审计提醒。
10. 以用户身份可见的个人消息、文档、任务和审批作为飞书工作认知主来源；机器人会话只作为可选交互入口。
11. 对等待回复、状态变化或外部结果的事项建立持久条件跟踪；新增证据只产生候选，由唯一主控作语义确认，并保留超时兜底。
12. 以稳定工作会话延续真实对话和项目上下文，达到压力阈值时使用 OpenClaw 原生语义压缩和 transcript 轮换。
13. 只长期保存稳定事实与认知路标；需要细节时知道去哪里查代码、文档、会话或系统。
14. 遇到未知问题时形成可执行的求知路径；必要时生成向责任人询问的草稿，经统一出站链路授权、发送并持续跟踪回复。
15. 把任务、会话、人工指令和执行结果通过稳定会话归属与因果事件连接起来，使 Agent 能持续理解状态变化而不依赖界面进程记忆。
16. 主动监督获准执行：把工作交给 Codex 后接收完成事件、按验收标准复核并给出下一步；向飞书发出问题后跟踪真实回执与回复，直到任务获得证明、明确阻塞或需要用户决定。
17. 把“业务相关”和“由用户承担结果责任”分开判断；只为具有正向归属依据的工作建立用户任务，并把他人工作保留为背景、依赖或风险证据。
18. 条件回复只提供新事实；主控必须回到原任务目标，记录事实改变和结构化后续动作，不能用“继续等待”替代结果推进。
19. 对没有新事件但已到复查时间的活动任务执行有界进度审计；每次只唤醒少量明确卡片，由同一个主控核查变化并推进结果。
20. 用脱敏、隔离、按用途分层的真实工作数据持续评估触发、归属、回复和推进质量；优化结论必须有冻结验证集或盲测集支持，不能以结构化输出成功代替语义准确。
21. 把人工输入和已解决任务的可复用结论统一转为不可变知识证据与差量事件；解决结果通过 `shadow_knowledge_delta_capture` 提交，由稳定知识维护会话查重、更新、取代或补链，避免新知识只追加不维护旧关系。
22. Agent 管理的 Codex 会话标题必须是有界、可检索的短语义标题；不得把 assembled context、完整 transcript、工具轨迹或证据包复制到线程标题。原始首次输入和 rollout 保持不可变，标题修复不得冒充内容删除。每个会话只保留一代可检索摘要快照；被长期事实直接引用的旧摘要可以降为不可检索归档证据，其余旧代必须物理清理。摘要标题必须有硬上限并保留 `thread_id`、短语义主题、分块编号和来源定位。
23. 以可替换来源适配器扩展企业协作平台和编程 Agent：底层共享证据身份、游标、幂等和回源定位，中间分别使用 Collaboration 与 Execution 规范记录，最终只在任务、决定、承诺、产物、人员、项目和知识层汇合。

### 2.1 核心资产与本轮优化边界

核心资产是可修订、可追溯并能影响后续判断的记忆，以及能核对结果、处理变化和持续执行获准下一步的推进能力。系统成功以真实结果、纠错有效性和减少人工重复解释衡量，不以卡片数、图谱规模或模型调用次数衡量。

当前优化顺序及已知偏差见 记忆与持续推进可靠性优化计划。分级推理与第一批通用可靠性修复已完成源码和隔离测试；其余工作及线上验收分别标注，不将目标架构冒充当前实现。

首批 Bug 跟踪、工程交付、职责纠正是验收样本，不是限定开发范围。实现必须适用于不同项目和任务；不得据这些样本建立专用业务分支。样本通过不代表系统整体成熟。

运行结果必须以原生运行终态为依据。中间回复、请求已接受、等待超时或缓存的 `running` 均不能作为成功或失败证明；失联时保留同一次运行身份和原事件租约，先核对再决定下一步。原生运行完成也不等于业务验收完成。

人工输入和飞书对话成功还需最终可见回复；后台控制唤醒允许运行时明确返回 `silent`，但缺失/空白回复不能推断成功。回执按稳定请求保存少量元数据，活动指针与回执原子更新，不复制对话或逐轮扫描历史回执。

活动执行必须具有下一次观察时间，到期只进行原运行核对，不终止长任务、不新开重复执行。进度复核的等待队列不占用实际执行额度；只有有效租约计入占位，过期租约可以恢复而不得吞掉原事件。详见 [ADR-0032](decisions/0032-memory-and-execution-reliability.md)。

推理等级按已有任务类型配置；不得另建模型来做简单等级路由，不得由紧急程度或关键词直接推导更大推理预算。复杂工程推理可以通过原生子任务能力显式提高等级，但不得因此扩大权限、复制完整上下文或新增任务主控。

用户主动暂停或退出不属于调度故障。修改模型、配置和文档不得隐式恢复巡检或启动积压任务；暂停期间的积压不用于推算故障率。

## 3. 非目标

以下内容不属于本项目的基础职责：

- 不重新实现一个与 OpenClaw 并列的通用 Agent Runtime。
- 不为日报、版本、会议、人员等每个业务领域各建一套数据库或主控逻辑。
- 不把所有历史材料一次性塞给模型，也不通过固定条数 FIFO 代替任务判断。
- 不让宠物界面、知识图谱、飞书采集器或旧数据库表成为第二任务主控。
- 不以关键词命中直接宣布事实、归类任务或判定影响。
- 不承诺在锁屏、休眠、断网、未登录或权限不足时完成依赖交互界面的操作。
- 不把模型名称、供应商版本或单台机器路径固化为产品身份。
- 不为模型额度耗尽另建规则引擎、关键词控制器或无模型语义降级链路；模型运行时可用是产品执行语义工作的前提。
- 第一阶段不包含持续麦克风监听。未来接入语音时也必须进入相同的证据、权限和任务契约。

## 4. 角色与责任

### 4.1 用户

用户是系统最终责任人和授权主体。用户可以确认现实完成、纠正事实、补充下一步、授予或撤销长期授权，并可要求删除或隔离个人数据。

### 4.2 Shadow Agent

Shadow Agent 是产品身份，负责理解工作、选择注意力、维护上下文、推进获准工作和向用户说明结果。它不把自己描述为 OpenClaw 或 Codex。

### 4.3 OpenClaw

Shadow Agent 是唯一主动主控，当前运行于 OpenClaw。业务身份、授权语义、记忆和结果推进由本项目定义；OpenClaw 提供会话、模型调用、工具执行及恢复设施。周期 Heartbeat 是可选故障兜底，不是主工作入口。

系统中不得出现第二个长期运行的本地规划器、第二套巡查决策器或另一个可以独立创建和推进任务状态的主控。

### 4.4 Codex

Codex 是推理和工程执行引擎。OpenClaw 在需要理解复杂材料、补全知识关系、修改代码、测试或生成文档时调用 Codex。Codex 可以在一次获准执行中自主完成多步工程工作，但不拥有独立于 OpenClaw 和 Workboard 的长期任务队列。

OpenClaw 发起的 Codex 子任务属于 Agent 管理的执行会话：完成、失败和超时必须回到原控制会话复核。用户自己创建的 Codex 会话默认只是可读取的证据来源；除非用户明确交给 Agent 管理并绑定到一张 Workboard 卡，主控不得静默追加指令或中断该会话。

模型和思考等级是运行配置，不是项目契约。当前值必须从 OpenClaw 运行配置与网关启动日志读取，不得写死在架构判断中。

### 4.5 上下文服务

上下文服务只负责确定性采集、事件接入、去重、摘要队列、图谱物化、索引和运行状态。它可以把已授权外部事件转交给 OpenClaw，并按明确出站模式把 OpenClaw 生成的消息持久化到统一发送链路；它不得自行规划回复、判断“下一项做什么”、创建或推进规范任务状态，或绕过出站记录直接执行外部写入。

### 4.6 Workboard

Workboard 是活动任务和任务生命周期的唯一真相源。任务标题、状态、优先级、执行关联、证明、评论、依赖和历史都以 Workboard 为准。

### 4.7 宠物界面

宠物界面是 Workboard 和运行状态的投影，也是人工确认、补充和查看证据的入口。它不得保存独立任务副本，不得通过显示截断改变统计含义。

主界面分为“主对话 / 工作”。主对话保留长期问答和任务链接；每张卡进入独立任务会话，默认展示连续交代、答复和结果，底部输入框常驻。概览、执行记录、证据是辅助视图。聊天记录从已有回执、Evidence、操作事件、检查点及 Workboard 评论分页投影，不建立第二份任务或模型历史。详见 [ADR-0033](decisions/0033-main-and-task-conversations.md)。

### 4.8 外部系统

飞书、腾讯文档、Git 服务、设备、文件系统和未来语音输入既可以是证据来源，也可以是动作目标。读取权限不自动推出写入权限，某一产品的写权限不自动推出另一产品的写权限。

飞书必须区分用户身份与机器人身份。`user` 身份读取用户本人可见的消息、文档、任务和审批，是工作认知主链路；`bot` 身份只接收发给应用机器人的消息并在该机器人会话中回复，是交互入口，不得冒充用户收件箱或个人文档来源。任务、审批的用户事件只是主链路的实时加速器；事件订阅未生效时必须保留 API 增量补偿，并将其报告为能力缺口而非系统离线。

飞书是当前企业协作适配器，不是系统永久唯一的协作模型。未来钉钉、企业微信、Slack、Microsoft Teams、Google Chat 等来源必须复用 Collaboration 领域的会话、内容、工作和组织语义，同时保留各自认证、权限、线程、卡片和资源格式。不得把其他平台事件伪装成 `feishu_*` 类型。

Codex 是当前编程执行适配器和工程执行引擎，不是所有编程 Agent 的持久格式。未来 Cursor、Claude Code、TRAE、Windsurf、GitHub Copilot CLI、Cline 等来源必须复用 Execution 领域的会话、回合、工具、产物和状态语义；模型供应商只作为执行元数据，不因使用 DeepSeek、OpenAI 或 Anthropic 模型而建立新的会话来源。

### 4.9 运行前提与短时离线

Shadow Agent 执行语义理解、任务判断和对外内容生成时，以已配置模型运行时授权有效且额度充足为前提。额度耗尽、账号失效或模型服务不可用属于运行故障，不是业务语义；系统必须暂停依赖模型的推进并明确显示故障，不得因此由宠物、正则表达式或后台脚本代替 Agent 判断任务含义、关闭任务或发送消息。

进程重启、网关短暂离线、网络闪断和外部接口瞬时失败必须由可靠投递保护。Agent 相关事件应先持久化，再尝试唤醒或执行；失败时保留原事件、租约、重试时间和幂等键，恢复后继续投递，直到 Agent 确认或进入可见的永久失败状态。短时离线保护只保证“不丢、不重做副作用、可恢复”，不产生第二个语义主控。

## 6. 规范数据模型

### 6.1 原始来源与证据

`sources` 保存来源身份、游标、最近状态和错误。`evidence` 保存从来源读取的原始事件或有界片段。

`source_observations` 保存供应商、领域、对象、事件、流、因果、可见性和回源引用；`collaboration_events` 与 `execution_events` 分别保存企业协作和编程执行的结构化字段。三张表只引用 `evidence_id`，不复制正文。已注册来源的采集事务必须同时写入对应规范记录；来源存储版本升级采用备份后一次性切换，不保留旧视图或双写兼容期。

证据必须：

- 具有稳定指纹或外部 ID，以便幂等采集。
- 保留来源定位、采集时间和可获得时的发生时间。
- 在正常运行中只追加，不被摘要覆盖或静默改写。
- 在内容过长时保留可回查源位置，而不是假装截断内容等于原文。
- 不保存凭据、Cookie、原始 OAuth Token、SSH 私钥或系统凭据文件。

“不可变”表示正常知识更新采用追加、取代和状态迁移。因隐私、法规或用户明确要求执行删除时，必须记录范围、原因和结果，不能通过伪造空证据掩盖删除。

### 6.2 知识召回卡

值得长期召回的证据可以生成知识召回卡。召回卡必须保留 `evidence_id`、内容指纹、摘要、关键词、可回答问题、作用域和显著性。

摘要用于候选召回，不替代原文；关键词用于找到候选，不直接决定实体同一性、任务归类或事实真假。

召回结果必须区分可用事实、候选事实、冲突和检索路标。Episode 的 `review_status` 与 Fact 可信状态相互独立；复核完成只表示已记录语义结果，不代表事实可信。已过期、被反驳或仅有失效证据支持的内容不得进入“已知事实”；争议事实只能作为冲突呈现。

### 6.3 时序知识图谱

图谱使用开放世界模型：Entity、Activity、Agent 是顶层语义，领域类型和关系可以扩展。未知词汇可以先以 learned 类型或关系登记，不得因词表未命中而丢弃知识。

事实至少包含主体、关系、客体或字面值、认知状态、置信度、有效时间和观察时间，并满足以下至少一项：

- 关联支持或反驳它的原始证据及证据画像；仅提及主体或客体的材料写入实体证据关系。
- 关联一个可展开到已有事实的推导链。

模型推断默认是候选，不得伪装成已验证事实。新材料与旧事实矛盾时必须保留冲突，不得仅因材料更新而静默覆盖。

人工纠正通过追加新 Evidence、建立 `supersedes`、失效旧召回卡并重算失去支持的事实完成。不得原地覆盖旧证据，也不得因一份证据被取代而误伤仍有独立有效支持的事实。

事实可信状态由当前未失效的证据评价集中计算：只有 E2 及以上支持且不存在未解决矛盾时为 `supported`；支持与反驳并存时为 `disputed`；只有 E2 及以上反驳时为 `refuted`；其余为 `proposed`。查询层可以把符合额外范围和时效条件的事实展示为 verified，但不得把 `verified` 持久化成第五种状态。

### 6.4 增量变化

`context_changes` 是 OpenClaw 消费的新变化流，不是任务列表。变化必须具备幂等事件键、稳定会话键、可处理时间、优先级、状态、租约和确认结果。

处理协议固定为：

1. 只领取当前稳定会话的有限批次并建立短租约。
2. 使用变化自带的局部图上下文判断是否可行动。
3. 有持久结果后确认 `processed`。
4. 无行动价值时确认 `ignored`。
5. 只有瞬时失败才使用 `deferred` 并允许重新领取。

不能把“队列中有变化”直接显示为“用户有同等数量的待办”。

### 6.5 长期工作简况

按 [ADR-0040](decisions/0040-user-knowledge-projection-and-onboarding.md)，个人简况和私有 `USER.md` 由同一个图谱投影生成器读取当前本人事实生成，不再允许 `work_focus_profiles` 独立保存职责正文。每条带事实/证据引用、可信度和有效范围；新相关事实、修订、冲突与时间失效都必须反映到下一次读取。Workboard 和授权配置仍各自是任务与权限权威。

冷启动要求最少身份、职责/排除项和首个目标，经用户预览确认后走现有 Evidence/图谱导入。已有用户从明确本人实体迁移，旧简况作为待复核证据保留，不隐式升级为可信事实。资料不完整不阻止明确交办，但不得猜测外部任务归属。模型每轮只读取有界当前投影，不注入完整档案、不因个人资料更新轮换原生线程；人工修改 USER.md 作为修订输入进入同一个维护流程，不建立双向独立主数据。

简况缺失时先呈现已知事实及缺项，不得为填满模板猜测事实。新材料通过知识维护改变图谱，简况版本由当前事实、证据、冲突及有效范围派生；普通日志和无关入库不触发版本变化。风险、等待和任务进展读取 Workboard，不在个人简况另存一套。

用户确认基本资料及软件/资料范围后，初始化计划进入既有可靠任务入口，建立用户补充/授权卡与 Agent 调查卡。未选来源不得全盘调查；授权卡不保存凭据。入队不等于建卡或调查完成。重复确认返回同一回执，不重写事实或重复建卡。

### 6.6 任务关注覆盖层

`work_task_attention` 只保存 Workboard 卡片的明确截止时间、人工置顶、重要程度、业务影响、项目键、证据引用、控制会话以及下一次结果复查时间。它不得复制任务状态。`next_review_at` 是内部复查调度，不是业务截止时间；两者不得混用。

截止时间只能来自：

- 用户明确输入。
- 飞书任务或其他权威任务字段。
- 文档中的明确日期。
- 规范化 `ddl` 或 `deadline` 标签。

计划启动时间、创建时间、更新时间、日报日期或模型猜测都不等于截止时间。

### 6.7 Workboard 任务

规范状态含义如下：

| 状态 | 含义 |
|---|---|
| `backlog` | 新发现但尚需用户确认是否接手，或明确延后的历史事项；不等同当前待处理 |
| `todo` / `ready` | 已确认的活动待办，可以参与工作雷达 |
| `scheduled` | 已安排启动时间，未必存在截止时间 |
| `running` | 正在执行，必须关联执行或会话证据 |
| `review` | Agent 认为执行已完成，但现实结果仍需用户确认或授权 |
| `blocked` | 存在明确阻塞，必须记录阻塞原因和解除条件 |
| `done` | 已获得足够完成证据，或用户明确确认现实已完成 |

任务生命周期规则：

- 新发现的工作先去重，再更新已有卡片或创建一张规范卡片。
- 同一目标的补充下一步默认更新当前卡片；只有用户明确要求或工作确实独立时才创建关联卡片。
- 现实世界结果无法被机器证明时，Agent 只能进入 `review`，不得自行标记 `done`。
- 用户确认完成是新的任务证据；必要时还应把具有长期价值的决定或结果追加到知识图谱。
- `done` 可以因新证据重新打开，但必须记录原因，不能抹除原完成历史。
- `backlog` 不进入“当前待处理”统计，除非被重新激活。
- `todo`、`ready`、`running`、`review` 和 `blocked` 在主控处理后必须留下明确的继续条件。Codex 子任务使用运行完成事件，外部沟通使用条件跟踪，时间性复查使用提醒；不得依赖无目标的周期全表扫描重新发现它。
- 后台可以用不调用模型的有界进度审计检查继续条件是否缺失或到期。审计每轮最多选择配置上限内的卡片，为每张卡写入幂等 `task_progress_due` 变化；模型只收到被选中的卡片，不接收整个 Workboard。
- Agent 管理的 Codex 子任务必须把 run id、child session key、实际模型、验收标准和结果证明关联到现有卡片。`sessions_spawn` 返回后由同一任务检查点产生可靠绑定动作，写入 Workboard 原生 execution、session 和 run 字段；不同活动 run 不得覆盖，同一 run 重试必须幂等。子任务成功退出只表示执行结束，不自动证明业务目标完成。

任务状态的决定来源固定如下，执行器只落实已经形成的决定，不因此成为第二主控：

| 输入 | 决定者 | 确定性执行 | Agent 后续责任 |
|---|---|---|---|
| “确认已完成”等结构化按钮 | 用户 | 记录操作、证明并幂等移动状态 | 接收同一因果事件，更新认知和关联后续 |
| “继续交代”等自然语言 | OpenClaw | 只保存 Episode、评论和可靠唤醒 | 解释含义并决定更新、关闭、拆分或询问 |
| 外部消息、文档或执行结果 | OpenClaw | 采集器只生成证据、候选和回执 | 根据目标与验收标准决定任务状态 |
| Workboard/Codex 工具调用 | 已获授权的 OpenClaw 决策 | 工具按幂等键执行副作用 | 复核结果与证明，不把退出码直接等同完成 |

旧 `tasks`、`patrol_runs` 和 `knowledge_candidates` 表属于兼容历史，不是规范任务接口。新功能不得直接依赖它们驱动主控或 UI。

### 6.8 外部事件与连续会话

`external_event_receipts` 保存事件接收、处理、重试和失败状态。`conversation_bindings` 保存逻辑上下文边界与稳定 OpenClaw 会话键的映射。二者都是投影和投递状态，不是任务库。

规范会话边界包括：用户直接交代的单一人工主会话、按真实 `chat + thread/root` 延续的外部会话、每张卡独立稳定的 task 控制会话，以及未分类自动变化使用的隐藏 inbox。任务通过 `work_task_attention.owner_session_key` 绑定自己的 task 会话，不复用主对话或来源会话；Workboard 卡仍是任务状态权威，会话只是上下文边界，项目只进入图谱、任务和检索作用域。按项目共享的历史 `workstream` 绑定仅保留审计，不得接收新变化或成为新任务的默认控制会话；固定 `knowledge-curation` 维护会话不属于该历史项目映射，继续按 INV-69 处理知识变化。任务会话规则见 [ADR-0033](decisions/0033-main-and-task-conversations.md)。

- 同一外部事件重复到达时可以更新接收时间和重试信息，但不得重复回复、重复建任务或重复触发审批动作。
- 飞书机器人单聊按 `chat_id` 保持连续会话；群聊按 `chat_id + thread/root` 隔离，且只有明确提及机器人时才自动进入回复链路。
- 机器人、应用卡片和自动通知与真人消息一样先进入 Evidence；有界窗口按真实时间顺序携带首写脱敏后的消息体，不以人工摘要替换，也不因发送者是 bot/app 而过滤。凭据、资源令牌和附件二进制仍不得进入模型上下文。机器人输出只能作为状态或线索，不能替代真人指派、用户承诺、权威归属或实际验证证据。
- 一段会话可以没有任务、关联已有任务或产生新任务。不得把每条消息自动变成任务。
- 个人账号可见消息通过快速增量轮询进入证据和变化流，默认只唤醒主控，不代表有权代用户回复。
- 个人群聊消息必须先判定归属：明确指派/提及当前用户、当前用户本人承诺、或明确延续已有活动卡，才可创建或激活 `todo/ready`。明确指派他人、无责任人的群问题和一般业务播报只进入证据与知识检索；“紧急、报错、负责人、上线风险”等措辞不能代替归属证据。
- 业务相关性和结果责任必须分开记录。其他人负责的工作即使属于用户所在项目，也只能作为背景、依赖、风险或责任人路标；不得据此创建、推进或关闭用户卡片。
- 人员身份以飞书稳定 ID 及 `sentBySelf` / `mentionsSelf` 等采集元数据为准。显示名称只用于阅读，禁止按姓名相近、同姓、别名猜测或文本分词把他人当成当前用户。
- 归属存在合理可能但证据不足时，只有确实需要用户决定是否接手，才可进入 `backlog`；不得直接进入 `todo/ready`。模型必须在任务记录中保存归属依据。
- 个人账号会话按 `chat_id` 或 `chat_id + thread/root` 建立独立稳定会话键；新增消息继续原会话，不进入共享的无界全局聊天上下文。
- 项目文件、Git 和文档变化保留项目候选键后进入隐藏 inbox。OpenClaw 可以把证据与一个或多个项目、任务、人员或职责建立可修订软关系，但不得因目录、群聊或项目键预先创建永久项目会话。
- 每张 Workboard 卡在 Shadow `work_task_attention.owner_session_key` 保存独立稳定的 task 控制会话，按 card_id 确定而非按项目或来源会话共享。项目与来源只是引用；任务可以有界查询其他会话证据，但不得复制完整历史，同一时刻只能由一个控制会话推进。
- Workboard 自身的 `session_key` 保留给 OpenClaw/Workboard 原生执行生命周期和子 Agent 会话，不得写入控制会话，也不得据其是否为空判断任务是否已被主控持续跟踪。
- 首页人工输入先进入稳定的 `agent:main:shadow:user` 主对话，由唯一主控判断问题、知识、提醒或任务；后台巡检使用独立 inbox。新建或续接任务必须引用本次 Evidence，回执完成前绑定独立 task 会话并可靠交接。后续卡片输入、精确 taskId 变化和复查进入任务会话；没有任务关联的外部消息仍在来源会话判断。宠物不得要求用户预分类，也不得以关键词替代语义判断。
- 每次任务相关操作必须记录 `operation_id`、`causation_id`、操作者、来源、卡片 ID、基础状态、期望效果、应用状态、Evidence ID 和控制 `session_key`。同一次操作产生的评论、证明、状态变化和知识 Episode 应合并为一个 Agent 变化包，避免 Agent 把同一人工动作理解成多件事。
- Shadow 只维护稳定逻辑会话键和有界上下文路标，不自建 transcript 轮换、拼接或摘要回灌。`thread_bootstrap` 只包含稳定控制协议，其 epoch/fingerprint 不得读取数据库动态状态；职责、任务、跟踪和项目事实只通过当前轮有界工具结果提供。物理 transcript 的压缩、截断和续写由 OpenClaw 原生 compaction 负责；`generation`、`context_epoch` 和检查点字段只允许作为诊断观测，不得形成第二套会话生命周期。
- `allowRawTranscripts` 只授权主控按明确 thread 读取本机 Codex 结果，不代表自动注入历史。`codex_sessions_list` 应限制返回数量；`codex_session_read` 只用于已绑定 Workboard 卡的执行证明，默认不展开完整 turns。创建 Codex 子任务时必须生成不超过 8 KiB 的执行简报；续轮只给出当前未满足的验收差异和新证据定位，不得把旧 transcript 再拼接回输入。
- 显式展开 Codex 历史也必须分页：默认最近 2 轮、每轮最近 12 项、16 KiB；按 `turn_offset/item_offset` 继续查，最大返回 32 KiB。工具边界先投影再脱敏，不能先把几十 MB 全文送入 Gateway 主线程脱敏。截断必须显式标注，不得把部分输出当完整验收证明；不删除或改写原会话，也不关闭脱敏。原生插件升级时需校验该边界，布局不匹配则停止部署并提示，禁止静默失效。
- Shadow 数据库工具和 Context Engine 提交在单一串行工作线程执行，不占 Gateway 网络/健康检查线程；这是执行隔离，不是第二个语义主控。工作线程失败时返回“结果待核实”，不得透明重放可能已提交的写操作。生产上下文写入服务和 Gateway 使用同一受验证的内置 Node 版本，禁止随 PATH 漂移。
- 飞书任务和审批事件优先实时接入；事件不可用或进程重启时由定时增量采集补齐。

### 6.9 提醒

`reminders` 保存提醒内容、到期时间、来源、关联任务、OpenClaw 调度标识、交付和人工确认状态。它是提醒投影，不复制 Workboard 任务状态。

- OpenClaw Cron 是用户提醒到期触发的权威调度源；`reminders` 用于宠物展示、来源追溯和人工确认，不用于 Agent 内部任务复查。
- 交付状态必须区分 `scheduled`、`notification_pending`、`delivered` 和 `acknowledged`；主控通知失败时保持可重试状态，不得先记成已交付。
- 用户明确说“提醒我”时可以创建提醒。Agent 从消息或文档推导提醒时，必须存在明确日期、明确行动主体和可定位证据，不得猜测时间。
- 活动任务的内部复查时间只进入 `work_task_attention.next_review_at`，由 `task_progress_due` 有界唤醒。内部复查不得调用 `shadow_reminder_create`，不得出现在宠物提醒列表，也不得创建 Reminder Cron。
- 提醒工具对绑定任务的同一到期时刻使用规范幂等键；模型改变标题或自定义键不得创建第二条。推导提醒还必须提交来源依据以及来源 Evidence 或定位地址。
- 活动提醒必须能够修改和取消；替换或取消调度时保留修订号、审计记录并可靠清理旧 Cron。
- 到期表示“应当通知”，不表示关联任务已完成，也不自动改变 Workboard 状态。
- “知道了”只确认本次提醒；“稍后提醒”创建新的调度并保留与原提醒的关系。
- 用户确认、延后、修改或取消提醒时，按钮先按提醒投影的确定性语义执行，再通过统一 Agent 操作事件可靠通知所属任务会话或 inbox；不得要求模型先批准这些按钮动作。
- 提醒和任务可以互相关联，但任何一方都可以独立存在。

### 6.10 条件跟踪与可靠出站

`condition_watches` 保存自然语言条件、确定性候选筛选器、证据游标、稳定会话、超时时间和语义处理状态。`outbound_message_drafts` 保存收件人、发送身份、原会话、正文修订、批准模式、有界审核上下文、审计状态和发送回执。`controller_outbox` 保存仍需后台可靠执行的任务操作、提醒调度、主控唤醒和飞书发送意图。三者都不是任务库。

- 创建跟踪时基线游标固定为当时最大证据行号；后续检查只读取该游标之后的有限证据。候选选择器升级时允许在基线与当前游标之间执行一次有界回放，并排除已复核证据；不得借此扫描全库或反复回放。
- 筛选器只负责产生候选。精确会话、外部 ID、线程和来源前缀确定候选范围；范围内的文字关键词只是语义提示，不能把图片、附件或不同措辞挡在主控之外。只有缺少精确范围时，关键词才可作为候选门槛。候选、超时都必须唤醒同一个 OpenClaw 会话，由主控调用语义工具决定 `satisfied`、`continue` 或 `cancelled`。
- 条件候选只是新增事实。主控必须先读取候选正文、发送人和来源，再回到关联 Workboard 目标与验收标准，记录本轮确认了什么、仍缺什么；不得把回答了子问题等同于业务任务完成。
- 条件候选或超时绑定活动任务时，主控必须在候选发生后先为该任务写入一次结果检查点，再调用 `shadow_condition_resolve`。条件决议复用该检查点作为任务结果审计，不允许仅凭候选文本直接改变持续推进语义。
- `continue` 必须保留已推进的证据游标和复核历史，并持久化一个结构化 continuation。内部行动、Codex 执行、外发草稿和提醒应保存对应引用；被动等待必须说明预期事件并给出新的未来复查时间；等待用户必须明确所需决定。只有备注文字或恢复原状态不是有效推进。
- `satisfied` 或 `cancelled` 关闭 condition watch 时，任务 continuation 不得仍引用同一个 watch。主控必须留下业务目标完成证明、下一行动、其他条件、内部复查或明确等待用户之一；条件关闭不自动关闭 Workboard 卡。
- 关联任务的结果跟踪必须有未来复查时间。调用方未提供时，系统写入明确标记为内部兜底的默认复查时间；它不代表业务 DDL，也不自动宣布条件满足。
- Agent 主动发起且要求回复的问题必须在草稿创建时绑定已有 Workboard 卡；真实发送后的 condition watch 继承同一 `task_id`。无任务目标的问题不得以“先问问”方式进入持续跟踪。
- 真实发送回执必须在同一可靠出站处理内创建带超时的 condition watch，并把 `work_task_attention` 的 continuation 更新为该 watch。该投影只描述下一唤醒来源，不复制 Workboard 状态，也不需要额外模型轮次。
- `shadow_condition_list` 必须返回有界起始/候选证据正文和身份元数据，不能要求主控凭 Evidence ID 猜测回复内容。
- 定时检查只补偿事件遗漏和服务恢复，不重新扫描全部历史，也不独立创建 Workboard 卡片。
- 宠物可以只读展示活动、候选和超时跟踪的条件、状态、时间、稳定会话及有界证据；打开详情不得修改跟踪状态，也不得把跟踪复制为 Workboard 任务。
- 出站动作采用稳定幂等键、有限批量、崩溃后租约恢复和指数退避。失败不得丢失，也不得无限高频重试。
- `hitl` 与 `automatic` 只能改变同一出站记录的批准方式，不得选择两套发送实现。`hitl` 由宠物修改、确认或取消；`automatic` 在创建记录时自动批准并进入同一个 `controller_outbox`。
- 发送身份由 `feishu.outboundMessages.senderIdentity` 统一控制，身份、批准模式和正文修订必须写入审计证据。当前运行策略为 `user`：机器人单聊入口经 HITL 批准后改为用户向对方发起私聊，群内明确提及在用户可见的原群回复。只有发送身份显式为 `bot` 时才允许 `automatic`；用户身份配置下即使误设 `automatic` 也必须降级为 `hitl`。
- 当前不使用联系人黑名单或白名单决定是否确认。灰度阶段所有回复和主动消息均由 `hitl` 控制；未来放开自动回复必须显式切换运行模式，而不是增加旁路。
- 可处理的机器人单聊和群内明确提及必须在对应稳定会话生成回复正文，再进入统一出站记录；不得降级为通用巡检后由模型自行决定是否建立回复草稿。
- 专用实时回复建立草稿后，必须确认同一证据产生的通用变化；同一 `reply_to_message_id + approval_mode` 只保留一个活动草稿，避免专用链与通用巡检重复回复。
- 人工审核上下文必须在草稿创建时形成快照，顺序区分触发消息、最近对话和生成依据；最近对话必须有固定条数上限，打开审核界面不得重新加载完整会话或把数据库规模映射为提示词规模。
- 主动消息缺少天然触发消息时，主控必须提供人工可读的上下文摘要；旧草稿可以从关联 Evidence 有界回填，但回填失败时必须明确显示上下文缺失，不得伪造对话。

### 6.11 统一人工反馈知识 Episode

用户通过“告诉 Agent”明确提供的稳定知识、任务下一步、任务完成确认、飞书消息修改批准和带原因拒绝，都必须通过同一个知识 Episode 入口进入现有 `evidence`、`graph_episode_annotations` 与 `graph_enrichment_queue`。不得为任务反馈、消息反馈或偏好学习建立独立知识库、专用图谱、第二提取队列或第二主控。

- 原始 Episode 必须保留用户输入、作用对象、必要的修改前后文本、有界上下文、来源定位和幂等标识；摘要、关键词和召回提示只是可重建投影。
- 业务动作与知识含义保持分离：Workboard 仍是任务状态源，`outbound_message_drafts` 仍是消息状态源，知识图谱不得通过学习投影直接改变二者。
- 统一入口中的稳定知识应先可靠追加原始 Evidence，再由现有语义复核队列补充高质量摘要和图关系；不得为了保存原文强制等待一次完整模型会话。
- 飞书拒绝必须由用户填写自然语言原因。拒绝原因、被拒绝草稿和审核上下文共同构成 Evidence；不得用固定原因枚举替代用户原话。
- 飞书修改批准必须保留原始草稿和批准稿，不能只保存 `edited=true` 或最终正文。
- 语义复核必须区分一次性指令、局部偏好、长期偏好、职责、职责边界、纠正和无长期事实。单次编辑或拒绝不得无依据扩展成全局偏好，单次任务指导不得自动等价于长期职责。
- 偏好和职责关系必须保留 Evidence、作用域、认知状态和有效时间；后续相反反馈通过现有修订、冲突和取代链处理，不覆盖旧证据。
- 任务详情必须展示同一 Workboard 卡关联的知识 Episode，并明确区分“已收录、等待语义复核、复核中、已建立图关系、无长期事实、需要人工复核和失败重试”。不得只显示 Workboard 评论而隐藏知识处理状态；关联的原始 Evidence 也必须出现在来源证据页。
- 卡片内“继续交代”保持单一输入和单一提交动作，可承载补充要求、问题、纠正和停止指令。宠物必须先保存原始知识 Episode，并以持久任务消息事件唤醒当前卡片的归属会话；OpenClaw 结合任务、职责和上下文决定回答、追加步骤、调整状态、关闭、拆分或询问。语义明确时不得要求用户再点一次“确认已完成”；含义不明确时保持任务开放并由 Agent 询问。宠物不得用正则或关键词自行解释任意自然语言并改变任务状态。
- 结构化按钮表达的是用户已经作出的决定：“确认已完成”、批准、拒绝、取消提醒等可以由统一命令执行器立即幂等落库，但同一操作仍必须生成 Agent 可确认的持久因果事件。Agent 收到后负责更新认知、检查关联任务和决定后续，不得被界面状态变化静默绕过。

## 7. 主动巡检契约

Shadow Agent 的唤醒入口包括实时事件、快速增量轮询、Cron 提醒、失败重试、人工操作、有界任务进度审计和可选的低频恢复 Heartbeat。所有入口先进入确定性注意力调度器：按会话/来源聚合、冷却、去重并检查是否存在实质变化，再只向同一个 OpenClaw 主控发出一次唤醒；上下文服务和宠物不得在旁路运行第二套规划循环。

后台自动 `attention` 受本机巡检时间窗约束，默认每日 `08:00-19:00`，结束时刻不再开启新轮次。时间窗外仍可增量采集、保存 Evidence、物化确定性状态和排队变化，但不得领取变化租约或调用模型；调度器计算下一开放时间并延后，不能丢弃、确认或反复重排变化。用户通过系统托盘修改时段或关闭自动巡检，设置写入共享 SQLite，daemon 在 15 秒内重新布置定时器。人工入口、飞书实时会话、到期提醒和已经批准的可靠出站动作不属于后台巡检，不受该时间窗阻塞。

实时对话与自动注意力必须共享按 `session_key` 串行的调度边界。不同会话可以并行，同一稳定会话任一时刻只能存在一个 OpenClaw 轮次。外部事件回执必须具备处理租约、失败退避和重启恢复；普通群消息不得绕过注意力调度创建按消息 ID 隔离的新会话。

人工操作、Workboard 状态变化、提醒动作、出站审核和外部执行结果也必须进入相同的可靠变化协议。业务状态写入与 Agent 通知可以由同一事务或 outbox 连接，但不得只改状态而让归属会话无从得知。Agent 暂时离线时变化保持待投递；恢复后按 `operation_id` 合并补送，同一操作不得因重试重复追加评论、重复关闭任务或重复发送消息。

每轮语义处理必须按以下顺序工作：

1. 调用 `shadow_attention_packet` 一次领取短版长期简况、直接相关活动卡和有限新证据。
2. 只在注意力包存在具体未决问题时调用认知路由；缺少飞书局部上下文时，只能以已知 `conversationKey` 调用 `shadow_conversation_window` 读取有界窗口，其余情况按路由指向查询局部图、代码、文档、证据或某张 Workboard 卡，不得先列出整个工作台或搜索全部消息。
3. 选择并推进至多一个明确、低风险、可在本轮形成结果的事项。
4. 写入结果、证明、剩余不确定性和任务状态。活动卡的任务到期变化或人工操作必须调用 `shadow_task_checkpoint`，绑定本次 `change_seq`，记录结果状态、Evidence 和唯一 continuation；检查点不得直接修改 Workboard 状态。
5. 调用 `shadow_context_ack` 确认已领取变化；活动卡缺少精确检查点时确认必须失败。只在用户需要知道或行动时通知。

自动注意力批次必须进入对应稳定会话。相同外部会话或工作流复用同一 session key，不同会话互相隔离；续轮使用 `thread_bootstrap` 和 `continuation-skip` 避免重复注入，达到压力阈值后由 OpenClaw/Codex 原生压缩而不是无限增长。

未知问题按以下顺序恢复：已有事实、可回查代码/文档/会话、可搜索范围、可询问人员、需要授权、仍未知但有下一步。`shadow_context_resolve` 只生成路由和询问建议，不发送消息；OpenClaw 使用 `shadow_outbound_draft_create` 建立出站草稿。获准发送后由可靠队列保留回执并在同一稳定会话建立 condition watch，等待回复期间任务保持等待或进行状态。

工作雷达排序优先级为：

1. 已逾期或临近明确截止时间。
2. 用户人工置顶。
3. 正在阻塞其他工作或影响多人交付。
4. 高业务影响、高风险或高优先级。
5. 与长期职责和近期目标相关的新变化。
6. 最近更新和队列年龄仅作同分辅助，不得成为主要排序依据。

旧知识语义精炼是后台维护任务。默认每轮最多领取两条，只能在工作雷达没有逾期、临期、置顶、阻塞、高优先任务且没有可行动变化时执行。该数量不代表 Agent 每轮只能理解或处理两项真实工作。

每轮不得重新遍历全部历史证据。当前实现必须依赖来源字节游标、内容指纹、图谱物化游标、变化租约和有界查询。飞书消息按会话键合并，文档目录与正文变化分开；完整项目核对可以低频执行，但不能把全部正文发送给模型。

`task_progress_due` 是对“只靠新事件”的补偿，不是第二个巡检 Agent。确定性审计只读取 Workboard 活动状态、任务关注覆盖层、执行状态和条件跟踪索引，跳过仍有未来触发的任务，按截止时间、置顶、阻塞、优先级和新鲜度评分，同分时先复查较久未检查的卡，每轮只投递配置允许的少量卡片。只有租约未过期的 `leased` 复查占运行额度；同卡已有 pending/leased 事件时不重复投递，但不能让其他卡被无限期 pending 占位阻塞。到期 Codex 执行先查询原生运行状态，明确存活则延后观察；终态或未知结果交给原任务核对，不由审计器关闭卡片。OpenClaw 收到后必须读取指定 `taskId`，核对真实变化并推进一个动作；若仍等待，记录检查结果、明确预期事件和新的复查时间。

本地采集、飞书快速轮询、条件/任务审计和可靠出站分别持有独立 SQLite 连接，并在各自 lane 内串行，防止同一连接事务重入，同时避免每日全量采集或长模型唤醒阻塞 60 秒消息轮询。SQLite WAL 与 busy timeout 协调短写事务；模型调用仍通过 `SessionDispatchQueue` 按稳定会话串行，不能与同一会话的自动注意力并发。

Codex rollout 增量采集在打开文件前固定本轮 `stat.size`，读取到该快照边界即停止；新追加内容留给下一轮。证据与游标按有限行数在同一短事务内提交，不能在异步文件读取期间保持写事务。主数据库心跳连续失败达到配置阈值时，上下文进程以非零状态退出，由 `PersonalShadowAgentContextService` 监督进程自动拉起；PID 存活不得单独作为在线证明。

Codex 会话摘要允许随助手回复、工具调用和结果继续更新，用于追溯和日报；新用户输入与回合结束信号可立即物化，连续工具输出必须经过安静期合并。每次重建替换当前可检索快照，只有摘要检测到新的用户输入时才能进入主动注意力队列。Agent 自己的分析、工具日志和确认结果不得形成自激唤醒环。

控制轮成本治理分为硬边界和观测边界。自动注意力包、会话窗口、一级证据结果和 Codex 简报继续执行各自字节预算；上下文服务提交给 OpenClaw 的初始提示超过 `controllerBudgets.maxPromptBytes` 时必须在调度前失败并保留可靠事件。OpenClaw 原生 `tools.loopDetection` 必须保持启用，以阻断重复、轮询和压缩后无进展工具循环。

生产控制轮不使用固定墙钟时长判定失败。应用向 Gateway 明确传入 `runTimeoutSeconds: 0`，并使用 60 秒 `agent.wait` 观察片持续等待；观察结果为 `pending`，或为无 `endedAt` 且阶段为 `queue/gateway_draining` 的 `timeout` 时，不释放变化租约、不写失败、不创建重试。真正需要数十分钟或更久的编程工作仍由主控通过 `sessions_spawn` 派发到独立 child session，并用完成事件回到原任务，避免把主控会话长期占在执行工具内。隔离冒烟和基准可使用 600 秒等独立上限，其结果只能说明测试轮是否在预算内完成。

`controller_turn_metrics` 是有限保留的可重建观测账本，不是会话、任务或计费真相源。每个 Gateway run 只保留一条幂等记录，包含匿名会话哈希、触发类型、模型、时长、字节、Token 分类、工具名计数和预算标志；不得保存正文、工具参数、工具结果或真实外部标识。Provider 不返回 Token 或本地 history 窗口被截断时必须明确记为缺失/不完整，不得猜测。Token、总工具数和耗时超过警戒线只写告警，后续应根据任务类型和真实分布调整检索、压缩或轮次设计，不能在执行中粗暴截断并伪装成完成。

## 8. 工具边界

Shadow Context 插件提供的规范工具集合为：

- 状态与注意力：`shadow_attention_packet`、`shadow_conversation_window`、`shadow_context_status`、`shadow_context_focus`、`shadow_context_focus_update`
- 变化消费：`shadow_context_changes`、`shadow_task_checkpoint`、`shadow_context_ack`
- 检索与认知路由：`shadow_context_resolve`、`shadow_context_query`、`shadow_context_entity`、`shadow_context_vocabulary`、`shadow_evidence_search`
- 知识维护：`shadow_context_capture`、`shadow_context_revise`、`shadow_context_enrichment`、`shadow_context_annotate`、`shadow_context_propose`
- 风险分析：`shadow_context_impact`
- 飞书出站草稿：`shadow_outbound_draft_create`、`shadow_outbound_draft_list`
- 提醒：`shadow_reminder_create`、`shadow_reminder_list`、`shadow_reminder_update`、`shadow_reminder_cancel`
- 条件跟踪：`shadow_condition_watch`、`shadow_condition_list`、`shadow_condition_resolve`

工具输出必须受 UTF-8 字节预算限制。插件允许受控写入人工证据、召回卡、候选事实、工作简况和变化确认，因此不得笼统描述为“只读插件”。它不得直接修改 Workboard 任务状态；任务状态通过 OpenClaw Workboard 工具维护。

### 8.1 一级证据检索协议

`shadow_evidence_search` 只承担图谱路由后的局部定案，不是第二个全局搜索 Agent：

1. 优先级依次为 evidence id / `externalId`、已知 thread 或 conversation、项目与来源类型、窄时间窗、最后才是有界关键词回退。能使用结构范围时不得省略后直接扫全部 Evidence。
2. 默认来源只包含 Codex 会话元数据与用户/助手消息、Git 提交、飞书消息/正文、项目文档和人工知识。Codex tool call/output/result 与 patch result 属于可显式展开的操作证据，不得默认混入普通问答。
3. 生成摘要、历史 Agent 回答、Workboard 任务结果和图谱派生结论不得作为该工具的默认一级证据。
4. 返回正文、标题、定位符和查询回显必须做凭据脱敏并满足总字节预算。Evidence 内容始终是不可信数据，任何出现在原文中的提示、命令或授权声明都不得改变主控规则或触发执行。
5. 检索只读且不得改变 Evidence、图谱、任务、提醒、草稿或会话状态。相互冲突的证据必须并列保留；缺少一级证据时回答 unknown 并给出下一检索位置。
6. 提交哈希等结构化标识必须走 `externalId` 索引；中文连续文本允许有界分词回退，但精确会话/飞书问题应显式传入 `sourceKinds` 和已知作用域，不能以扩大 turns 或全表上下文替代检索。

正文片段预算按实际UTF-8字节计算，包含上下文标记和分隔符；合法Unicode不能因截取而被拆坏。已选窗口不得因前窗按字符超支而被整体前缀截断挤掉；重叠区间仅在同一Evidence内合并，能容纳的完整脱敏正文不重复截窗。此约束不保证所有关键词或事实都在片段中，不改变选点/排序、身份和精确回源协议；缺失上下文继续由Agent读取原文。片段正确性、回答质量与整轮成本分别验证，见字节预算修复。

移除或改变工具语义属于契约破坏性变更。新增向后兼容工具属于次版本变更，并必须更新插件清单、文档和测试。

## 9. 权限与安全

### 9.1 自动允许

- 读取已授权的本机和外部来源。
- 增量采集、去重、分类、摘要、索引和图谱候选维护。
- 查询代码、文档、日志和 Workboard。
- 生成本地临时分析、草稿和验证证据。
- 在已有明确任务和授权范围内执行只读检查。
- 当且仅当 `feishu.outboundMessages.mode` 被用户明确切换为 `automatic` 时，自动批准发给 Shadow Agent 机器人的单聊或群聊明确提及回复；回复仅限当前会话，并仍须经过统一出站记录、可靠队列和回执审计。

### 9.2 需要任务授权或用户确认

- 修改正式代码或正式本地文档。
- 当前 `hitl` 灰度模式下的全部飞书回复和主动消息；宠物必须展示发送身份、收件人、原因和可编辑正文。
- 主动发送外部消息，或代用户回复个人账号收到的消息；当前实现不因联系人身份建立黑白名单例外。
- 同意、拒绝或转交审批。
- 修改远程文档、表格、任务和权限。
- Git 提交、推送、合并。
- 部署、发布、替换设备文件或控制设备。
- 删除、移动、覆盖数据。

用户可以为具体工作流提供持续授权，但授权必须描述目标、范围、允许动作、有效期和撤销方式。一个系统的授权不得外推到另一个系统。

### 9.3 永不自动

- 财务承诺、法律承诺和人事决定。
- 生产设备控制、安全控制和可能危及人员或设备的动作。
- 凭据披露、绕过认证、读取被明确阻止的凭据路径。
- 在界面状态不确定时随机点击或反复尝试。

`config/policy.json` 是策略声明和采集器阻止路径的来源。当前并非所有外部动作都由代码级策略引擎强制拦截，因此 OpenClaw 运行规则、工具权限和人工确认仍是必要控制。文档不得把策略文件描述为完整安全沙箱。

## 10. 证据与结论质量

验证结论必须区分以下等级：

| 等级 | 含义 |
|---|---|
| E0 | 无直接来源的推测 |
| E1 | 人员陈述或二手材料 |
| E2 | 直接检查源码、差异、文档、消息或结构化记录 |
| E3 | 本地构建、单元测试、模拟或受控执行 |
| E4 | 目标集成环境或端到端链路验证 |
| E5 | 真实现场、生产环境或责任人明确验收 |

不得把构建通过写成现场验证，不得把浏览器点击成功写成 API 契约正确，不得把接口存在写成生产可用。每项结果应记录对象、版本、环境、方法、范围、输出和未覆盖项。

影响传播结果只用于发现风险和验证候选。只有新的检查、测试或现实确认才能形成“已经受到影响”的事实。

### 10.1 模型评测证据

真实消息数量、JSON 可解析率和工具调用成功率只证明数据可读与链路可运行，不证明 Agent 判断正确。模型评测必须至少分别记录：触发/忽略判断、用户结果责任、当前用户动作、已完成工作、等待他人、回复必要性、继续条件、引用证据和不确定性。

开发集用于发现问题和调整实现，验证集用于阶段验收，holdout 只在方案冻结后执行。人工或 Codex 复核形成的 gold label 必须引用具体消息范围并允许标注“上下文不足”；模型自行生成且未经复核的标签只能作为候选。隔离模型烟雾先按场景抽取至多 3 个 Episode，确认输入、租约、输出和零副作用后才能扩大样本。真实数据与模拟数据的准确率、延迟和失败必须分开报告。

## 11. UI 契约

- “Agent 在线”只表示 OpenClaw Gateway 健康，不表示采集器、外部授权和每项任务都正常。
- 主控、上下文采集和飞书连接状态必须分开显示；不得用一个绿点替代组合健康。
- “正在做”来自 `running` 卡片；没有运行卡时可以显示等待巡检，但不能制造虚假执行。
- “需要你确认”只包含 `review`、需要用户授权的 `blocked` 或等价人工动作。
- “Agent 待处理”只统计活动任务，不包含全部历史、已完成或未激活 backlog。
- 列表可以只展示前若干项，但必须说明总数与筛选范围；显示 4 条时不能让 33 条历史看起来都是当前待办。
- “刚完成”来自 Workboard `done` 历史，不来自 Codex 会话标题或本地旧任务表。
- 点开任务必须能够看到任务说明、状态变化、执行步骤、关联会话、工具/命令摘要、结果、阻塞和证据。
- 到期提醒必须以独立、醒目的列表展示，包含来源和时间，并提供“知道了”和“稍后提醒”；提醒数量不得混入 Agent 待处理任务数量。
- 提醒列表不得展示仅供 Agent 自己复查任务的内部检查点；内部检查点属于任务关注投影，不是用户通知。
- 宠物首页只提供一个通用自然语言入口，不增加“问、记、提醒、任务”等并列模式。所有原话先进入统一 Evidence/Episode 链路，再由唯一 Shadow Agent 主控结合上下文决定回答、维护知识、创建提醒或创建/续接 Workboard 卡。界面进程不得实现第二套知识、任务、提醒或意图分类器。
- 明确交给 Agent 的可执行工作必须在本轮创建或续接一张规范 Workboard 卡，并写明目标、验收、来源、权限边界和下一触发；一次性问题和普通讨论不得为了展示活动而建卡。同一输入不得产生重复卡片。
- 任务详情必须提供“继续交代”入口，以常驻输入框取代弹出遮罩，默认打开独立任务对话；同一卡片可查看用户消息、Agent 决策、执行动作、结果和证据。主对话显示交接答复和任务链接，不混入任务全文。项目只作为软关系和召回作用域；共享知识按需检索。
- “持续追踪”状态条必须可打开只读详情；详情至少显示条件、状态、最近检查/超时时间、关联会话和可用证据，查看动作不得触发条件决议。
- `candidate` 和 `timed_out` 是 Agent 的语义复核触发，不是用户待办。绑定活动任务时必须合入同一任务卡详情，未绑定任务时才可留在“持续跟踪”中并明示由 Agent 核对；不得用“有新结果”误导用户，也不得产生第二张任务卡。
- 待确认飞书消息必须独立显示数量和列表；展开后展示发送身份、收件人、原因和可编辑正文，并提供确认与拒绝。拒绝前必须填写原因；修改批准或拒绝均先生成统一知识 Episode。确认只写入可靠发送队列，不能在渲染进程直接调用飞书。
- 宠物右上角 `X` 只隐藏窗口，不退出宠物、上下文服务或 OpenClaw。系统托盘角标必须提供“显示工作现场”、“自动巡检”、“巡检设置”和“退出 Shadow Agent”；巡检设置可修改启用状态与本机起止时间，并显示当前保存值。单击角标或重复启动宠物应恢复并聚焦已有窗口。退出必须是托盘中的显式动作，并在 Electron 退出前确认上下文服务、OpenClaw 及其项目进程树已经停止；停止失败时界面与托盘必须保留并提示错误。

## 12. 可用性、性能与恢复

- 同一机器只允许一个上下文服务和一个 OpenClaw Gateway 实例。
- 上下文服务、网关和宠物必须能分别重启；宠物故障不得影响任务真相源。
- 采集器必须按来源隔离失败。单个来源失败不得被当成“无数据”，也不得阻止其他来源更新。
- 启动时首轮采集与外部事件恢复必须串行进入数据库写入阶段；首次恢复失败不得阻止恢复定时器安装，后续按租约和退避继续。
- 数据库写入必须幂等；重复运行不得重复创建同一证据、事实或任务。
- 变化租约超时后可以恢复，但已经确认的变化不得重复执行。
- 模型运行时不可用时，依赖语义判断的任务保持原状态并显示故障；不得把“调用失败”解释为任务完成、取消、拒绝或无需处理。恢复后继续消费已持久化事件。
- 所有来自宠物、飞书、提醒、Workboard 和执行器的 Agent 相关事件必须在唤醒前持久化。网关、Agent 或网络短暂离线时不得丢失；恢复补送必须以 `operation_id` 和外部幂等键抑制重复副作用。
- 模型上下文必须使用稳定引导、有界变化、少量未确认候选、摘要、召回卡和局部图，禁止把数据库规模线性映射到提示词规模。自动注意力默认不超过 12 KiB、硬上限 16 KiB；仓库内的团队原文和结构化快照只能作为证据与导入来源，不得成为整篇提示词附件。
- 数据库恢复必须先停止写入并备份 SQLite 主文件、WAL/SHM 和 OpenClaw 状态。`npm run init` 只能初始化模式或重建派生索引，不能冒充数据恢复。
- Workboard 和证据图是不同权威面，备份与恢复必须同时考虑，不能只恢复其中一份后宣称系统完整。

## 13. 配置与机密

- 可共享默认配置位于 `config/`；机器路径和个人差异应进入本地覆盖或运行目录。
- 项目目录迁移后，部署脚本必须以当前源码根目录重新生成 OpenClaw 工作区、主数据库、Workboard 数据库和 Codex runtime 路径；现行运行配置不得继续依赖旧源码目录。
- 迁移运行状态时必须先停止唯一上下文服务、OpenClaw Gateway 和宠物，完整复制 SQLite 主文件及 WAL/SHM、OpenClaw 状态和必要工具，再更新绝对路径并通过新目录启动验证；旧目录只能在确认无进程和启动项引用后清理。
- OAuth、网关令牌、Cookie、API Key 和个人身份缓存只允许存在于受保护的本机运行状态，不得进入文档、测试快照或交接包。
- `runtime/openclaw-poc/state/openclaw.json` 是当前运行配置，不是可公开模板。读取模型状态时不得输出其中的秘密字段。
- Agent 管理的 Codex transcript 当前保存在本机用户级 `~/.codex/sessions`，因此同一 Windows 用户的 Codex 应用可以索引和展示；这不构成对其他用户的公开发布。模型请求仍由配置的远程模型服务处理，“本机保存会话”不得写成“内容完全离线”。
- 需要更强物理隔离时必须显式选择独立 Windows 账号、独立 Codex Home 或经批准的本地模型运行时，并重新验证认证、会话可见性和任务监督；不得通过复制或打印令牌实现隔离。
- 项目名和约定目录可以稳定保留；个人账号、私人 URL、会话内容和凭据必须脱敏。
- `docs/knowledge/` 可以在用户明确授权下随受控仓库保存组织内部认知资料；共享、镜像、交接和制品发布前必须核对接收权限，凭据和秘密仍不得进入其中。

## 14. 测试与验收

每次改变主控、任务、图谱、授权或主动巡检行为时，至少必须通过：

1. `npm test`
2. `npm --prefix .\openclaw\shadow-work test`
3. `npm run doctor`
4. `npm run openclaw:test`
5. 受影响界面的 E2E 或截图检查

涉及模型调用时，应额外执行真实模型烟雾测试；涉及飞书出站时，必须同时验证 `hitl` 不生成发送动作、确认后只生成一次发送动作、取消后不发送，以及 `automatic` 复用相同 outbox；涉及外部系统写入时，应使用测试记录、dry-run 或最小可撤销写入验证，未获得弹窗确认不得用真实联系人验证；涉及设备时必须明确区分模拟、集成和现场证据。

涉及飞书注意力、归属、回复或持续会话优化时，还必须运行真实数据适用性审计和隔离回放。调优过程只可读取 development 与 validation；holdout 只在候选方案冻结后执行一次。没有 gold label 时只能报告链路、格式、安全和性能指标，不得宣称语义准确率提升。

测试必须验证行为和证据，不只验证进程退出码。OpenClaw 在线验证应读取真实工具目录、插件结果、Workboard 和网关日志。

自 2026-10-22 用户确认起，后续真实 Agent/模型评测最低使用 `high`，评测默认 `high`，可提高为 `xhigh`。历史低档结果只作为诊断基线，不冒充高档或生产等效验收；效果对比必须分别记录模型、思考等级、上下文和数据版本。该评测要求不改变生产按任务类型分配思考等级的策略，也不要求不调用模型的单元测试加载模型。

## 15. 文档与变更治理

文档职责固定如下：

- `PROJECT_CONTRACT.md`：规范边界和不变量。
- `ARCHITECTURE.md`：当前实现、组件和数据流。
- `GENERIC_EPISTEMIC_GRAPH.md`：图谱、知识与证据领域设计。
- `OPERATIONS.md`：安装、运行、故障和恢复。
- `FEISHU_SETUP.md`：飞书采集权限与验证。
- `FEISHU_EVALUATION_DATASET.md`：真实评测数据、分层、盲测和模拟边界。
- `SOURCE_ADAPTER_ARCHITECTURE.md`：多源证据信封、Collaboration/Execution 规范存储、当前 Codex/飞书映射和后续适配器准入。
- `docs/README.md`：文档索引、状态和审计日期。

修改任一 `INV-*`、权威数据源、权限等级、任务状态语义、证据等级或工具语义时，必须：

1. 说明用户需求和被改变的不变量。
2. 记录备选方案及不采用理由。
3. 提供数据迁移、回退和兼容策略。
4. 更新契约版本、架构文档、运行规则和测试。
5. 验证现有数据不会被重新解释为另一种状态。

普通实现重构不得顺手改变这些契约。

## 16. 当前已知偏差与退出条件

这些偏差是已知技术债，不代表新的设计方向：

| 编号 | 当前偏差 | 负责人 | 约束 | 退出条件 |
|---|---|---|---|---|
| DEBT-01 | SQLite 仍保留旧 `tasks`、`patrol_runs`、`knowledge_candidates` 表，飞书采集器仍会写少量兼容任务 | 运行维护 | 不得由它们直接驱动 UI 或主控 | 飞书任务和授权提醒改为直接生成图谱变化或幂等 Workboard 卡后，冻结旧写入口 |
| DEBT-02 | `src/codex-client.mjs` 和 `config.codex` 保留早期本地主控时代参数 | 架构维护 | 不得据此判断在线 Agent 模型和思考等级 | 迁移仍需要的执行封装到 OpenClaw/Codex 调用层，删除无调用配置 |
| DEBT-03 | 飞书消息已有统一出站门，但审批、远程文档、Git、部署和设备等动作仍主要依赖运行规则 | 安全策略 | 不得把飞书出站门宣称为全系统统一权限沙箱 | 其余外部动作也统一经过可审计策略门和授权记录 |
| DEBT-07 | 仍有人工反馈和当前外部任务等待语义复核；旧摘要已分层为可检索冷库存 | 知识维护 | `active_review` 不得被冷库存阻塞；冷库存不得进入 `verifiedFacts` 或当前待办，只有检索命中或显式指定才可晋升 | `audit:knowledge:strict` 中活动 enrichment、活动 graph review、无来源结构路由和普通事实证据缺口归零；`coldInventory` 单独报告但不计失败 |

新增技术债必须写明负责人、影响、临时保护措施和退出条件，不得只写“以后优化”。

已解决的 `DEBT-04`：V4 将规范运行规则纳入 `openclaw/workspace-template/`，部署配置时同步到 OpenClaw 工作区，并由契约测试校验一致性。

已解决的 `DEBT-05`、`DEBT-06`：V4.1 分开显示主控、采集和飞书状态，并仅把具有 `requires_user` 或明确授权等待语义的阻塞卡归入人工确认。

V4.2 以统一出站记录和 `controller_outbox` 收口飞书 HITL 与未来自动回复；运行模式只改变批准方式，不再保留直接发送旁路。

已解决的 `DEBT-11`：V4.14 把统一人工入口改为本地事务提交。原始 Evidence、`direct_input_receipts` 回执和 `process_direct_input` outbox 动作同时落库，界面立即返回；后台在固定 `agent:main:shadow:user` 会话中使用稳定模型幂等键处理，离线或重启后沿用同一次运行身份续送。持久回执保存处理状态、模型回复、关联卡和错误，只有回执完成才向用户显示已处理。

V4.3 为统一出站记录增加持久化审核上下文快照，并要求主动草稿显式提供上下文摘要；宠物审核界面不再只显示收件人、原因和正文。

V4.3.1 将持续追踪状态条扩展为只读详情入口，直接投影 `condition_watches` 及其有界证据，不引入第二套追踪状态或隐式任务操作。

V4.4 将宠物中的明确记忆、任务反馈和飞书审核收敛到现有知识图谱的统一 Episode 入口；飞书拒绝增加必填自然语言原因，消息修改保存前后文本，同时保持 Workboard 和出站草稿各自的数据权威。

已解决的 `DEBT-08`、`DEBT-10`：V4.5 将控制会话归属写入 `work_task_attention.owner_session_key`，完成 13 张活动卡迁移；自然语言任务指令不再由宠物正则改变状态，结构化确认和任务指令统一先持久化为因果操作，再由可靠 outbox 应用并唤醒归属会话。V4.5 当时把无上下文人工输入临时放入 inbox；该入口已被 V4.9 的独立人工会话取代。

已撤销的 `DEBT-09`：多 Agent 审查确认 OpenClaw 已提供原生 safeguard compaction、历史占比和 transcript 截断机制。Shadow 不再实现物理会话换代；现有代际字段降为只读诊断数据，避免形成第二套会话生命周期。

V4.5 区分控制会话与 Workboard 原生执行会话，新增统一 Agent 操作协议、幂等 Workboard 执行器、离线 outbox 补送和明确任务直达注意力包；飞书审核决定也通过同一 Agent 变化入口通知稳定会话。

V4.6 开放 OpenClaw 原生会话编排能力，由唯一主控发起、接收并复核 Agent 管理的 Codex 子任务；Codex Supervisor 通过本机 stdio app-server 提供用户 Codex 会话的有界只读结果，写控制保持关闭。任务继续条件统一为执行完成事件、条件跟踪、内部复查时间、可执行下一步或结构化等待用户，飞书主动沟通继续使用统一 HITL 草稿和发送后回复跟踪。

V4.6 的飞书出站策略改为配置驱动的发送身份；当前使用用户身份并强制 HITL，机器人单聊入口通过用户私聊发送，避免用用户令牌回复不属于用户的机器人会话。

V4.7 将业务相关性与用户结果责任分开：注意力包暴露稳定身份信号，禁止按相似姓名或同领域推断归属；主动问题绑定 Workboard 目标，回复跟踪继承 `task_id`；条件复核返回有界正文，并要求 `continue` 同时保存结构化后续动作和复核历史。人工职责纠正继续复用统一知识 Episode 和可靠 Agent 操作归档误分类卡。

V4.8 采用事件优先与有界进度审计：精确范围内的图片、附件和不同措辞不再被关键词永久漏掉，旧游标执行一次有限恢复；任务结果跟踪获得内部复查时间，失去触发器的活动卡按优先级逐张形成 `task_progress_due`，仍由唯一 OpenClaw 主控核查和推进。采集、飞书、审计与出站按 lane 使用独立连接，既避免同一 SQLite 连接事务重入，也不让全量采集或长模型调用阻塞消息轮询。

V4.8.1 修复活跃 Codex rollout 采集追逐文件增长并长期占用 SQLite 写锁的问题：采集固定快照边界、按 200 行以内短事务提交，并在数据库连续失联时让上下文进程主动退出，由既有监督进程恢复。

V4.8.2 将宠物窗口生命周期与 Agent 进程生命周期分开：`X` 只隐藏到系统托盘，托盘角标负责恢复和显式退出，重复启动只唤回已有窗口，不再因隐藏界面误停宠物进程。

V4.8.3 将用户提醒与 Agent 内部复查彻底分流：内部复查复用已有任务关注层和有界审计，提醒工具只创建用户通知，并对推导来源及同任务同时间幂等进行代码级校验；现存误建提醒迁回任务关注层后取消 Cron，保留审计历史。

V4.8.4 明确持续追踪的产品语义：候选证据和超时条件由 Agent 复核，不计入用户待办；宠物状态条改为明确的 Agent 处理文案，只读详情展示候选正文、关联任务和展开状态。

V4.8.5 将团队身份职责档案接入现有通用图谱：仓库保留原文和确定性结构化快照用于审计，人员关系不建立第二数据库；运行时只按问题召回有限人员、职责、项目和证据定位，项目状态带来源日期与刷新标记。同名历史证据不得挤掉高优先级结构化职责，工具包装和渲染后的模型可见内容也必须遵守查询预算。

V4.8.6 将 OpenClaw 原生 Codex runtime 切换为用户级 Codex Home，共用本机 `codex login` 凭据，并对 OpenAI 模型强制使用 Codex runtime；Agent 管理的子任务获得工作区写权限，完成回调后可在同一已绑定 child session 上接受一次有界修正或下一步。用户手工创建的 Codex 会话继续只读，不开放全局写控制。

V4.9.0 将宠物首页的“问、记、提醒”三模式收敛为一个“告诉 Agent”入口。原话先保存为 Evidence，由独立稳定的人工会话判断是否回答、维护知识、设置提醒或创建/续接 Workboard 卡，后台巡检 inbox 与人工对话隔离；任务详情以“继续交代”承载后续要求和问题，并可靠回到原卡控制会话。网关以接受、等待终态和读取新增回复三步收敛结果，模型正文已完成但收尾压缩失败时不得误报为未执行。原生 Codex runtime 首轮直接装载白名单内动态工具，不依赖旧会话缓存或不可用的延迟工具搜索。界面不再要求用户替 Agent 做意图分类，也不为每张卡创建独立模型会话。

上述 V4.9.0 会话共享是历史决策，已由 2026-10-15 的 ADR-0033 部分取代：主对话长期保留，每张卡改为独立稳定任务会话；仍只有一个主控和一份 Workboard 任务状态。

V4.9.1 完成契约与架构复核：统一入口新建卡在成功返回前显式绑定 `agent:main:shadow:user`，冒烟测试同时验证建卡、控制会话归属和归档；修正 inbox、动态工具加载、UI 标签和流程图中的过时描述，并明确本机会话持久化不等于离线模型推理。

## 17. 契约完成定义

### 运行与调度的可靠性边界（2.30.2）

- 模型终态、增量 ACK、任务验收是三类独立证据。模型返回 `ok` 不得代替业务进展校验；有到期变化却没有任何确认进展时保留事件并指数退避，不得立即重放成功回执。
- 同一未确认运行只能按原 run ID 观察。自动注意力一次观察片结束后释放全局调度入口，让其他会话继续；不得取消原运行或把观察时间当作执行超时。同一会话仍禁止并发运行。
- 已确认的终态和最终结果持久化用于幂等返回，不复制提示和历史正文。Gateway 重启后，可按精确 run/session/turn 的原生结束证明恢复；会话最新消息或卡片 `running` 缓存不能作终态证明。
- 通常只有确认上轮终态后才允许为未消费事件分配新尝试 ID；保留退避计数，不将新尝试当成新任务。例外仅为控制轮已由 Gateway 明确确认不在运行，且原生轨迹、持久输入队列和 worker claim 均不存在：保留原回执为业务结果未知，发出同会话结果核对事件，不重放原命令、不直接完成任务。直接人工交代优先于普通积压，不保证绕过运行时容量限制立即完成。
- 宠物轮询只能使用只读 RPC 和共享快照，同一客户端合并在途请求，不得经 Agent 工具通道读取卡片或污染工具循环检测。
- 健康检查衡量 Gateway 响应，不衡量模型任务进度。短暂超时不能直接证明进程死亡；持续失去响应且复核失败才重启，必须记录原因、进程、探测耗时与可取得的退出码。
- 详见 [ADR-0034](decisions/0034-attention-progress-and-gateway-read-plane.md)。这些变更不增加语义主控、不改任务权威源、不扩大外发权限。

### 来源摄入与持续跟踪闭环（2.30.2）

- 个人源的本地身份状态是诊断信息，不得以一次验证命令失败阻止能够自行刷新凭据的真实只读调用。成功、失败、跳过必须分开，`lastSuccessAt` 只能在对应业务读取完整成功后更新；局部成功也不能掩盖该轮错误。
- 消息固定查询起止时间并持久化续页位置，每次只读一页；`has_more=true` 不得推进完整覆盖时间。重复页按来源身份幂等保存；短重叠窗口补偿索引延迟，但不保证召回无限期延迟的消息。全量补偿与快速轮询对同一数据库串行更新游标。
- 条件唤醒成功不等于条件已判断。关联具体 watch 和候选代次，确认该代次已被 `shadow_condition_resolve` 处理或已被新代次替换后才能完成投递责任；成功终答但未写结果必须退避再复核，未确认运行继续观察原 ID。
- 历史 failed/completed 但条件仍待判断的记录由同一可靠队列有界恢复；已完成或归档的父卡只核对并结束失效条件，不得自动重开卡片。Workboard 的 `metadata.archivedAt` 与原生归档列均须识别。
- 详见 [ADR-0035](decisions/0035-intake-and-review-recovery.md)。不改变任务责任判断，不新增模型主控，不将底层故障转成用户业务待办。

一次涉及 Shadow Agent 核心能力的工作只有同时满足以下条件才算完成：

- 角色与权威数据源没有漂移。
- 原始证据、任务结果和未验证边界均可追溯。
- 存储结构变化已完成备份、一次性迁移和旧接口清理。
- 权限和外部副作用符合本契约。

### 本地识别策略与冷启动配置（2026-10-22）

- 实际 ASR 输入含补音/重叠最长 35 秒，优先在20～30秒附近停顿处切分；不跨已知说话人边界，不把 unknown 标签当成同一个人。声纹和讲话时长只使用原始、不重复的语音片段。
- 强制切分的短重叠只服务文字衔接。没有逐字对齐时，正式正文采用核心转写，重叠转写作为同一 Evidence 的候选，不做字符串猜测删字、不另造消息。异常筛查不等于识别准确率验收；片段内部换人/抢话仍是既有能力缺口。
- Fun 在隔离 worker 中单并发、同录音复用、结束释放；不为安装或试跑修改系统驱动，默认保留桌面资源余量。用户明确要求强制实测时，仅该测试进程可跳过内存余量检查，回执必须公开此例外并记录真实占用，不改变长期默认配置。运行配置明确本地后备策略，无自动云上传。
- 用户选择语音来源后，既有冷启动计划创建一张 Agent 配置验收卡，按电脑条件和用户偏好准备运行环境并测试。复用原主控、Workboard及初始化幂等队列，不另造权限/任务调度体系。知识库保存偏好，运行配置保存引擎及路径，USER.md不维护第二套配置。
- 录音总长度与35秒窗口分开；长单文件有界读取，VAD 状态跨读取块连续，声纹和 ASR 使用原音频全局范围。读取块不定义说话人或语义边界；自然长录音与多人抢话质量仍需单独验收，不能以文件读完证明识别内容无损。

### 生成式语音识别限时与部分结果（2026-10-25）

- 生成式本机ASR以单次实际输入时长乘 `voice.asrTimeBudgetFactor` 设置单调时钟预算，默认2倍，可配置1至10倍；这是资源上限，不是失控/准确性判据。模型冷加载另计，35秒Fun输入限制不因此改变。用户已允许从最初1倍放宽，不能因正常语音稍慢就宣布模型异常。
- 父进程监督与worker token边界软停止同时存在。较短范围恢复共享原请求总截止，不能每次重试重新获得完整总预算。终止请求和实际进程退出/资源释放分别记录，不承诺操作系统精确毫秒释放。
- 超时或输出token触顶且无EOS时，保留已接收的原始文字及原音频范围、倍率、预算、耗时和停止原因；两种原因分别为 `audio_duration_deadline` / `output_token_limit`，后一种附实际token数与上限。`completion=partial`独立保存在原转写文件，不能作为完整转写Evidence或静音结论；已完成的其他段照常保留。没有词级对齐时不伪造部分文字的精确结束位置。
- 同次触顶不自动重识别/转后备，不以反复调用规避预算。刚好在最后一个token正常EOS不误标未完成。Fun当前单次至多35秒、输出512token；MOSS实验输出上限随时长增长，不套用所有录音统一512。作业接收完成与识别完成独立表达；重开/重放不丢部分文字、不自动重试。界面可分页展开“转写未完成”并区分时间/输出上限，不生成声纹/人物确认或任务事实。
- VAD先判断候选，增益仅作用于识别副本，默认峰值受限、最多12dB，可设0关闭；原录音、时间、声纹输入不变。不能用音量阈值直接断言无人声；无语音候选不启动生成式识别。前置增益尚不默认启用。
- 现有非生成式SenseVoice的执行机制不在本轮变更内。MOSS现作为显式`moss-local`选项接入共用队列和结果协议，不自动改变既有默认配置、不静默改用另一模型。两段中文多人输出已获用户“可用”确认，不外推到所有录音或真实人物匹配。源码可选不等于已切换正式后台，详见共用入口验证。

### MOSS共用语音输入（2026-10-25）

- 结果保留原时间轴和`sourceWindow`。全部属于前窗上下文的输出不重复发Evidence；跨核心边界的文字保留`contextOverlapMs`，无词级对齐时不按相似文本硬删。不得把短文件拼接控制说成自然长会议质量证明。
- 局部说话人标签及`acousticScope`均按MOSS窗口隔离。提取声纹时排除不同标签的重叠范围，使用未加增益的原音频；不足条件时保留未知。跨窗复用现有声纹关联，窗口内不同标签不自动折叠，同一编号跨窗不代表同一人；相似度候选不等于实名确认。
- MOSS沿用上游解析器，不以语义词表修正模型输出。解析器可忽略未闭合尾段，因此在关闭解析流前核对末段完整状态；未闭合时保存整段原始文字为`partial/invalid_model_output`，不得只发布可解析前缀并标完整。已触及时间/token上限的原停止原因优先保留。加载回执记录解析器指纹，升级上游必须重跑有效输出及截断反例。
- Windows停止ASR须停止本次启动的worker进程树，不能只结束虚拟环境启动器。截止、部分文字和进程退出分别核对。格式异常或运行失败用`invalid_model_output` / `worker_error`保留该范围及原始输出，前窗已完成结果仍可入库；未执行的后续范围明确标记，不伪造完整或静音结果。
- 所有完整段、部分结果、候选和人工修订仍沿原Evidence/Workboard链路。更换provider不更改身份权限、知识权威或默认自动登记规则；不重写原音频及既有标注。真实安装、手机传输回执与自动接管另行验收。

### 录音到达和标注纠错闭环（2026-10-22 后续）

- 接收目录使用显式启用及到达截止时间，不默认将旧录音全部作为新事件。手机完整包必须通过编号、前驱、SHA、采样数及录制时间连续性检查；缺包保留等待，失败持久重试。
- daemon 管理独立 intake 进程，统一调用 voice-input；电脑 capture-only 和手机接收只负责原音频，不允许另起第二条识别入库主链。停止 Agent 时停止其 intake/ASR 子进程树，离线增量保留。
- 托盘“声音与人物...”复用图谱 Person 和本机样本。确认/撤销原子追加修订证据、失效旧模板并通知主控职责重审；不得以 UI 点击成功直接完成任务或把声纹候选当授权。
- 界面分别表达转写、增量消费和任务验收。标注状态自动刷新，不伪报模型已经处理；未分辨/混合说话组不能整组认领。
- 手机暂不可测试。现有 NEAR 停录不证明 PC 已接管；本轮回放不证明无缝切换、手机锁屏后台录制或真实断连补传。不得通过隐式打开麦克风来补这个验收空缺。
- 实施边界见 [ADR-0042](decisions/0042-voice-intake-and-identity-review.md)、[操作说明](operations/local-voice-setup.md)、闭环测试。

### 已有录音接入与人工标注（2026-10-24）

- 历史补采须用户明确选择范围，保留原始录制时间、设备/录音/会话身份和音频 SHA。已有合法转写包直接复用，不因导入触发重新识别或上传。完整电脑片段的清单与手工导入采用同一录音身份；手机分包仍执行原完整性检查。
- 匿名声纹索引只提供跨文件声音候选，不等于人物。导入前验证索引仅含声学数据，目标已存在时不得覆盖用户标注；录音、转写、声纹及私人回执保留在本机忽略目录。
- 标注界面按全量录音分页，不能用最近50份或首200组冒充完整历史。显示录制时间、逐段文字和试听入口；整组确认与逐段纠错分开，未知/混合声音只能逐段确认。声纹登记仍须显式选择，不随改字或选人自动发生。
- 纠错通过现有 voice-input 追加 Evidence 修订，并进入同一源会话增量。由现有主控判断向知识维护和相关任务分别投递；不得在 UI 或导入脚本另写事实/卡片，知识 ACK 与任务 ACK 独立。源会话已消费不代表知识整理或任务完成。
- 可独立打开标注窗口，不启动 Agent、Gateway、intake、麦克风或 ASR。正式库导入使用已有 schema，不附带应用级迁移。后台暂停时只保存证据与待处理增量，不宣称 Agent 已理解历史内容。
- 文件校验、转写可读取、人工识别准确率和模型实际采用分别验收。历史 VAD 片段累计时长不是连续完整录音。接入范围与结果见历史语音接入验收。

### 声音标注推荐与候选重匹配（2026-10-24）

- 标注窗口默认“优先标注”，另提供“按人查看”和“全部录音”。推荐以已有任务关联、明确身份冲突、跨录音覆盖及可登记声学样本为依据，逐项说明原因；不把相似度冒充身份概率，不编造音质或业务价值分数，不调用大模型重新阅读所有录音来生成排序。
- 人物可以拥有多条人工登记样本和多个原匿名声音簇。人物层聚合展示不合并/删除音频、匿名簇或 Evidence；自动匹配与人工确认分别计数，自动匹配不冒充原文身份已确认，不训练新增声纹模板，不直接派生职责或执行授权。
- 重匹配是只读派生视图，由独立 worker 读取既有向量并缓存，不重跑 ASR、不上传、不写新的事实库。窗口首次后台加载，后续保存合并触发重算；未变化文件不重复解析、仅文字修订复用声学评分。手动刷新用于重新核对源文件与候选，无须重新转写。
- 候选排名按人物聚合多样本；不同模型/维度不比较。人工身份优先，混合/部分确认和明确冲突不自动整组认领，所有 unknown 不作为同一个人聚合。歧义保留，不能多数投票覆盖人工纠错。撤销/改人/停用样本后自动重算，旧计算版本不得覆盖新标注。
- 默认推荐可降低缺少声学特征且没有任务/冲突关联片段的优先级或不纳入推荐，但全部原件仍可访问。标注目标是补足有价值的身份信息，不是清空所有未人工确认记录。
- worker 不获写权限；显式确认、登记、撤销与改字仍由原 voice-input 事务追加修订并投递。派生视图更新本身不产生几千条伪人工修订或重复知识事件。测试分别证明数据不变、候选归组/撤销机制、UI行为及实际人工准确性，不能以计算耗时冒充识别正确率。
- 机制、真实历史只读耗时和隔离界面结果见声音标注推荐验收。
