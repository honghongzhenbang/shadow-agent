# 个人化与分发边界

## 哪些属于系统

`openclaw/workspace-template/AGENTS.md`、`COLLABORATION.md` 以及策略代码定义通用行为。这里不填写真实用户姓名、所属公司、职责或项目，也不把个人资料通过其他 Markdown 文件绕回主提示。

## 哪些属于用户

个人档案、职责、项目关系、偏好和工作简况进入各用户的私有资料与知识库。通过明确来源导入，回答具体问题时渐进检索。人工输入事实不是授予执行权限；授权仍走现有系统策略与 HITL。

资料可保存在不入 Git 的 `config/*.local.json` 或 `runtime/profiles/`。本仓库历史上有用户明确允许纳入私有 Git 的资料，这不等于允许公开发行。

团队导入示例见 OPERATIONS.md。保持同一档案的 `profile-id` 和输出路径，可沿用 Document 标识和原导入来源；新用户必须提供自己的档案和本人身份，不使用开发者资料初始化。

## 工作简况与冷启动

按照 [用户知识与冷启动](user-knowledge-onboarding.md) 操作。旧 `bootstrap-work-focus.mjs` 已停用，不再独立导入工作简况 JSON。新用户确认基本资料后进入通用图谱，已有用户绑定原本人实体；USER.md 只派生展示，人工修改进入同一知识维护流程。软件和资料范围必须询问用户，登录在安全授权入口完成。初始化任务走既有 Workboard，不在个人档案维护任务状态。

## 发布前核对

1. 当前仓库 `private=true`；不能直接公开 Git 仓库、历史或完整目录。`.gitignore` 不会抹掉已跟踪的私有档案。
2. 发行应从明确文件清单构建，不从本机目录全量压缩。排除 runtime、logs、数据库、凭据、`.local.json`、真实会话/评测数据、`docs/knowledge` 及包含内部人物、地址、项目的历史审计和测试夹具。
3. 只附合成示例。检查初始化脚本、入口配置和部署文档，确认没有开发者身份、真实 Evidence ID、固定公司关系或个人盘符默认值。
4. 在空目录、空数据库和另一份合成身份资料上验证安装、导入与查询；有代码测试通过不等于已验证完整公开发行包。

本轮完成通用策略与初始化入口整改，未制作或认证公开发行包，也未删除现有私有资产。
