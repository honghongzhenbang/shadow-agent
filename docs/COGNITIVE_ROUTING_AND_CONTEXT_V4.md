# 认知路由与渐进式上下文 V4

本文定义 Shadow Agent V4 的工作记忆、长期记忆和未知问题恢复机制。它受
[项目契约](PROJECT_CONTRACT.md)约束，并取代 `FEISHU_ATTENTION_V2.md` 中“每批变化新建短会话”的设计。

## 1. 目标

2026-10-22 源码修复：`shadow_context_resolve` 与 `shadow_context_query` 接受固定 `asOf` 和可选 `scopeKey`；返回事实保留作用域和有效区间，证据过期即时重新分类，不因旧 supported 缓存升级为事实。仓库路标保留 repoPath/版本元数据；短中文词和精确身份增加专门回归，不声明已经有语义向量召回。原文件实际主机读取和真实 Agent 配对收益尚需后续验收，见首批实现验证。

真实回放进一步发现 `query` 仍有独立的未排序种子入口，导致人员别名被历史会话挤出。现两工具共用 `findSeeds`，在有界候选集中保留完整名称/别名命中，先保留主词再截取中文二元词，业务实体候选不会只因历史会话更新更晚而被排除。名称命中只提供候选，不合并身份、不提升事实可信度；ID/规范键精确查询仍保持原身份。检索质量与耗时分别测量，不能用候选数上升宣称回答必然改善。

同日真实工具轨迹发现 Codex 的 developer 控制说明被旧采集逻辑标为 `codex_agent_message`，其普通英文词进入业务搜索。`shadow_evidence_search` 现仅在文本发现分支排除原始角色明确的 system/developer 控制消息；FTS 和 LIKE 共用过滤，精确 ID 回读继续可用。普通助手回复、未知角色、工具结果、协作消息不因该规则被排除。未删除原始资料、迁移历史分类或重建摘要，也不将此项收益计入语义排序；其他读取路径仍需单列调查。实施证据见融合验证及控制消息回归。

一级证据的领域筛选不是“代码类/聊天类”关键词分类。当前规范来源有 Codex、飞书和 Voice，直接采集的 Git 提交/项目文档没有 `source_observations` 行；附加 `execution` 会排除它们，即使正文含完整 SHA。工具说明已显式区分这些范围，工具日志需要按类型选择；精确 ID 也遵守传入范围。需要拓宽搜索时由调用者发起显式请求，不能在 SQL 中暗加 Git 例外。已用 4 个真实 SHA 请求验证该边界；补 Git adapter 和历史回填尚未实施。

2026-10-23来源审查：上述“精确ID可读”只限该工具支持的类型，不是所有图谱来源ID。digest/import/memory/index可能由实体返回却不能被primary搜索消费。实验新增单ID只读分页与显式summarizes链接入口，默认关闭且不改变primary过滤/事实状态；它不替代原件可达性和版本核验。DocumentSet仍存在末块覆盖检索线索的问题，文档级派生路标未实现，不能用补读工具掩盖入口缺口。参见验证边界。

Shadow Agent 不追求记住全部正文。它应当像可靠的长期工作人员一样，同时具备四种能力：

1. 记得少量稳定事实、决定、职责和当前承诺。
2. 知道更多信息在哪里，如何重新取得。
3. 知道谁负责什么、谁可能回答什么，以及通过哪个会话联系。
4. 不知道答案时仍能形成下一步求知计划，而不是永久阻塞或编造答案。

这对应四类状态：

| 状态 | 含义 | 规范存储 |
|---|---|---|
| Working memory | 当前讨论、当前目标和最近动作 | OpenClaw 稳定工作会话 |
| Episodic memory | 原始消息、文件片段、工具结果和执行经历 | Evidence Log |
| Semantic/metamemory | 稳定事实，以及“知识在哪里、谁知道” | 通用时序知识图谱 |
| Prospective memory | 待办、等待、提醒和下一步 | Workboard、condition watch、reminder |

## 2. 不是全文知识图谱

原始消息和普通日志默认只进入 Evidence Log 和全文索引。满足以下至少一项时，才应长期入图：

- 对象具有跨会话稳定身份，例如人员、团队、项目、产品、仓库、文档、接口、设备或外部系统。
- 关系会影响以后如何理解或查找工作，例如职责、依赖、维护人、代码位置、权威文档或联系渠道。
- 事实会在以后改变判断，例如决定、版本差异、已确认限制、现场结论或授权边界。
- 该材料本身是可靠的知识入口，例如仓库根目录、文档链接、搜索接口、群聊或负责人员。

常规上下文查询不对完整 Evidence Log 同步执行全局相关度排名。它先返回知识卡、局部图和已关联证据，再由 `shadow_context_resolve` 指向具体代码、文档、系统或会话读取原文；这样数据库规模不会线性进入每次思考延迟。

“收到一条消息”不是入图理由。“以后需要知道它在哪里或它改变了什么”才是。

## 3. 认知路由图

通用图谱同时保存事实和元知识。元知识回答的不是业务问题本身，而是如何取得答案。

### 3.1 可路由实体

| 类型 | 示例 | 作用 |
|---|---|---|
| KnowledgeTopic | 相机时间戳、机器人通信协议 | 连接问题、来源和专家 |
| InformationSource | Git 仓库、飞书文档、测试系统 | 表示可查询来源 |
| CodeLocation | 仓库、目录、文件、符号 | 指向源码位置 |
| CommunicationChannel | 飞书单聊、群聊、邮件 | 指向可联系入口 |
| Person / Team / Role | 同事、团队、岗位 | 表示职责和专长 |
| Procedure / Skill | 构建流程、审批流程 | 表示如何取得或验证信息 |
| QuestionPattern | “这个提交属于哪个任务” | 复用已验证的查询路径 |

这些是开放类型，不形成封闭业务枚举。

### 3.2 路由关系

| 关系 | 含义 |
|---|---|
| RESPONSIBLE_FOR | 某人、团队或角色对对象承担责任 |
| EXPERT_IN | 某主体对主题具有可求助专长，不等于正式责任人 |
| MAINTAINS | 主体持续维护代码、文档、系统或流程 |
| DOCUMENTED_IN | 主题或对象在哪个来源有说明 |
| IMPLEMENTED_IN | 功能、契约或主题在哪个代码位置实现 |
| DISCUSSED_IN | 主题通常在哪个会话讨论 |
| CONTACT_VIA | 主体可通过哪个工作渠道联系 |
| QUERY_VIA | 信息应通过哪个工具、接口或步骤查询 |
| CAN_ANSWER | 某来源或主体可回答某类问题 |
| FALLBACK_TO | 当前路径失败后可转向的后续路径 |

每条关系继续使用通用事实字段：证据、有效时间、观察时间、置信度、认知状态和人工确认标记。人员离职、职责调整、文档迁移和代码重构均通过时态修订维护，不覆盖历史。

人工认知资料按来源形成独立快照作用域。再次导入同一资料时，新增或保留的路标继续追加证据；从资料中移除且没有其他有效证据支持的关系转为 `superseded`，只由该资料支持且不再参与任何活动关系的实体转为 `inactive`。其他资料、代码检查或文档证据支持的同名事实不受影响。

## 4. 稳定工作会话

一次新消息不是一个新会话。按 [ADR-0033](decisions/0033-main-and-task-conversations.md)，业务上下文使用以下稳定边界；知识维护仍有独立内部会话，不是新的语义主控：

| 会话类型 | 稳定键 | 适用范围 |
|---|---|---|
| user | `agent:main:shadow:user` | 用户直接交代、询问和统一人工入口 |
| task | `agent:main:shadow:task:<card-id-hash>` | 每张任务卡独立持续推进，精确引用本卡和必要证据 |
| conversation | `provider + chat + thread/root` | 飞书等真实持续对话 |
| inbox | `agent:main:shadow:inbox` | 自动变化、项目证据和暂不能归类的跨域输入 |

外部群聊即使讨论多个项目，也先保持原会话连续性；知识图谱可以把消息、会话、任务、人员和多个项目保存为有证据、可修订的软关系，不把一段真实对话机械拆散，也不把会话主题直接当成任务归属。项目是知识与召回作用域，不是永久模型会话。任务卡仍是业务状态，不是第二份模型 transcript；它绑定独立稳定的任务控制会话，主对话只交接精确证据，不复制整段历史。

每个稳定边界保存 OpenClaw session key。达到上下文压力时由 OpenClaw 原生 compaction 压缩活动 transcript；Shadow 不自建代际或因业务数据变化轮换 Codex thread。原生压缩摘要至少保留：

- 当前目标和已确认决定。
- 未决问题、承诺、等待项和下一步。
- 相关人员、项目、任务和外部会话。
- 必须精确保留的提交、任务、文档和证据标识符。

完整旧 transcript 只读保留；检查点不是证据替代品。

## 5. 渐进式上下文

上下文按任务阶段展开，而不是按数据库表一次装入：

| 层级 | 内容 | 默认 |
|---|---|---|
| L0 | 用户身份、稳定职责、授权和红线 | 每个新会话代际一次 |
| L1 | 当前稳定会话检查点、活动目标和未决项 | 每个新会话代际一次 |
| L2 | 本轮新增消息、变化摘要和直接来源定位 | 每轮 |
| L3 | 本轮出现的人员、团队、职责和协作关系 | 按需 |
| L4 | 相关项目、任务、知识事实和认知路由 | 按需 |
| L5 | 原始正文、代码、diff、测试输出和执行工具 | 核验或执行时 |

OpenClaw Context Engine 负责 L0-L1 的一次性投影和会话压缩；本轮入口携带有界 L2。模型在出现具体歧义时通过上下文工具展开 L3-L5。工具能力也按任务阶段收窄：判断消息时不需要部署或设备控制工具，进入获准执行后才开放相应能力。

## 6. 未知问题恢复协议

Agent 不得把“知识库没有答案”直接转换为长期 `blocked`。它必须依次评估：

1. **Known**：已有高质量事实和证据，可以回答并标明范围。
2. **Retrievable**：图谱知道代码、文档、会话、接口或历史证据位置，先读取并核验。
3. **Searchable**：只有主题或项目范围，使用项目搜索、飞书搜索或已授权网页检索定位来源。
4. **Askable**：图谱知道责任人或专家，形成具体问题和需要的回答格式。
5. **Needs authority**：需要外部发送、审批、设备或敏感读取，向用户申请对应动作授权。
6. **Unresolved**：现有来源和人员均不足，向用户说明尝试记录、剩余不确定性和建议的最小下一步。

每次解析返回一个有序 Resolution Plan。候选步骤包含：目标、来源或人员、方法、依据、预估成本、所需权限、当前新鲜度和失败后的下一跳。模型负责结合当前任务选择，规则不直接宣布答案。

## 7. 向人员询问

向同事发送飞书属于外部写入，不因图谱显示“负责人”就自动获得发送权。默认流程为：

1. Agent 先完成本机和已授权只读来源查询，避免把可自行解决的问题抛给同事。
2. 生成短而具体的问题草稿，包含必要背景、已检查内容、希望获得的答案和时间要求。
3. 按 `config/policy.json` 请求一次发送确认；用户以后可以为明确人员、会话和问题范围授予长期授权。
4. 发送成功后，记录外部消息 ID，并在同一稳定工作会话创建 condition watch。
5. 回复到达后由原会话继续处理；等待状态不等于任务完成。
6. 超时后只提醒或选择下一条路由，不反复自动催问。

若回答形成可复用事实，保存回答证据并更新图谱；一次临时答复不自动升级为永久职责关系。

## 8. 注意力与任务准入

所有获准输入可以进入 Evidence Log，但只有以下结果进入工作执行层：

- 明确要求用户行动。
- 用户已作出承诺。
- 延续已有活动任务或稳定工作会话中的未决项。
- 需要用户作责任、授权或取舍决定。
- 对明确职责产生可验证风险或截止时间变化。

普通群聊背景、机器人播报和他人任务可更新认知路由，但不创建 Workboard 卡片。注意力判断在对应稳定会话中完成，不通过共享全局长会话，也不为每批消息创建新会话。

## 9. 成本边界

- 没有实质变化时不运行模型。
- 相同稳定会话续轮必须使用相同 session key。
- 工作区静态提示使用 continuation skip；`thread_bootstrap` 只含稳定控制协议，动态职责、任务、跟踪和关系不参与 epoch/fingerprint。
- 自动注意力每轮最多 4 个变化、每个变化最多 12 条最近证据，默认 12 KiB、硬上限 16 KiB；展开只回答一个具体歧义。
- 原始工具结果依靠 OpenClaw pruning；长会话依靠原生 compaction 和 transcript rotation。
- 不增加另一个常驻规划器或前置大模型。Context Engine 是同一 OpenClaw 主控的上下文能力。

## 10. 验收

V4 至少通过以下回放：

1. 同一飞书会话连续两批消息复用同一 session key。
2. 两个不同群聊不共享会话历史。
3. 同一项目的 Git 和文档变化保留项目候选键并进入 inbox；Agent 可建立多对多软关系，但不会创建永久项目会话。
4. 普通消息不自动成为图实体或 Workboard 卡片。
5. 已知代码位置时，未知问题返回源码查询路径。
6. 已知责任人但缺少答案时，返回询问草稿、授权要求和回复跟踪计划。
7. 所有路径失败时返回尝试记录和最小下一步，而不是编造答案。
8. 稳定会话续轮不重复注入全部工作区；修改职责、待处理数量或条件跟踪不会改变 bootstrap 指纹或轮换 Codex thread。
