# ADR-0015 真实数据优先的飞书评测

- 状态：接受
- 日期：2026-08-29
- 决策者：项目用户、Codex
- 关联契约：INV-03、INV-06、INV-17、INV-19、INV-37、INV-53、INV-56、INV-57
- 取代：无

## 背景

早期隔离回放证明了稳定会话和局部图谱能够运行，但 18 个批次的结构化响应成功不能证明任务归属、回复必要性和持续推进准确。固定条数切批还会混合话题，历史 API、实时事件、群提及、回复链和轮询补偿也没有被同一数据集覆盖。

项目需要一套能反复回答三个问题的评测方式：哪些外部变化应进入 Agent，进入后是否形成正确的用户动作，以及为得到结论消耗了多少上下文、工具调用、时间和 Token。

## 决定

1. 真实、已授权、用户可见的飞书消息是评测主体；采集只读，不下载资源，不启动生产 Agent，不执行外发或任务副作用。
2. 标识、凭据、敏感 URL 参数和资源键在首次落盘前脱敏；完整消息、人员名、模型输入输出和人工标签只保存在 Git 忽略的私有 runtime。
3. 使用 `reply_to/thread` 建立结构流，私聊默认以 4 小时、群聊默认以 2 小时无消息间隔形成 Episode，并受消息数和字节预算约束。Agent 仍可按精确会话键补取相邻窗口，Episode 不是永久业务边界。
4. 每个 Episode 分别审计是否适合触发路由、任务归属、回复草拟、持续会话或负样本；适用性规则不等于 gold label。
5. Episode ID 决定 development、validation 与 holdout，拆分稳定且不随提示词变化。抽样、人工复核和调优不得读取 holdout 正文；候选方案冻结后才运行盲测。
6. 模拟业务内容不计入真实准确率。重复投递、乱序、重启重放、实时事件与轮询重叠、瞬时失败重试等无法稳定从历史重现的运输故障，由真实 Episode 派生并标记为 synthetic transport。
7. 准确率按触发、结果责任、当前动作、回复需要和继续条件分别计算；链路成功、JSON 可解析、安全零副作用和 Token/延迟分别报告，禁止合成一个模糊总分。

## 备选方案

- **只用模拟数据**：覆盖方便，但无法证明真实群噪声、简称、上下文跳转和职责关系下的准确性，驳回。
- **把全部历史随机切块后交给模型**：样本量大但上下文混乱、成本失控、标签用途不清，驳回。
- **让被测模型同时生成 gold label**：只能形成候选，无法检测模型自己的系统性偏差，驳回。
- **所有消息先进入 Agent 再判断**：会把负样本成本和生产副作用混入评测，驳回。

## 影响

- 新增私有数据集采集、构建、适用性审计和抽样复核工具。
- 仓库增加匿名适用性报告；生产数据库、Workboard、OpenClaw 会话和飞书出站不变化。
- 后续注意力优化必须先在 development 发现问题，再经 validation 验证；holdout 结果决定是否可以宣称泛化改进。

## 数据迁移

既有 P2P 捕获和回放证据继续作为历史基线，不自动转换为 gold label。新数据使用 `shadow-agent/feishu-evaluation-*/v2` 模式；旧私有捕获不参与新基线，除非重新经过 v2 清洗和适用性审计。

## 回退方案

删除 v2 评测脚本和私有 runtime 数据即可回退，不影响生产状态。回退后仍保留既有 P2P 隔离回放；不得因此恢复“结构化响应成功即语义正确”的结论。

## 验证

- 数据集单元测试覆盖凭据、飞书 ID、敏感 URL 参数、回复关系、分段、用途判定和边界风险。
- `npm test` 必须通过。
- 真实抓取必须报告会话、消息、失败、覆盖模式和 Git 忽略证据。
- 适用性报告必须给出 development、validation、holdout 数量、用途门槛、真实覆盖缺口和模拟策略。
- 隔离回放必须证明 Workboard、提醒、外发和生产数据库写入为零。
