# ADR-0019 统一人工入口的持久回执与自动续送

- 状态：接受
- 日期：2026-08-31
- 适用版本：V4.14.0+
- 取代：ADR-0013 中“同步调用失败后由用户重新提交”的临时语义
- 规范依据：[项目契约](../PROJECT_CONTRACT.md)
- 补充：[ADR-0033](0033-main-and-task-conversations.md) 增加主对话到独立任务会话的可靠交接及完整回复展示；本文持久回执、离线续送和唯一 Workboard 状态规则不变。

## 背景

统一入口已经先保存用户原话 Evidence，但 Electron 仍同步等待 Gateway、模型和 Workboard 查询。Gateway 离线时界面只能报错，用户必须自己重提；界面关闭后也没有持久回复可供恢复。这既把长模型调用放进交互进程，又让“证据已保存”和“请求会继续执行”之间存在缺口。

## 决定

1. 每次人工输入在一个 Shadow SQLite 事务中创建原始 Evidence、唯一 `direct_input_receipts` 回执和 `process_direct_input` outbox 动作。事务提交后界面立即返回，不等待模型。
2. 回执是交互投递状态，不是任务或意图状态。它只保存稳定会话、幂等键、处理阶段、回复、关联卡、run ID 和错误；Workboard 继续拥有任务生命周期。
3. 后台始终在 `agent:main:shadow:user` 中处理。回执幂等键作为 Gateway run identity，首次 `started_at` 作为所有重试共同的历史下界；恢复不得改用新会话或新 run identity。
4. Gateway 等待失败后仍读取该轮新增助手回复。已有回复时保留结果；没有回复、卡片查询失败或进程中断时由既有 outbox 指数退避。相同 Evidence 的卡片按引用去重并绑定原人工会话。
5. 宠物从数据库快照读取最近回执。`queued / processing / retry` 显示仍在后台处理，`completed` 才显示回复或卡片，终态失败显示最后错误。界面不实现语义降级或本地关键词分类。

## 备选方案

- 继续同步等待：实现简单，但不能满足离线恢复和窗口重启后的可观测性。
- 建立独立消息队列服务：会复制现有 `controller_outbox` 的可靠投递职责，增加第二套恢复机制。
- Gateway 失败时用本地规则判断任务：会形成第二语义主控，违反单主控契约。

## 影响

- 新增 `direct_input_receipts` 表和一种 outbox action；不新增任务状态机。
- 用户提交延迟缩短为本地事务时间，模型耗时移到后台 lane。
- 同一稳定会话仍串行执行，避免人工输入与同会话其他轮次交叉。

## 数据迁移

SQLite 启动时以 `CREATE TABLE IF NOT EXISTS` 增量创建新表。历史 Evidence 不自动生成回执，避免把已处理原话重新执行；只有升级后的新输入进入可靠链路。

## 回退方案

可停止领取 `process_direct_input` 动作并回退应用代码；新表和已有回执保留只读审计，不删除、不重新解释。不得回退为“失败后自动用关键词建卡”。

## 验证

- 数据库单元测试覆盖成功回执、卡片归属、同一 run identity 重试和重启恢复。
- 宠物 E2E 覆盖已可靠接收、完成回执和 Gateway 离线后的自动重试提示。
- 契约测试校验 INV-62、ADR 索引和统一版本号。
