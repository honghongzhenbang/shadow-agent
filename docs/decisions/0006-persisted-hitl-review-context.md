# ADR-0006 持久化 HITL 审核上下文

- 状态：已接受
- 日期：2026-08-15
- 契约版本：2.3.0

## 背景

统一飞书出站链已经保证消息必须经过草稿、批准、可靠队列和回执，但 V4.2 的人工审核页面只拿到收件人、生成原因和拟发送正文。审核人不知道它在回复哪条消息、前面谈了什么，也无法判断正文是否答非所问。

审核时再临时查询整段飞书历史会产生三个问题：同一草稿在不同时间看到的材料不一致；长会话会让读取成本随历史增长；来源暂时不可用时草稿无法审核。

## 决定

`outbound_message_drafts` 增加 `review_context_json`，在草稿创建时保存版本化、有界的审核快照：

1. 当前触发消息单独保存。
2. 最近对话按发生时间保存，最多八条，区分收发方向。
3. 保存人工可读摘要、生成依据、来源定位、Evidence ID 和稳定 session key。
4. 实时飞书事件由事件桥直接生成快照；OpenClaw 主动草稿必须显式提供 `contextSummary`。
5. 旧草稿读取时可以从关联 Evidence 和 conversation key 有界回填；无法回填时明确显示上下文缺失。
6. 审核确认、自动批准、发送队列、发送身份和回执链不变。

## 备选方案

- 打开弹窗时查询完整飞书历史：拒绝。它不稳定、成本无界，并把审核可用性绑定到外部来源。
- 只保存一段模型摘要：拒绝。摘要可帮助理解，但不能替代触发消息和最近原话。
- 把上下文塞入 `metadata_json`：拒绝。审核上下文是规范数据，不应与内部审计事件混在一起。

## 迁移与回退

数据库采用幂等 `ALTER TABLE` 增列，旧记录默认 `{}`，不改写原始 Evidence。回退应用版本时新增列可保留，旧代码会忽略它；若删除该列必须先导出仍处于待确认状态的草稿。

## 结果

人工审核能稳定看到草稿产生时的必要对话，同时上下文大小与数据库历史规模解耦。未来切换 `automatic` 仍复用相同记录；自动模式可保留审核快照作为事后审计证据，不需要第二条发送链。
