# ADR-0039 通用策略与个人资料隔离

- 日期：2026-10-20
- 状态：已实现，补充 ADR-0038 的个人化边界。

## 问题

只删除一条业务背景不足以保证可复用性。本次审计发现：工作简况初始化写死职责和证据 ID；团队导入器写死本人姓名、组织标题和部门；核验脚本固定查询某个版本；示例数据可原样入库；默认 CLI 和执行器示例使用开发者盘符；通用策略从运行目录的偏好文件读取，可能再次把私人事实提升为主提示。

## 决策

1. **规则**：AGENTS 与 COLLABORATION 是代码版本化的通用行为规则。主策略只读取这些明确路径，不读取运行目录的个人偏好副本。旧副本归档保留，不自动入图或作为指令。
2. **资料**：个人职责、项目、同事与偏好通过私有 Evidence/知识图谱更新和检索。查询结果是有来源、可修订的资料，不授予权限；不得以没有发生的检索解释回答。
3. **导入**：团队 Markdown 格式显式声明来源、owner、profile ID；本人须在原文存在且不与“本人”标注冲突。部门从原文获取。工具不假装支持任意文档，不通过增加公司名正则扩展。
4. **初始化**：工作简况使用显式 JSON，默认只读验证；有现存证据且显式 apply 才写入。示例配置标记 exampleOnly，避免示例被当作真实个人知识。
5. **环境**：部署位置显式配置或 PATH 发现。运行配置应用必须使用 `loadConfig()` 的有效知识库路径，以及当前 OpenClaw state 下的 Workboard 路径，不硬编码回正式默认库。示例路径是占位符或项目内相对路径，不使用开发者真实盘符作为公共默认值。
6. **分发**：受控私有仓库与公开制品不同。此前允许进入 Git 的私人原文、结构化快照和评估不因本次修改被删除；发行时必须明确排除，不得公开完整 Git 历史。

## 不扩大的范围

不迁移正式知识库，不改任务归属、不重写历史会话、不实施尚未决定的上下文压缩方案。既有工作简况已经过后续整理，不执行新初始化覆盖。部门/人员格式解析仍是有明确输入格式的确定性适配，不冒充通用自然语言知识提取器。

## 验证要求

- 两份不同姓名、部门的合成档案独立生成正确归属；缺失或冲突 owner 拒绝。
- 初始化无输入不创建库，dry-run 不更新简况，未知 Evidence 拒绝 apply。
- 原样示例不能进入图谱。
- 运行配置应用后仅引用通用规则，旧本机偏好保留在历史目录，不进入主提示。
- 相同配置继续复用原有数据；部署与正式模型业务成功分别报告。
