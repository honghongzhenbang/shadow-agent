# ADR-0034 增量进展确认与 Gateway 读写职责分离

- 日期：2026-10-16
- 状态：已实现；部署与实测记录见同日故障复盘。

## 问题与证据

一次 `shadow_attention_packet` 因参数超限被拒绝；“只调用一次”的提示阻止模型自我修正。模型正常终答但没有 ACK，调度器把运行成功误认为变化已处理。同一批次生成相同 run ID，再读取同一终态，日志出现 6,188 次派发，并非 6,188 次新模型执行。

Gateway 重启后，其瞬态 wait 缓存不能证明旧运行结束；应用没有保存成功结果，又把已结束运行降级为未确认。单个全局注意力 Promise 持续等待，阻塞其他待办。另一条独立问题是宠物每 2.5 秒刷新详情调用 `workboard_read` Agent 工具，误触发工具循环检测；列表每 5 秒发起请求，没有在途合并。

首次 Gateway 退出没有持久原因日志，不能证明一定由健康检查杀死。已证实旧监督器在三次 3 秒探测失败后重启，故需改正证据不足的判定及缺失的观测。

## 决策

1. 运行回执记录确认的终态、最终答复与匿名指标，不存提示/历史。相同请求离线也能幂等返回，不再询问已确认的原运行。
2. 断线期间终态丢失时，只读原生 trajectory；必须同时匹配 run、session、turn 的成功结束与 model.completed，不凭附近的文本猜测。找不到证明则继续原运行观察。
3. 自动注意力每次最多等待一个观察片；pending 保留原 ID 和租约，30 秒后再观察，期间允许调度其他会话。运行本身没有新增总时限。
4. 保存本次事件范围，终态后查询该范围 ACK 进展。零进展退避 30 秒至 15 分钟；确认终态后的新尝试才使用新 ID。部分 ACK 后仅处理剩余变化，不代写 ACK，不代判任务完成。
5. 参数失败且尚未领取可纠正；成功领取一次后不能反复扩大数据包。工具 schema 的 4 条/16 KiB 上限不放宽。
6. 界面使用 `workboard.cards.list` 的共享只读快照，详情不再运行 Agent 工具；合并并发请求，短时缓存成功结果，失败不得用空列表覆盖缓存。
7. 连续健康失败达到次数与持续时长两个条件后，再作独立确认。默认持续 120 秒、复核 15 秒，含义是本地 HTTP 服务无响应，不是模型运行超时。监督日志轮转保留最近两份、单份约 1 MiB，避免无限积累。
8. `codex_session_read(include_turns=true)` 必须在脱敏前分页与限制输出。10:59 后原生完整读取两段约 16/35 MB 的本机会话，性能采样显示主线程绝大部分时间耗在工具结果脱敏，健康检查最终重启了进程。默认 2 轮/12 项/16 KiB，提供偏移继续读取；原始会话与权限不变。窄修补维护在仓库，由启动脚本校验部署；不改未知供应商布局，不禁用脱敏。
9. 本地数据库工具与 Context Engine 写入移到一个串行 worker。现场暂停采样捕获到 `searchKnowledge → resolveCognitiveRoute` 占住 Gateway 主线程；只修输出大小不足以保护服务。worker 不执行模型、不改变语义/权限、不自动重放未确认写入。上下文写入服务同时固定到与 Gateway 相同的内置 Node，避免全局 PATH 运行时漂移。

## 边界与代价

- 不推倒 OpenClaw，不新增调度主脑；这些是运输、确认和读面边界修复。
- 多个会话可以有未结束的原生运行，但每个会话最多一个；实际模型并发仍由运行时控制。
- 原生 SQLite 回退仅位于 OpenClaw 模块。运行时升级导致 schema 不匹配时返回未知，不擅自重做任务；相应金标必须随升级验证。
- 直接人工交代优先；大量连续人工交代可能推迟背景整理，后台公平性和 Agent 自主复查计划另行评估，本次不改成第二个规划器。
- 本次不清理原始证据、不迁移大数据库、不改权限或认证。

## 验证

覆盖无 ACK、部分 ACK、断线重启、完成回执离线重放、原生证明不匹配、长运行观察让出、同会话互斥、UI 并发合并及健康恢复日志。隔离 E2E 不接生产发送链路；生产验证需另记录精确任务和派发/ACK 证据。
