# ADR-0029 来源规范存储一次性切换

- 状态：接受
- 日期：2026-09-02
- 决策者：项目用户、Codex
- 关联契约：INV-73、INV-74、INV-75、INV-76、INV-77、INV-78
- 取代范围：ADR-0028 中“不迁移、长期通过只读视图兼容旧 Evidence”的数据迁移策略

## 背景

V4.22 用三个 SQL 视图验证了 Observation、Collaboration 和 Execution 的字段边界。生产库已有数十万条执行证据；每次查询从旧字段和 JSON 元数据推导规范结构，会重复解析且无法为全部领域字段建立直接索引。继续保留视图或双写会让验证结构变成永久兼容层。

## 决定

1. `evidence` 继续是唯一原始正文和来源定位载体，不复制消息、工具输出或源码。
2. `source_observations` 成为来源事件的唯一规范结构化接口；`collaboration_events` 和 `execution_events` 分别保存两个领域的专有字段。
3. 已注册 Provider Adapter 在 Evidence 写入事务内直接写对应规范记录。未知来源不依据 Evidence kind 猜测供应商。
4. 存量 Codex/飞书记录在一致性备份后一次性回填；迁移完成即删除三个旧视图、旧查询 API 和插件中的旧表引用，不设双写期。
5. 迁移保留 Evidence ID、指纹、正文、时间、`source_locator`、游标、Workboard、图谱与外部回执，不改变任务或知识权威源。
6. 第二供应商仍须通过增量、去重、断线恢复、历史补采、身份、线程和回源测试，但直接写同一规范结构，不再增加供应商兼容视图。

## 回退

切换前备份完整 SQLite。切换验证失败时停止运行组件并恢复整库备份；不通过重新启用旧视图形成长期双轨。

## 验证

- 根项目与插件测试覆盖直接写入、领域隔离、会话窗口和来源过滤。
- 迁移报告记录迁移前后数量、备份路径、遗留视图、孤立 Observation 和缺失领域记录。
- 生产库迁移后执行两类 `source-events` 查询，并确认旧视图不存在。
