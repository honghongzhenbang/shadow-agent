# ADR-0018 活动知识债务与冷库存分层治理

- 状态：接受
- 日期：2026-08-30
- 决策者：项目用户、Codex
- 关联契约：INV-03、INV-04、INV-06、INV-24、INV-26、INV-27、INV-29、INV-50、INV-60、INV-61
- 取代：ADR-0010 中“仅在空闲时顺序领取旧知识”的历史清仓假设

## 背景

V4.12 真实库审计报告 1911 个严格检查项，但它们不是 1911 条独立错误：16 条待图谱复核同时计入 enrichment，244 条为系统自动生成但没有证据评估的结构关系，其余主要是已具备临时召回卡的历史摘要。1650 条 pending 的 attempts 全为 0，证明依赖空闲 heartbeat 按 FIFO 每轮处理两条既不能及时学习人工反馈，也不适合消化历史库存。

进一步核对发现 17 条 `TRACKS_PROJECT` 仅由本机项目表生成。它表达的是可访问工作区，却容易被解释成用户职责；另外 6 条冒烟测试人工知识留在生产数据库。继续批量调用模型会增加成本和噪声，不能修复这些数据语义问题。

## 决定

1. 知识治理分为 `structural_route`、`active_review` 和 `cold_inventory`。三者继续使用同一通用图谱和 Evidence Log，不建立第二套知识库。
2. 项目表、线程表和采集器确定性生成的导航边标记为 `structural_route`，必须记录 source table/key；它们不进入 `verifiedFacts`、普通事实证据债务或待复核列表。
3. 用 `HAS_LOCAL_WORKSPACE` 表示当前用户在本机具有项目查询入口。旧的系统生成 `TRACKS_PROJECT` 结构边停用；只有职责档案、人工确认或明确工作证据才可创建责任/维护/跟踪关系。
4. 人工反馈、显式导入和当前外部任务属于 `active_review`。触发变化必须携带 Evidence ID，主控可用 `shadow_context_enrichment(evidenceIds=[...])` 精确领取并在同一稳定会话完成语义复核。
5. 已建立临时召回卡的旧 Codex、Git、仓库、文档和任务结果摘要转为 `cold_inventory`。它们保持可检索，不占活动门禁；命中查询、活动任务引用或人工指定时才原子晋升为 pending 并租用。
6. 审计同时报告严格检查项和唯一受影响对象，避免重复计数。冷库存、结构路由和活动债务分别统计；无来源结构边、普通事实缺证据、活动队列积压仍是严格失败。
7. 只有带确定测试生成器、测试标题和测试 locator 的数据可由治理迁移删除。执行前必须使用 SQLite 在线备份并通过 quick check，删除后检查引用与数据库完整性。

## 备选方案

- **继续每 15 分钟处理两条**：无法及时学习人工反馈，历史清仓需要过长时间，驳回。
- **一次性让模型处理全部历史**：Token、延迟和错误关系风险不可接受，驳回。
- **删除全部未精炼历史**：破坏可追溯性和后续按需查询，驳回。
- **把结构边伪装成 E1/E2 事实以通过审计**：制造虚假证据等级，驳回。

## 影响

- 严格审计数字会显著下降，但冷库存仍完整可见；下降来自语义分类正确，不是掩盖数据。
- 结构导航继续帮助定位仓库和项目，但不能参与任务归属结论。
- 人工反馈不再与数千条历史摘要竞争队列顺序。
- 插件工具兼容扩展 Evidence ID 精确领取，项目实现版本升至 V4.13.0。

## 数据迁移

迁移先备份主数据库，再删除严格匹配的冒烟 Evidence 及级联知识记录；将旧系统 `TRACKS_PROJECT` 结构边置为 superseded，建立 `HAS_LOCAL_WORKSPACE`；其余系统映射改为 `structural_route`；可检索的确定性历史 backfill 改为 `cold`。迁移幂等，不能修改人工事实正文或 Evidence ID。

## 回退方案

停止 Agent 后用迁移前 SQLite 备份整体恢复。代码回退时 `cold` 队列不会被旧租约查询选中，Evidence 和临时召回卡仍在；如需恢复旧行为，可在备份验证后把 cold 状态改回 pending，但不得恢复旧 `TRACKS_PROJECT` 职责语义。

## 验证

- 单元测试覆盖结构路由不进入已验证/待复核事实、精确 Evidence 晋升和冷库存不被 FIFO 领取。
- 迁移测试覆盖幂等、测试污染限定删除、旧关系停用、引用检查和统计不重复。
- 真实库迁移前后分别运行 `PRAGMA quick_check`、普通审计和 strict 审计，并保留备份 manifest。
- 隔离检索回归继续验证重复仓库不能推出开发目录或职责。
