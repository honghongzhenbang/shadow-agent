# ADR-0032 记忆检索与执行恢复可靠性

- 状态：接受；源码与隔离验证完成，未上线
- 日期：2026-10-15
- 关联契约：2.29.3
- 范围：通用知识路由、控制轮运输回执、原生执行观察、进度复核额度

## 决定

1. 知识路由以已迁移的规范列为准。复核完成和可信证据是不同维度，不读旧 metadata 状态兜底，也不把完成整理提升为可信。
2. 成功必须具备原生 `ok` 终态。人工输入和飞书对话还必须有最终可见回复；后台控制唤醒可接受运行时明确给出的 `terminalReply.disposition=silent`，但空白、缺失回复不能推断为静默成功。优先使用绑定 run 的 `terminalReply`；缺省时只在本轮时间窗口查找具有最终停止标记、无工具调用的助手回复。中间文字只供错误诊断。
3. 稳定请求的运输记录复用 `settings`。提交前记录请求身份，接受后保存原生 run ID；每个真实请求一条，不按重试次数复制，不存 prompt/transcript。每个未确认会话另有一个微小活动指针，调度只查询活动指针，不逐轮遍历历史回执；指针与回执在同一事务中更新。连接中断或接受回执丢失时只观察原 ID，不重新提交。终态记录仍保留旧请求幂等依据。
4. 不把长时间执行解释为失败。Codex continuation 自动获得缺省观察时间，模型也可明确指定；到期先只读查询原运行。存活回执仅延后复查，终态触发原任务验收，未知结果触发求证。探测期间卡片被用户更改则丢弃旧观察，不覆盖用户决定。
5. pending 复查不是实际运行。只有未过期 leased 复查占额度，同卡仍只保留一个待处理事件；租约过期后原事件继续可恢复，不自动 ACK。保留截止日期、置顶、优先级等现有评分，同分时先复查较久未检查的卡。已确认存活的执行保持原绑定，不能被通用 internal_review 覆盖。
6. 断线时不能释放仍可能被模型处理的注意力租约。恢复入口从持久运输回执寻找旧运行，不要求原增量仍未 ACK；暂停和巡检时间窗继续优先。长 outbox 执行续租，观察未确认不受普通十次失败上限影响。

## 不做什么

不增加主控、任务数据库、业务类型状态机或模型难度分类器；不扩大授权；不迁移历史知识；不把几个验收案例做成规则。工具协议合并与责任语义优化按原计划后续推进。

## 剩余边界

- 一个未知运行在原生运行时也无法查证时，安全策略是保留待核对并展示错误，而非自动重新执行。
- 已确认失败的旧请求不会偷偷重做。新语义决定可以检查部分副作用后继续工作；失败证明不代表工具副作用全部回滚。
- 本次没有并发化自动注意力或整个 outbox。健康但很长的主控轮仍会占用当前观察位置；真正长工程任务应由现有独立 Codex 子执行承担。
- 回执是按运行记录的少量元数据，不是新的摘要历史。当前保留幂等依据；后续清理必须先证明没有 outbox/人工回执/注意力依赖，不采用固定时间删除未知运行。
- 模拟 Gateway 证明运输与状态不变量，不证明真实模型责任判断、答案质量或长期无人值守效果。

## 验证与回退

验证覆盖规范状态生命周期、知识裁剪、失败中间回复、提交/等待断线、SQLite 重开、旧失败请求去重、租约续期、过期占位、原运行存活/终态、探测期间人工完成。详见 验证记录。

没有模式迁移，不需要复制正式巨量数据库。若部署后出现问题，停止消费、保留运行回执和原生运行 ID，按代码提交回退；不得清回执来强制重新执行。当前尚未部署，不宣称已完成真实业务验证。
