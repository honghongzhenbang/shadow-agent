# ADR-0040 用户知识投影与冷启动

- 日期：2026-10-21
- 状态：接受，实施与验收见关联运维文档
- 取代 ADR-0039 中独立写入工作简况的机制，不改变其隐私边界。

## 唯一权威

Evidence 保存输入与修订依据，通用图谱保存当前事实、冲突与来源；Workboard 保存任务状态，系统配置保存授权。`USER.md` 和工作简况都是同一个生成器的输出，不允许直接成为第二份知识库。模板只含通用行为，不含开发者身份。用户实体绑定是安装级指针，不复制姓名或职责。

投影条目必须指向当前用户相关的 Fact，显示 Fact/Evidence ID、作用域、有效期与可信度。模型可以选择相关事实的展示类别，不能另写一份脱离事实的职责正文。未知关系进入待整理，不根据同名猜本人；有争议、失效或缺证据的事实不进入可用简况。所有查询复用知识可信度规则。

## 更新与成本

采用读时生成的有界投影：索引查询本人相邻事实，再检查关联证据、冲突和时间，不扫描原始历史。内容指纹是修订标识，包含依赖内容；新增相关事实也参与计算。这样不用为每个图谱写入入口再造同步协议。超过候选上限显式报告覆盖缺口，不静默宣称完整。

后台定时刷新私有 `USER.md`；模型每轮从数据库取得最新有界投影，不信任磁盘旧正文，也不因此轮换原生 thread。提示中的资料明确是数据而不是指令/授权。文件写失败不影响图谱提交；下次重试。人工修改文件先作为知识修订 Evidence 进入既有维护队列，保留原文和基线；绝不把修改正文直接回灌为事实，生成内容也不重复采集。

## 冷启动

首次要求用户提供称呼、岗位/团队、负责与不负责的范围、第一个目标。允许明确填写“暂无排除项”，不把空值当已确认。先生成预览，用户确认内容指纹后才导入；不得由模型伪造用户确认。自然语言/文件可先整理为该预览，之后走相同入口。连接账号后独立绑定账号 ID；不要求先接通所有办公软件。

导入复用结构化认知资料 -> Evidence -> 通用 Fact；没有另一套 onboarding 事实库。首个目标是用户意图，不是任务状态，后续通过现有交代任务入口创建/跟进卡片。资料不足时允许问答、显式交办和本地工作，但不能从外部消息推断本人责任并自动建卡。权限仍由系统授权决定。

用户确认页同时列初始化任务计划。用户侧补充职责/协作关系、选择软件和范围、完成安全登录；Agent 侧按所选来源做有界文件/编程记忆/办公会话调查。确认后的计划原子写入现有 direct-input receipt/outbox，由主对话查重建 Workboard 关联卡、交给任务会话执行。不另建 onboarding 队列、任务状态或调度器。未连接的软件仅阻塞相关调查，不阻塞其他来源；计划入队不等于卡片已创建，receipt 和 Workboard 才是执行证明。

## 现有用户迁移

先备份、在副本验证；只接受唯一明确的档案本人标记或显式指定实体 ID，不按姓名模糊匹配。已有图谱事实继续使用，不重复导入整份资料。旧工作简况保存为待复核 Evidence，包括动态待办，但不升级为可信职责。删除旧简况表后所有读取走统一投影；多本人或缺失信息报告待确认项，不要求重新填写已知信息。

## 验收

空库预览不写库，确认幂等；错误指纹和缺必填项拒绝；相同确认不重复建实体；新增、撤销、反证、到期、其他用户修订与服务重启覆盖；人工文件修改不覆盖知识或丢失；旧数据迁移保留 Evidence/Fact ID；文件丢失可重建；旧独立写入口拒绝；上下文有界且 bootstrap 指纹不因个人知识变化轮换。真实库迁移不以模拟数据验收冒充完成。
