# ADR-0030 规范任务处理权与内部推进权限

- 状态：接受
- 日期：2026-09-02
- 决策者：项目维护者
- 关联契约：INV-02、INV-10、INV-34、INV-36、INV-63、INV-79

## 背景

Workboard 卡片状态、历史标签、备注中的“等待授权”和任务关注层 continuation 曾同时参与判断下一处理者。结果是部分 `todo` 卡显示为 Agent 待处理，详情却长期停在笼统的“等待用户授权”；过期或缺失的 condition watch 又会被进度审计跳过。Codex 子任务还会把自己看不到 Shadow 控制工具误报成人工阻塞。

## 决定

1. Workboard 继续是任务生命周期唯一来源；`work_task_attention.continuation_*` 是非终态任务下一处理者和下一触发的唯一来源。UI、审计器和 OpenClaw 共用同一个分类器，不再从标签、备注或 `todo/blocked` 状态猜测。
2. `requires_user` 必须携带结构化 `userAction`，原因只能是缺少具体输入、需要用户决策、受保护外部动作授权或现实验收。外部授权必须明确指出受保护动作。
3. 明确指派、用户直接交代或已确认卡片延续，授权 Agent 进行本地只读调查、工作区修改、测试和草稿。对外消息、外部文档写入、Git 提交/推送、部署/发布、设备控制、特权访问和破坏性操作仍受保护。
4. OpenClaw 控制层负责检查点、条件解析、变化确认和 Workboard 生命周期；Codex 子任务负责有界工程执行。子任务缺少 Shadow 控制工具不构成用户阻塞。
5. 缺失、模糊、过期或无效 continuation 统一转为到期的 `internal_review`，由有界进度审计重新规划；审计最多保留两个在途复核，不批量唤醒全部卡片。
6. 注意力调度优先处理高优先级人工操作、任务复核和条件结果；普通会话等待超过 15 分钟后进入同一优先桶并按到期时间处理，避免任务被消息积压阻塞，也避免普通消息饥饿。
7. 宠物只把已经取得 `task_progress_due` 租约或正在执行 Codex 的任务显示为“当前正在做”。尚未领取的内部复核留在同一 Workboard 待处理队列；绑定活动卡片的 condition candidate/timed_out 只作为该卡的触发证据展示，不再形成第二个“Agent 正在核对”区域。

## 备选方案

- 继续通过卡片标签和状态分栏：状态来源冲突，无法解释也无法可靠恢复，驳回。
- 所有阻塞都要求用户确认：会把内部调查权限误当外部授权，驳回。
- 旧状态逐步兼容：长期保留双重语义，驳回；采用一次性切换。

## 影响

- 宠物中的“需要你确认”只显示真实、可执行的用户动作；当前执行和待处理共用同一任务卡详情，条件触发不会复制任务。
- 原来模糊等待的任务会被重新交给 Agent 判断，但不会因此自动跨越任何外部副作用边界。
- 有效人工审核、未发送 HITL 草稿、未来有效 condition watch 和运行中的 Codex 执行保持原状态。

## 数据迁移

迁移前停止三个运行进程并一致性备份 Shadow 与 Workboard 数据库。一次性增加 `continuation_user_action_json`，把无效 continuation 改为到期 `internal_review`，写入 `taskHandling:version=1`，随后按新代码完整重启。不保留旧分类旁路。

## 回退方案

停止运行进程，恢复迁移目录中的两个数据库与迁移前代码，再重启。不得仅恢复一个数据库。

## 验证

- 单元测试覆盖结构化人工动作、旧模糊等待、有效/过期条件、执行状态和一次性迁移计划。
- 插件测试覆盖检查点字段与条件解决后的用户动作保留。
- 真实 dry-run 核对变化数量和原因；迁移后要求剩余非法状态为零。
- 重启后检查宠物分栏、OpenClaw/Context 在线状态及单卡有界恢复。
