# ADR-0035 来源摄入与判断结果恢复

日期：2026-10-17；验收更新：2026-10-18。状态：源码修复及正式后台授权、消息摄入已验证；历史窗口补采和全量业务结果仍待验收，见修复报告。

## 问题与责任边界

本次从正式任务和消息抽样定位以下缺陷，而非按任务标题批量改数据：

| 缺陷 | 所在层 | 处理 |
|---|---|---|
| 身份验证失败提前返回空 errors，采集仍显示成功 | 本项目采集/调度 | 身份本地诊断不作硬门；以真实读取结果记录成功、错误、跳过 |
| 只读一页却把覆盖时间更新为现在 | 本项目采集 | 固定窗口、持久分页、读完才推进覆盖；同库串行 |
| 已中断旧运行仍无限观察 | 本项目运行恢复 | 精确 run/session 的原生结束证明恢复失败终态 |
| 原生 wait 将未知 run 返回为 queue timeout | OpenClaw 运行接口 | 仅添加 `runKnown` 观察字段，不更改其执行或排队；可幂等、拒绝上游结构漂移的受控补丁 |
| 条件唤醒 action 完成，条件未判断；失败十次永久遗留 | 本项目可靠队列 | watch+generation 业务回执、未判断退避、历史队列恢复 |
| 通用卡片分类未识别 RPC 嵌套归档字段 | 本项目投影 | 补齐字段；现有桌面列表已正确过滤，不批量归档 |

## 决定

1. 保留 OpenClaw，保留唯一语义主控和 Workboard 权威。摄入、存储和可靠性属于确定性机制，不另起判断模型。
2. 消息每轮最多一页 50 条，重启从同一窗口下一页继续。末页才推进 `feishu.last_message_time`；新窗口保留 2 分钟重叠以减轻索引延迟。缺失分页结构、续页不前进或请求失败保留原位置并显示错误。
3. Gateway 显式 `runKnown=false` 不能单独证明业务失败。仅对 attention 控制轮，在确认原生轨迹、pending input、worker claim 均不存在后结束已丢失的执行观察，保留 `outcome=unknown`，发布同会话 `runtime_reconciliation_due`。Agent 先检查已有产物、回执和副作用，不能直接重做动作。人工输入及发送队列不适用此自动放行。
4. 无明确不存在证明、数据库读失败、运行仍排队或仍在执行时，保持同一 run。观察时间片不是模型截止时间。
5. 条件候选代次由状态、触发时刻、候选证据和超时时刻确定。同代投递幂等；终答未更新条件则 15 分钟后新语义尝试，运行 pending 不换执行 ID。旧失败/假完成记录在同一队列恢复，不另造提醒/卡片。
6. 恢复旧条件前核对父卡和后续证据，已结束的父卡不重开。业务判断仍由 Agent 处理，不写关闭任务的关键词规则。
7. 鉴权验收必须在后台实际运行身份和启动环境中进行。交互命令成功不能替代计划任务验证；凭据不可读时保留失败及覆盖位置，不复制明文凭据规避。

## 非目标与风险

- 不证明当前全部任务已经正确识别或完成；也不替代对真实工程工具能力的独立验收。
- 2 分钟重叠不是无限延迟补采保证；长延迟消息仍依赖补偿扫描。
- OpenClaw 原生扩展优先。受控源码补丁仅补接口缺陷，记录来源、测试和退出条件；上游提供等价运行存在性字段时移除，不维护平行调度器。当前补丁锚点不匹配则停止部署，不静默忽略。
- 不把全部历史塞给模型；继续按会话聚合和预算展开。恢复故障投递会消耗真实推理，必须检查是否得到结果，不能只看队列变动。

## 验证

覆盖鉴权诊断失败但业务可读、真实失败、跳过、两页续采、重复页、坏分页、精确中断终态、原生记录存在时不释放未知运行、运行丢失的单一核对事件、条件未写结果/继续跟踪/取消、失败重试、重复恢复和归档投影。实际运行结果见 修复报告。
