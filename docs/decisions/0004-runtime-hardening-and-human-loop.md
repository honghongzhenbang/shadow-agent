# ADR-0004 运行时收口与人工闭环

- 状态：接受
- 日期：2026-08-14
- 决策者：用户、Codex
- 关联契约：INV-01、INV-06、INV-10、INV-13、INV-19、INV-23、INV-25、INV-27
- 契约版本：2.1.0

## 背景

V4 已完成 OpenClaw 单主控、稳定会话和渐进上下文，但评审发现实现仍有四类偏差：普通机器人群消息可能误入独立模型会话；提醒可能在主控通知失败前过早记成已交付；待复核或过期知识可能混入“已知”；宠物缺少人工输入、精确健康状态和提醒维护入口。任务与审批配置了 15 分钟补偿，但守护进程没有实际调度。

## 决定

1. OpenClaw 继续作为唯一运行时底座，负责持久会话、工具、Cron、Workboard 和 Codex 执行；本项目不重写通用 Agent Runtime。
2. 自动注意力、机器人对话和人工输入共享按 `session_key` 串行的调度边界。普通未提及机器人的群消息只留证据和审计回执。
3. 外部事件回执增加处理租约、失败退避和重启恢复。任务、审批补偿轮询按配置真实运行；控制、外部采集、模型注意力和重型采集使用独立执行通道。
4. 提醒采用版本化状态机；主控通知成功前保持 `notification_pending`，修改和取消会废止旧动作并清理旧 Cron。
5. 查询结果区分已验证事实、待复核材料、冲突、路标和可询问人员。人工纠错只能追加新证据和取代链。
6. 宠物只提供“问、记、提醒”的轻量稳定会话入口以及任务、提醒反馈，不在 UI 内复制业务主控。

## 备选方案

- 替换 OpenClaw：会重新承担会话、Cron、工具和执行运行时，成本高且不能直接解决当前接入偏差，驳回。
- 在宠物内直接写知识或任务数据库：形成第二主控和第二套校验规则，驳回。
- 仅靠提示词要求不要误判：无法保证事件租约、提醒幂等和知识有效期，驳回。
- 引入向量数据库：当前 FTS、路标图和有界查询足够，不能解决可信生命周期，暂不采用。

## 数据迁移

- `reminders` 增加修订号和通知状态字段；旧记录原样保留并按旧状态映射。
- `external_event_receipts` 增加处理开始、下次尝试和更新时间；已完成和已忽略记录不重放。
- 原始 Evidence 不修改。知识修订只追加新 Evidence、`supersedes` 关系和事实状态传播。
- Workboard 卡片不迁移；宠物只改变读取与分组语义。

## 回退

代码可回退到 `v4.0.0`，但新增 Evidence 和审计记录不删除。新增 SQLite 列保持向后可忽略；回退前必须停止上下文服务并同时备份数据库 WAL/SHM 与 OpenClaw 状态。

## 验证

- 主项目单元与契约测试。
- OpenClaw 插件工具和知识状态测试。
- 真实 Gateway 工具清单与稳定会话烟雾测试。
- Electron 宠物 E2E、截图和点击审计。
- 失败事件、提醒通知失败、旧状态迁移和只读状态查询测试。
