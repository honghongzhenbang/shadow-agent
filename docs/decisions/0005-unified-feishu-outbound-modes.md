# ADR-0005 飞书统一出站模式

- 状态：接受
- 日期：2026-08-14
- 决策者：用户、Codex
- 关联契约：INV-10、INV-14、INV-18、INV-25、INV-28、INV-30
- 契约版本：2.2.0

## 背景

旧机器人事件链把单聊和群内明确提及直接交给 OpenClaw，再由事件桥发送；主动询问则计划使用待确认草稿。灰度测试要求全部消息先由用户确认，但正式阶段还要放开自动回复。如果为两种阶段各保留一条实现，会造成身份、幂等、回执、重试和回复跟踪语义漂移，也容易让未来自动回复绕过审计。

## 决定

1. 飞书回复与主动消息共用 `outbound_message_drafts -> controller_outbox -> lark-cli -> Evidence/condition watch` 链路。
2. `feishu.outboundMessages.mode=hitl` 是缺省和当前部署模式。OpenClaw 只能创建草稿，宠物负责修改、确认或取消；插件和渲染进程均没有直接发送能力。
3. `automatic` 只改变批准方式：事件桥仍创建同一种出站记录，但立即标记为已批准并进入同一个 outbox。当前仅允许 Shadow Agent 机器人单聊和群内明确提及的原会话回复。
4. 发送身份作为记录字段保存。机器人入口回复使用 `bot`，代表用户主动联系使用 `user`；批准模式、正文修订、发送回执和错误均保留审计。
5. 当前不使用联系人白名单或黑名单。未来若需要按联系人放权，必须作为独立策略变更评审，不能改变本 ADR 的单链路不变量。
6. 未经用户在宠物中确认，不使用真实联系人验证 `hitl` 发送；自动模式切换也必须是用户明确决定。
7. 上下文服务启动时先完成首轮采集，再启动事件桥恢复；事件桥必须先安装恢复定时器，首次恢复冲突只延后处理，不能让实时链永久失去恢复能力。

## 备选方案

- 保留旧自动回复旁路：实现简单，但会形成两套幂等、回执和权限语义，驳回。
- 仅靠提示词要求确认：模型或工具变更可绕过，不能保证发送前持久审计，驳回。
- 现在引入联系人黑白名单：灰度阶段没有必要，且会把“是否发送”和“如何发送”混在一起，驳回。
- 永久只支持 HITL：不能满足后续正式自动回复目标，驳回。

## 数据迁移

`outbound_message_drafts` 新增 `sender_identity` 和 `approval_mode`。已有草稿迁移为 `sender_identity=user`、`approval_mode=hitl`，保留原状态、正文和审计。旧外部事件回执不删除；未完成事件在新模式下恢复时只能生成草稿或统一 outbox 动作。

## 回退

回退前停止上下文服务并备份 SQLite、WAL/SHM 和 OpenClaw 状态。代码可回退，但新增列和出站 Evidence 只读保留。不得通过恢复旧直接发送旁路来处理待发送记录；需要暂停时保持 `hitl` 并停止上下文服务。

## 验证

- `hitl` 收到可处理消息时不直接调用模型发送工具。
- 草稿未确认和取消时均无发送动作；确认后只入队一次，正文修订可追溯。
- `automatic` 使用同一出站表和 outbox，并保持 `bot` 身份。
- 发送失败按相同修订和幂等键退避重试。
- 宠物 E2E 覆盖草稿展开、编辑、确认、取消和布局。
