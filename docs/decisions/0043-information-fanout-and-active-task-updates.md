# ADR-0043 同源双路处理与运行中信息更新

日期：2026-10-23。范围：既有 Evidence、context_changes、知识维护和任务会话之间的最小闭环。沿用 ADR-0026、0028、0034、0038；不是新主控或新知识库。Skill 进展汇报暂不实施。

## 决定

输入控制会话阅读来源原文和相关卡片后，分别判断知识价值与任务影响。`shadow_information_dispatch` 将同一 Evidence 引用投递给知识维护会话和零到多个活动任务；两路不互为前置。也允许只选择一路，或说明均不需要。程序负责完整性、持久投递和身份，不用关键词决定业务归属。

```text
来源证据 -> 输入会话作关联判断 -> 持久分发决定 -> 来源当前页 ACK
                                  |          |
                                  v          v
                              知识维护     任务所有者
                                  ^          |
                                  |     有新增内容的候选
                                  +----------+
                                  |
                              实质修订反馈 -> 相关活动任务复核
```

## 投递与消费

- 分发记录、独立接收事件与接收对象在同一事务保存。新来源批次 `evidence_batch_ingested` 的 ACK 必须有当前原文页的分发决定；既有任务交代和人工反馈仍走已有操作/学习链路，不重复套来源分发。不能以投递成功代替接收方读完。
- 每个接收方沿用自己的租约、原文分页和 ACK。知识先完成、任务先完成、半途重启均不能吞掉另一方事件。
- `information_dispatches` 保存路由决定及来源页；`information_deliveries` 只保存 Evidence ID、内容版本、接收方、用途和事件引用，不复制正文或图谱事实。新增表在写入入口显式初始化，读取不迁库。
- 精确重试复用回执；跨来源通知对相同证据版本、接收方和用途去重。不同任务、不同版本及新 Evidence 不互相去重。
- 正文已完成知识复核时，知识分支保存可追溯的满足证明，不重新制造 pending 复核。正在处理的租约不被重置。
- 同源语义新发现不是消息重投递：任务提交新的候选给维护会话。改变分发理由文字本身不代表新业务变化，也不反复唤醒同一已处理投递。
- 既有非活跃群背景筛选不扩大：只能对完整匹配、尚未领取且未分发的来源批次记 `background_policy`，明确 `agentReviewed=false`；不能清除消费者租约或包含其他证据的批次。飞书回复草稿成功不再代替来源审查。

## 知识回流

- 任务只提出候选，图谱写入仍由专用知识维护会话负责。任务摘要不是新的独立原始证据。
- `alreadyRepresentedFactIds` 引用由该候选原始来源支持的现有事实，避免再给任务摘要添加一份支持。身份、有效性与支持关系均由后端核验；同一来源的新声明仍可正常提出和维护。
- 实质复核版本由事实内容、范围、有效期、证据关系、有效可信判断等推导，不因摘要措辞、时间戳或可信缓存刷新而变化。相同复核重试和等价任务候选共用回执；A 到 B 再到 A 是新修订。
- 原始来源已关联的任务、原候选任务及维护会话明确给出的 `taskImpacts` 都可收到修订反馈，不向整个项目广播。所有路径读取 Workboard 活动状态；已完成或归档任务不因通知被重开。
- 复核、语义版本和反馈入队原子提交。目标状态读失败时保留可重试失败，不把知识写入成功冒充通知完成。
- ACK、复核 completed、事实 supported、任务 done 是不同含义，任何一个都不能替代其他结果。

## 运行中信息

普通 Gateway `chat.send` 返回 started 不证明原轮已采用。2026.8.1 本机 `agent` RPC 发起的运行实测中，普通 steer 及 `/steer` 消息排到了后续运行；原轮仍按旧计划行动。公开 SDK 的 `resolveActiveEmbeddedRunSessionId`、`queueAgentHarnessMessage` 在隔离探针中能把更新送进同一原生运行。

产品通知只携带有界待处理变化索引，按工具边界提示活动 Shadow 会话读取同一队列，不复制新原文进系统提示、不另起会话、不强行中断已经执行的工具。读取后由任务所有者决定是否调整计划，按既有检查点和 ACK 保存结果。运行时拒绝/离线时增量保持 pending，后续正常调度可恢复；不能把通知 queued 记成 adopted。

通知只能送到已绑定的活动 Shadow 会话。用户自行使用的 Codex 会话仍只读；工程子执行器也不能替代任务所有者判断影响。当前控制轮采用、通知工程子运行、子运行实际改变行为必须分别验证；公开 SDK 的单运行探针不证明所有第三方执行器都支持实时修正。没有安全、已验证的子运行更新入口时，应报告能力缺口并保留原运行，不重复启动执行器。

运行钩子的原生 session 身份与解析结果必须一致；同一原生 session 内运行交替的最后瞬间仍由运行时队列控制，当前公开接口不能原子校验 expected run。队列返回 true 也不等于异步投递成功。因此提示保持中性、无授权且不 ACK；后续持久消费及实际动作才是采用证明。当前查询限制返回条数，但大量 pending 行下仍有排序开销，不宣称常数时间。

插件安装只复制所需共享模块。任务所有者与绑定持久 SQL 从应用模块提取为轻依赖公共函数，旧入口委托同一实现，避免运行时插件反向加载整个应用数据库。隔离安装测试验证导入闭包，不运行正式安装器。

## 时间与授权

发生时间、获知时间和事实生效时间继续区分。录音晚到不会自动覆盖较晚飞书决定；缺少可靠时间时结合版本和明确撤回依据判断，证据不足保留冲突。内容、人物标签、知识反馈和通知均不新增操作授权。

## 验证与发布

自动测试覆盖双路先后互换、独立分页/ACK、租约冲突、原子回滚、重试/重启、已完成知识、同源复述、新声明、语义往返修订、终态卡和原始来源审查。真实运行至少 high，分别保存原运行身份、更新时刻、接收回执与实际下一动作。

详细实测与限制见 验证报告。源码提交不等于正式生效：本轮不重放正式队列、不治理正式知识库、不启动后台或宠物、不发送消息。既有检索投影、历史治理 M2/M3、子执行器联动与长期 G1 灰度仍单列，不以单次机制探针代表整体业务准确率。
