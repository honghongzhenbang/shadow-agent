# ADR-0009 面向结果的持续推进与责任归属

- 状态：接受
- 日期：2026-08-25
- 决策者：用户、Codex
- 关联契约：INV-19、INV-28、INV-33、INV-34、INV-36、INV-37、INV-38、INV-39
- 契约版本：2.8.0

## 背景

系统能够把飞书消息聚合到稳定会话，也能用条件跟踪等待回复，但仍出现了两类结果偏差。

第一类是责任归属错误。群聊中“示例人员18”汇报华沿适配结论并明确提及示例人员11，后续示例人员11要求出测试报告。采集层正确记录了发送人、被提及人员和 `explicit_other_mention` / `unassigned_group`，主控却把业务相关性误当作用户的结果责任，创建了 `user_work` 卡片，并根据示例人员18的后续交付关闭该卡。精确身份信号存在，但没有在任务决策中形成足够强的正向归属要求。

第二类是跟踪不等于推进。对外问题收到部分回复后，主控可以只调用 `shadow_condition_resolve(continue)` 恢复原跟踪，不记录该回复确认了什么、剩余目标是什么、下一步由谁做以及什么事件会再次唤醒。系统因此看似在线，实际没有朝任务验收结果移动。

## 决定

1. 将“业务相关性”和“用户结果责任”分开判断。相关性只决定是否保留为背景、依赖或检索线索；创建或激活 `user_work` 必须存在正向归属依据。
2. 正向归属依据限于：当前用户被明确指派或提及、当前用户本人形成承诺、权威任务字段指向当前用户、用户明确接手，或消息明确延续一张已经确认归属的活动卡。群聊未指派、明确指派他人、同业务领域、姓名相近和关键词相似都不是正向依据。
3. 人员身份以稳定 ID 和采集层 `sentBySelf` / `mentionsSelf` 为准。名称只用于展示；不得用模糊姓名匹配推断“这是用户本人”。
4. 他人的任务和交付可以成为用户任务的依赖、风险或背景证据，但不得创建、推进或关闭用户任务。若确实阻塞用户已有目标，只更新该目标的依赖关系。
5. Agent 主动发起且期望回复的问题必须绑定现有 Workboard 目标。出站草稿、发送回执和回复 condition watch 沿用同一 `task_id`；无目标的普通通知可以独立存在。
6. 条件候选是新事实，不是任务结果。主控先回到父任务的目标和验收标准，判断候选解决了哪一部分，再优先查询可用代码、文档、任务和会话证据。
7. `continue` 必须同时持久化一个结构化 continuation。允许的类型为内部行动、Codex 执行、外发草稿、提醒、带未来复查时间的被动等待或明确等待用户；只有文字备注不算推进。
8. 条件详情必须返回有界候选证据正文和身份元数据，使主控与宠物都能看见“谁说了什么”，不能只返回 Evidence ID。
9. 用户纠正职责归属时，继续复用统一人工反馈知识 Episode 和 Agent 操作协议：先记录纠正证据，再可靠评论/证明并归档误分类卡，最后唤醒归属会话学习。不得直接改 Workboard 或图谱数据库。

## 备选方案

- 只按 `explicit_other_mention` 硬拦截所有群消息：拒绝。其他人的消息可能是用户已有任务的重要依赖，硬拦截会让 Agent 失去工作上下文。
- 继续依赖提示词自由判断：拒绝。现有事故表明身份字段虽存在，但软提示不足以稳定区分相关性与责任。
- 为回复跟踪建立独立任务系统：拒绝。它会与 Workboard 争夺任务权威，并把发送、等待和业务目标拆成多套状态。
- 收到部分回复后一律再次追问：拒绝。正确动作可能是查代码、核文档、推进 Codex、等待明确事件或请求用户决定，追问不是通用结果。

## 影响

- 注意力包增加发送人、稳定自身份判断和被提及人员等有界字段。
- 主动问题草稿增加 `task_id`，发送后创建的回复跟踪继承该任务。
- 条件决议增加结构化 continuation 和审计历史；旧的无 continuation `continue` 调用会被拒绝。
- 运行工作区规则明确禁止姓名近似归属，并要求先确认结果责任再创建任务。
- Workboard 仍是唯一任务源；条件、草稿、知识图谱和宠物不获得任务状态权。

## 数据迁移

- `outbound_message_drafts` 新增可空 `task_id`。已有草稿保持为空，不反向猜测任务归属。
- `condition_watches` 不新增第二状态表；continuation 与语义复核历史保存在现有 `metadata_json`。
- 已存在但缺少 `task_id` 的跟踪继续可读；再次执行 `continue` 时必须补充结构化 continuation。
- 已确认误分类的卡片通过统一 Agent 操作归档，历史事件、评论和原始证据保留。

## 回退方案

回退插件、上下文服务和工作区规则到 V4.6，并停止创建带 `task_id` 的新草稿。新增列和 metadata 保留但不读取；不得删除历史纠正 Episode 或恢复已确认误分类卡。回退只恢复旧调用兼容，不改变用户已经作出的职责判断。

## 验证

- 注意力包测试验证精确发送人、自身份和被提及人员可见。
- 契约测试验证业务相关性不等于结果责任、姓名相近不得归属。
- 插件测试验证主动问题缺少 `task_id` 时失败，发送后的 condition watch 继承任务。
- 条件测试验证候选正文可读、无 continuation 的 `continue` 失败、结构化 continuation 可持久化并保留复核历史。
- Agent 操作测试验证误分类卡只归档一次，并保留评论、证明和知识 Episode。
- 部署后读取真实卡片、插件工具目录和运行日志，确认没有第二任务源或直接数据库修复旁路。
