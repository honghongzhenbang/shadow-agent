# ADR-0010 事件优先与有界进度审计

- 状态：接受；项目 `workstream` 控制归属已被 ADR-0014 取代
- 被部分取代：ADR-0014
- 日期：2026-08-25
- 决策者：用户、Codex
- 关联契约：INV-01、INV-06、INV-17、INV-22、INV-36、INV-39、INV-40、INV-41
- 契约版本：2.9.0

## 背景

实时采集和条件检查持续运行，但系统仍可能表现为“只等不推进”。精确飞书会话中的图片回复因不含创建跟踪时的关键词被跳过，证据游标仍前移；关联任务因此看不到真实变化。另一方面，活动 Workboard 卡只有在外部事件、执行回调或人工操作到达时才会再次唤醒。历史卡片若没有留下有效继续条件，会永久停留在 `todo` 或 `blocked`。

直接恢复周期 Heartbeat 或把全部活动卡交给模型，会重新引入大上下文、重复推理和第二规划循环。完全依赖事件也无法修复已经缺少触发器的孤儿任务。

## 决定

1. 任务推进采用“事件优先、有界进度审计兜底”。实时事件、执行回调、条件候选和提醒仍是主路径。
2. 精确会话、外部 ID、线程和来源前缀是候选的结构边界。边界内的关键词只作主控提示，不是硬门槛；图片、附件或不同措辞也必须形成候选。
3. 从旧候选算法升级时，每条活动跟踪只在自身基线与当前游标之间执行一次有限回放，排除来源证据和已复核候选，并记录选择器版本。正常运行仍只扫描新证据。
4. 与 Workboard 任务关联的结果跟踪必须有未来复查时间。未显式提供时写入 120 分钟内部兜底；该时间不是业务截止时间。
5. 新增确定性任务进度审计。它只读取活动卡、`work_task_attention`、执行状态和条件跟踪索引，跳过仍有未来触发的卡片；按结果价值排序，每轮最多投递一张 `task_progress_due`。只要任一进度复查仍为 pending/leased，全局不再投递下一张。
6. `task_progress_due` 绑定精确 `taskId` 和唯一控制会话。OpenClaw 读取该卡及其局部来源，核对是否变化并推进一个低风险动作；若仍等待，必须记录检查依据、预期事件和新的未来复查时间。
7. 本地采集、飞书快速轮询、条件/任务审计和可靠出站分别使用独立 SQLite 连接，并在各自 lane 内串行。SQLite WAL 协调短写事务；模型调用继续按稳定会话串行，不阻塞消息轮询，也不获得第二任务源。

## 备选方案

- 恢复固定 Heartbeat 扫描全部任务：拒绝。它把无变化本身变成模型调用，成本随任务数量增长。
- 条件继续使用关键词硬过滤：拒绝。图片、附件和自然语言变化会被永久漏掉。
- 本地脚本直接改变任务状态：拒绝。它会成为第二语义主控，且无法理解验收结果。
- 每张卡建立独立 Agent 会话：拒绝。任务仍按已有 conversation/workstream/inbox 控制会话归属，审计只投递单卡变化。

## 影响

- 条件候选数量可能略增，但只发生在精确范围内，且由同一主控语义确认。
- 没有继续条件的旧活动卡会逐张进入复查，而不是长期沉默；默认每 5 分钟最多投递一张。
- `work_task_attention` 增加内部复查、进度事件和 continuation 引用字段，不复制 Workboard 状态。
- 每个 lane 内仍然串行，消除同连接事务重入；lane 间使用独立连接，使全量采集和长模型唤醒不阻塞飞书消息轮询。

## 数据迁移

- 数据库启动迁移自动增加 `next_review_at`、`last_progress_requested_at`、`last_progress_event_key`、`progress_revision`、`continuation_kind` 和 `continuation_reference_id`。
- 旧活动任务不改状态；首次审计按现有优先级逐张建立复查事件。
- 旧活动条件记录候选选择器版本并进行一次有界恢复。已经复核过的候选不会重复提交。

## 回退方案

关闭 `taskSupervision.enabled` 可停止新增任务复查事件；条件选择器恢复旧实现时应保留已产生候选和复核历史。新增列可以闲置但不得删除。回退不得重启全量 Heartbeat 或直接修改 Workboard 状态。

## 验证

- 精确跟踪会话中的图片消息可形成候选，其他会话仍不匹配。
- 旧游标漏检证据只恢复一次，已复核证据不重复。
- 任务结果跟踪自动获得未来复查时间。
- 有有效未来条件的卡片不被审计；缺少触发器的卡片只产生一条幂等 `task_progress_due`。
- 守护进程状态任务最大并发为一；全量单元测试、运行时 doctor 和真实漏检回放通过。
