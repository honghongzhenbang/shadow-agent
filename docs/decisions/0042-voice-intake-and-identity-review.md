# ADR-0042 录音到达队列与人物标注闭环

日期：2026-10-22。状态：已实现，验收层级见对应报告；10月24日已核对手机实机状态，物理传输与切换仍未验收。

## 一条业务链

```text
电脑 capture-only / 手机接收器 retain-audio
  -> 本机已完成录音清单
  -> voice_inbox_jobs 持久队列
  -> 同一 voice-input 本地识别与音频归档
  -> Evidence + Collaboration + 完整证据交付游标
  -> 原主控 attention / 会话 / Workboard / 知识维护
```

`voice-intake` 是文件传输与 ASR 执行进程，不是第二个 Agent。由现有 daemon 启停和恢复，独立连接数据库，不占主控事件循环进行识别。人物窗口也是同一库的受限操作入口，不维护另一套通讯录、任务或知识状态。

## 到达与恢复

- 显式配置来源目录及 `since` 到达截止时间。首次接入不自动补扫全部历史；离线录音的原始 `recordedAt` 保留，不用文件到达时间冒充事件时间。
- 电脑 VAD 片段可独立入队。手机 package 必须收到 final、连续编号及正确前驱才能组包；缺包只等待，不消耗 ASR 重试。身份、SHA、PCM 格式、采样数和时间连续性不符保留错误，不静默拼接。
- 按 device/package 幂等，只将音频流式拼到磁盘，不将数小时 PCM 展开到内存。最长 12 小时、最大 2 GiB；逐段保留原始录音 ID、时间、SHA 与采样数。35 秒识别窗口仍由 ADR-0041 管理，不能用传输包边界替代。
- 队列保留租约、尝试次数、退避时间和录音 ID。退出后到期租约可恢复；完成转写不重复写 Evidence。持续缺失的文件、配置错误和坏包明确可查。
- 主进程退出时停止其 intake 进程树；意外失去父进程也停止 CPU/GPU 子进程。原始录音不由 intake 删除。日志轮转，仅保留当前和上一份。
- 5 秒发现文件/标注变化；随后沿用既有 attention 合并、运行时段、暂停与容量规则。不是收到文件 5 秒内必然得到模型结论，也不绕过用户暂停。

## 人物与纠错

托盘“声音与人物...”提供声音分组、局部试听、已有 Person 选择、新建人物、确认、声纹登记和撤销。渲染端不接收模型向量或任意文件访问权限。声音相似性只是候选，不自动确认实名，不将声音认同本人转换为执行授权。

人工确认/撤销追加修订 Evidence、停用失效模板，并通过原 context_changes 请求职责重审。版本 token 防止过期页面覆盖较新标注；原始证据不删除。完成 ACK 仅代表该批信息已处理，任务完成仍由既有验收语义决定。

界面显示待复核/处理中/增量已处理，每 5 秒只读刷新当前状态。未知说话人和已包含多个人物的组不能整组绑定；逐片段处理沿用 `voice-input.mjs label --segment`，尚不宣称能自动分离段内换人或抢话。

## 部署与证明边界

新电脑采集器仅产出音频，不再自行跑另一条 SenseVoice 入库链。旧手机接收器应使用 `--no-transcribe --retain-audio`，接收目录加入 intake，禁止同时启用旧直接入库。配对凭据留在原接收器，不迁入主控或源码。

本轮不启动麦克风、不导入历史录音、不替换手机 APK。现有手机 NEAR 事件停止录音，不包含 PC 麦克风就绪确认；因此不能宣称已实现或验收无缝自动接管。后续要单独验证/补充接管握手、断连重传和双端重叠，不能靠文件回放替代。两个设备重叠音频保留为两个观察，不按时间相近擅自去重。

验收分为：协议/存储、真实本地 ASR、Electron 点击、真实主控语义、手机物理切换。前一层成功不能代替后一层。测试全用隔离库；模拟人物/消息不可进入正式图谱。

## 2026-10-24：明确授权的历史接入

用户随后要求接入原采集会话的真实音频、转写和声纹候选用于人工标注。该授权覆盖选定历史录音的 Evidence 导入，不包含恢复正式 Agent 或替换手机。上节“不导入历史录音”为10月22日当轮范围，保留其历史证明边界。

历史导入只复用原始包，不重跑 ASR；完整电脑清单保留原录音身份以与自动 intake 幂等。匿名声学索引可在空目标上复制，不能覆盖现有标注或导入另一套人员知识。声音列表改为全量分页，增加逐段文字/人物修订，继续使用同一修订 Evidence 和知识/任务双路投递，不引入新维护会话。单独标注窗口不唤醒后台。见接入验收。

## 2026-10-24：减少重复标注

用户确认增加缓存后的自动重匹配、按人物聚合、代表片段推荐和撤销重算。采用纯计算匹配模块 + 只读缓存worker + 原标注事务，不增加数据库状态维度或第二个知识维护器。

首次读取转写特征在worker中进行；后续样本变更只计算余弦候选，按人物取多个样本的最佳匹配并检查次优人物差距。声学计算结果按样本版本与源特征缓存，文件变化/新增/撤销可失效。评分仅作候选；同一匿名声音的人工身份冲突必须保留，不能被自动匹配或多数样本压掉。窗口关闭释放worker，重开从正式标注重建派生视图。

默认推荐按真实关联任务、身份歧义/冲突、覆盖的不同录音以及有效语音样本排序，并选择未确认的代表片段。未知短片段不擅自合并成一个声音；没有声学样本、任务或冲突价值时只保留在完整浏览，不以待确认总数作为用户工作量。全部录音与单条来源保持可读。

人工确认和自动匹配在人物详情中分开；保存只作用于当前录音组/片段。候选重排不改 Evidence、Person、事实或任务。若后台知识与任务需要确认说话人，仍经原证据修订和主控判断，不能把显示归组直接写成可信知识。业务价值优先使用已有任务投递关联，不新增昂贵的全量语义评级。

## 2026-10-24：试听不等于声纹登记

取消前8秒试听限制。组入口播放完整原录音（包含其他说话人的上下文），文字段入口播放该段的完整时间范围。界面提供进度定位、暂停和继续；每次后端读取最多2MiB、播放块目标30秒，按采样帧计算续播位置，不能把分块读取误说成最多只听30秒。保留归档根目录、文件类型、路径与IPC来源校验；允许未知/混合组试听，不放松其整组确认和声纹登记限制。

一个转写段包含多个人时，原文仍是观察输入，不因缺少人名丢弃。当前逐段修改不能在段内再划分说话时间或重新提取单人特征；自动重分离和人工划分时间范围属于未实现缺口。不要把多人段标成同一人或拿聚合embedding当作其中一人的声音模板。既有错误标注应由用户撤销，不自动删除用户已经保存的样本。
