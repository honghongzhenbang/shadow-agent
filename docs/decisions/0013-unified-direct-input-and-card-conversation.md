# ADR-0013 统一直接输入与卡片跟进

- 状态：接受；项目 `workstream` 控制归属已被 ADR-0014 取代，同步投递语义已被 ADR-0019 取代
- 被部分取代：ADR-0014、ADR-0019、[ADR-0033](0033-main-and-task-conversations.md)。下文共享任务控制会话与弹出式继续交代是历史设计，不再适用。
- 日期：2026-08-28
- 适用版本：V4.9.0+
- 规范依据：[项目契约](../PROJECT_CONTRACT.md)

## 背景

宠物首页原有“问一下、记下来、设提醒”三个并列模式。用户若要明确交给 Agent 一项工作，只能猜测应选哪个模式；继续增加“交任务”会把语义分类责任交给用户，并使入口和后端分支持续增长。与此同时，任务详情已有可靠操作事件和控制会话归属，但“补充下一步”的文案只覆盖一种表达，无法自然承载询问进展、纠正方向或停止任务。

## 决定

1. 首页只保留一个“告诉 Agent”自然语言入口。原话先写入统一 Evidence/Episode，再交给独立稳定的 `agent:main:shadow:user` 人工会话，由唯一 OpenClaw 主控判断问题、知识、提醒或任务。后台巡检保留在 `agent:main:shadow:inbox`，避免自动工作噪声和压缩失败影响用户交代。
2. 用户明确要求 Agent 完成、推进、制作、核查或持续负责的工作，构成正向任务归属证据。主控优先更新同一目标的活动卡；没有时使用 `workboard_create` 创建唯一规范卡并立即推进一个获准的低风险步骤。新卡必须在本次入口返回成功前把 `work_task_attention.owner_session_key` 绑定到 `agent:main:shadow:user`，不能因缺少项目或外部会话路由而落入后台 inbox。
3. 一次性问题和普通讨论不创建卡片。前端不使用关键词、按钮模式或本地分类器决定业务语义。
4. 任务详情使用“继续交代”作为卡片内通用消息入口。消息通过统一 Agent 操作协议保存 Episode、操作标识、Workboard 评论和控制会话唤醒；Agent 在原卡中回答或改变后续计划。
5. Workboard 卡是人可见的任务对话和状态载体，不等于独立模型会话。控制会话继续按来源 conversation、项目 workstream 或 inbox 复用；只有明确独立工作才创建关联卡。

## 后果

- 用户不再为 Agent 预判意图，也不需要第四个按钮。
- 所有明确任务都会在 Workboard 中获得可见状态、证据和后续触发。
- 卡片内的人机往来可持续追踪，但不会让模型会话数量随卡片线性增长。
- 统一入口的同步调用失败时，原始 Evidence 仍保留；界面明确显示失败，不启用关键词降级。
- 网关应先接收运行、等待终态，再读取人工会话新增回复；正文已完成但收尾压缩失败时，不得把已完成动作误报为未执行。
- 原生 Codex runtime 无法可靠搜索延迟动态工具时，白名单内 Shadow/Workboard 工具必须直接装载；不能让新会话依赖旧会话工具缓存。

## 验收

- 首页不存在输入模式标签，问题和任务使用同一提交 API。
- 明确任务的模型提示要求去重创建/续接 Workboard 卡，并返回卡片标题与 ID。
- 新建卡的控制归属必须是 `agent:main:shadow:user`，真实冒烟同时验证建卡、归属和归档。
- 卡片内消息产生 `interpret_task_message` 变化并在执行/证据页可见。
- 项目契约、运行工作区、E2E 和实际 Gateway 配置同步更新。
