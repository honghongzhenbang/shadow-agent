# ADR-0036 长期委托、独立执行器与原生能力扩展

- 日期：2026-10-18
- 状态：接受，按下述分界实施和验收
- 依据：用户确认自主推进、按需生长、本机优先，以及先设计契约再实现测试。
- 取代：`proposals/2026-09-04-external-capability-boundary.md` 中要求把所有外部业务封装成统一语义接口的设想；不取代现有来源规范、知识治理和 HITL。

## 1. 要解决的实际问题

用户交代一个结果后，不应继续承担拆步骤、找工具和反复催进度的工作。系统需要自己调查、实验、制作缺失工具、验证并推进，同时不能把“多运行模型”“更多卡片”当成成果。当前实现的主要缺口是运行配置把主控和编程模型绑在一起，重复应用模板会覆盖扩展技能，以及能力接入缺少可复验、可撤回的发布手续。

本次不重写 OpenClaw，不另造插件市场、MCP 客户端、规划器、任务库或记忆库。

## 2. 边界

| 层 | 职责 | 新需求是否修改核心 |
|---|---|---|
| 记忆与推进内核 | 证据、冲突修订、注意力、唯一卡片、检查点、回执和授权 | 改变这些语义时才修改 |
| OpenClaw 运行时 | 模型调用、稳定会话、工具调用、压缩、原生子任务 | 配置模型和运行时，不另包一层模型代理 |
| 编程执行器 | 接收有界任务、改代码、测试、返回结果；不决定主卡状态 | 可独立选择 Codex 模型，不继承主控的 API 模型 |
| 能力扩展 | 原生 MCP、CLI + Skill、工作区 Skill、必要的原生插件 | 通常配置或独立扩展代码；不在主控添加钉钉/邮箱/禅道分支 |
| 来源接入 | 增量游标、消息/执行证据、事件去重和身份 | 需要持续摄入时实现现有来源接口；工具能调用不等于已实时监听 |

保留应用名、原生资源标识和能力说明，允许主控使用原生业务工具。统一的是证据定位、授权、任务关联、执行结果和失败恢复，不是强迫所有应用变成同一种聊天或表格接口。

## 3. 长期委托

长期研究与普通交付共用 Workboard 卡片、任务稳定会话和检查点。主控在卡片中维护目标、验收、授权范围、当前假设/证据、下一项可执行实验、停止/复核条件。每轮只提交有界动作和可观察的后续触发，不为每个实验复制主任务。

用户交代研究方向才启动对应委托；允许主控针对现有目标提出改进或补工具，但不为了显得活跃自建无关研究。近期输入、截止日期、风险和预期减少的人工工作共同决定优先级。时间到期仅唤醒复核，具体查什么、何时再查由主控决定。无人回复时可继续其他获准动作；权限或现实条件不足时提出明确需求。

不增加第二个周期性“反思 Agent”。原生 Skill Workshop 的后台自动整理保持关闭，自主修复先生成提案。成功结果仍走现有知识差量、专用维护会话、冲突处理路径。

实现使用现有 `work_task_attention.progress_plan_json`，随 `shadow_task_checkpoint` 原子保存有版本的行动判断，不复制 Workboard 生命周期。`shadow_context_focus(taskId)` 精确读取；下一次注意力包只注入该卡片的简版。修改旧版本会被拒绝，方案不得产生新授权。提供 `learning` 和原始 Evidence 时，同一事务调用原有知识差量入口；查重、可信度和冲突仍由知识维护会话决定。未提交 learning 不自动假装已学习。

## 4. 模型与执行器分离

运行配置显式声明 `controller` 和 `codingWorker` 的模型及 `agentRuntime`。主控可走原生 Codex，也可走 OpenClaw 内置 API 运行时；编程子任务有独立默认模型。相同模型引用不能同时要求两个不同 runtime，必须使用不同模型引用或供应商别名。

模型供应商地址、协议、鉴权继续由 OpenClaw 原生配置管理。不复制账号凭据，不接受扩展提案改变主控授权。切换不迁移 Workboard、知识库或来源游标。进行中的任务保持原执行绑定，切换后的新轮次重新验证工具调用、压缩与结果回写，不能承诺两种 runtime 的缓存、成本和推理质量相同。

## 5. 能力生长闭环

1. 用户目标或当前卡片暴露能力缺口。主控先搜索已有工具/Skill，记录缺口和验收，不能仅凭工具名认定缺失。
2. 优先复用可信厂商 MCP/CLI；没有现成能力时，交给当前卡片的 Codex 子任务在独立工作区实现和测试。
3. Skill 使用本机 OpenClaw Skill Workshop 的提案、扫描、哈希绑定和恢复机制。不得覆写用户手写或系统 Skill。
4. MCP 候选使用原生 `mcp.servers` 定义，独立配置中做真实 `mcp probe`。只允许明确列出的工具，凭据使用环境/SecretRef；不把服务声明的 `readOnlyHint` 当成授权。
5. 发布前核对候选哈希、测试时间、配置是否被别人修改。发布记录只证明配置安装，不冒充 Gateway 已加载或业务成功。原生发送能力不能绕开现有 HITL；默认新接入仅安装为禁用状态，启用和授权必须显式执行。
6. 发布后的新轮次验证实际工具可见性，再用只读或沙箱业务样例验收。真实写入须已有授权。回执、错误、下一步留在原卡。
7. 撤回只还原本次接入的配置项；遇到后续人工修改拒绝覆盖。保留凭据配置、其他能力、卡片和证据。

## 6. 本轮交付与非目标

本轮交付持久行动方案及有界恢复、检查点和知识差量原子提交、独立模型/执行器配置、原生 Skill Workshop 接入、带隔离探测和哈希校验的 MCP 安装/撤回脚本、长期委托规则与测试。默认模型不切换；不替用户注册第三方账号，也不安装未知生产 MCP。

不宣称已经做到任意软件全自动接入、无限自我进化或无人审核对外行动。新应用的认证、特殊协议、摄入/事件语义以及真实写入验收仍需要具体接入任务。核心自修改只允许独立分支、测试、审查和受控部署，不允许运行中的主控直接改自己的安全边界。

## 7. 验收

- 模板重应用不丢失原生 MCP、供应商和额外技能/工具配置，且禁止扩展提升已有 deny。
- 主控换成 API 模型时编程子任务仍指向 Codex；无账号凭据的场景只称配置验证通过。
- 本机固定 OpenClaw 版本对隔离模拟 MCP 完成真实协议连接和工具发现；配置发布、过期探测、配置冲突、撤回均有测试。
- 新能力未经业务验证不显示为业务可用；失败不影响现有业务连接。
- 原有任务、知识、人工输入、HITL、宠物端到端测试保持通过。
- 后续运行评估统计人工介入次数、有效交付率、误归属/错误关闭率、每次有效进展成本和延迟，而不是累计任务数量。

## 8. 技术依据

以仓库固定 OpenClaw 2026.8.1 的 `docs/tools/skill-workshop.md`、`docs/cli/mcp.md`、`docs/concepts/agent-runtimes.md` 和 `docs/tools/subagents.md` 为实施依据。版本升级时重新验证，不把网站最新版能力当成本机已经具备。
