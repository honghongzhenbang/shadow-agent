# ADR-0012 用户提醒与内部任务复查分流

- 状态：接受
- 日期：2026-08-25
- 决策者：用户、Codex
- 关联契约：INV-15、INV-22、INV-36、INV-41、INV-44
- 契约版本：2.9.3

## 背景

V4.8 已用 `work_task_attention.next_review_at` 和有界 `task_progress_due` 管理活动任务的内部复查，但主控规则仍把“未来复查时间”表述为 reminder continuation。OpenClaw 因此又调用 `shadow_reminder_create`，把内部检查点显示给用户并创建 Cron；模型每轮采用不同标题或幂等键时，同一任务同一时间还会出现重复提醒。

## 决定

1. 用户提醒与内部任务复查是两个不同语义面，但复用现有数据结构，不新增任务系统。
2. `reminders` 和 Reminder Cron 只承载需要通知用户的事项，包括用户明确要求的提醒，以及有明确时间、行动主体、来源依据和可定位证据的推导提醒。
3. Agent 内部复查只写入 `work_task_attention.next_review_at`，由既有有界进度审计到期后产生 `task_progress_due`；不得进入宠物提醒列表。
4. `shadow_reminder_create` 对推导提醒执行代码级来源校验。绑定任务的提醒按 `task_id + due_at` 形成规范幂等键，不接受模型通过改标题或自定义键制造同一时刻的第二条提醒。
5. 现存误建内部提醒先把到期时间迁回对应任务关注记录，再取消 Reminder Cron。历史 reminder 行保留为已取消审计，不删除。

## 备选方案

- 仅在宠物中隐藏 `explicit=0`：拒绝。这样 Cron 和重复数据仍存在，也会继续唤醒主控。
- 新建第二套内部定时器：拒绝。V4.8 已有任务关注层和有界审计，重复实现会增加状态分裂。
- 只修改提示词：拒绝。提示词能修正语义选择，但无法硬性阻止同任务同时间重复写入。

## 影响

提醒列表只显示用户应当看到和处理的通知；普通任务复查不会打扰用户。活动任务仍会由原有审计自动复查，不因清理提醒而失去继续条件。

## 数据迁移

迁移只处理已确认属于内部复查、绑定 Workboard 卡且由 Agent 推导的活动提醒。每张卡保留最早的未来复查时间，随后通过原取消链路清理 Cron；不删除提醒历史，不改变 Workboard 状态。

## 回退方案

回退工具校验和规则时仍保留已迁移的 `work_task_attention.next_review_at`。不得把已取消历史提醒批量恢复为活动 Cron；如确需用户通知，应以明确来源重新创建。

## 验证

- 缺少来源依据的推导提醒被工具拒绝。
- 同一任务同一到期时间即使标题和模型幂等键变化也只生成一条。
- 内部复查迁移后，活动提醒和 Cron 不再包含这些检查点，任务关注层仍保留未来复查时间。
