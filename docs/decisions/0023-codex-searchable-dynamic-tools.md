# ADR-0023 Codex 动态工具按需搜索

- 状态：已取代
- 日期：2026-08-31
- 决策者：项目维护者
- 关联契约：INV-53、INV-55、INV-66、INV-67
- 取代：V4.9 中全量 `direct` 动态工具装载决定
- 被取代：ADR-0024
- 适用版本：V4.18.0+

## 背景

旧版 Codex harness 的延迟工具搜索不稳定，项目因此把允许列表中的 Shadow、Workboard、提醒和会话工具全部以 `direct` 方式注入首轮。当前随仓库部署的 OpenClaw 已把 `searchable` 作为 Codex 动态工具默认模式，并保留少量调度工具直接可用。生产指标显示，一个只有 200 字且不调用工具的全新隔离轮仍消耗约 3.17 万输入 Token，主要成本来自固定运行上下文而非业务提示。

## 决定

1. 保留现有 `minimal + alsoAllow` 能力与授权列表，但把 `codexDynamicToolsLoading` 改为 `searchable`。
2. Codex 使用原生工具搜索按需发现动态工具；不得通过 shell、脚本文件或提示词复制工具协议来绕过搜索。
3. 每次部署该配置后，以全新隔离会话搜索并调用只读 `shadow_context_status`。测试必须验证真实工具调用、可见回复和匿名运行指标均存在。
4. `direct` 只作为当前 runtime 已有失败证据时的临时兼容回退。回退记录必须包含版本、失败证据、影响和退出条件。
5. 工具加载模式不改变业务能力、唯一主控、工具白名单、HITL 或外部副作用授权。

## 备选方案

- 继续全量直接注入：拒绝。工具数量增长会持续扩大每轮固定上下文，即使任务完全不使用这些工具。
- 删除低频工具：拒绝。当前问题是装配方式，不是 Agent 能力过多。
- 自建工具路由模型：拒绝。Codex harness 已提供原生搜索，增加模型会形成新的成本和故障层。
- 为每类任务建立固定工具会话：拒绝。会把工具选择固化为新的会话拓扑，并削弱主控的灵活判断。

## 影响

- 全新控制轮不再常驻全部动态工具定义，固定输入 Token 应明显下降。
- 第一次使用某个动态工具会多一次搜索步骤，工具总调用数可能小幅增加。
- 工具说明质量会直接影响搜索命中，因此代表性冒烟是部署门禁。

## 数据迁移

无需迁移 Evidence、图谱、Workboard、会话或任务。应用运行配置并重启 Gateway 后，新建会话使用新模式；既有 Codex 线程如保留旧工具上下文，可自然压缩或在明确维护时重建，不批量删除历史。

## 回退方案

把模板临时恢复为 `direct`，重新应用配置并重启 Gateway。回退不得修改白名单或任务数据，并必须登记导致搜索失败的 OpenClaw/Codex 版本和复现命令。

## 验证

- 契约测试校验模板为 `searchable`。
- 全新隔离会话真实调用 `shadow_context_status`，且不产生写入副作用。
- 无工具冒烟对比切换前后的输入 Token、工具调用和耗时。
- 主项目、插件、Gateway 集成和宠物 E2E 全部通过。

2026-08-31 初始灰度中，旧 `direct` 全新无工具轮为 31,742 输入 Token、约 45 秒；`searchable` 全新无工具轮为 19,397 输入 Token、7,936 缓存读取、约 23 秒，非缓存输入下降约 39%。另一全新隔离轮通过搜索真实调用一次 `shadow_context_status`，记录 800 输入 Token、30,464 缓存读取且无写副作用。数据用于确认装配方向，不作为永久性能承诺。
