# ADR-0026 统一知识差量与专用维护会话

- 状态：接受
- 日期：2026-09-01
- 决策者：项目用户、Codex
- 关联契约：INV-26、INV-61、INV-69

## 背景

人工输入已经能生成可检索知识 Episode，但通常只追加新卡；问题解决后的可靠结论也没有统一的后处理入口。让原任务直接改图谱会扩大上下文、混合执行与治理责任，并容易重复新增或覆盖旧知识。

## 决定

增加统一的两阶段知识维护协议：

1. 原始会话只追加不可变 Evidence。人工输入使用 `manual_knowledge`；已解决任务调用一次 `shadow_knowledge_delta_capture`，保存紧凑结论、候选长期知识、来源 Evidence/locator 和幂等键。
2. 两类 Evidence 都产生精确知识复核变化，并路由到唯一稳定 `knowledge-curation` 会话；知识差量 Evidence 不再产生普通证据批次唤醒，首次路由后不再滑动延后执行时间。
3. 维护会话禁止再次调用 capture/delta/revise 产生递归 Evidence；它先按本条 Evidence 的关键词、检索提示和来源有界查询现有知识，再选择合并支持、新增、修订/取代、`no_durable_facts` 或 `needs_followup`。
4. 图谱修订保留旧 Evidence。新事实可以通过 `supersedesFactId` 关闭旧事实有效期；不原地改写或删除历史。
5. 版本化源码或一级证据直接支持的技术事实可由维护会话完成候选写入。职责、身份、偏好、权限、承诺和未解决冲突需要明确人工确认。
6. 人工输入与任务差量复用同一知识作用域 schema；该作用域贯穿 capture、revision、annotation 和事实证据评估。Annotation 未显式传 scope 时继承原 Episode 范围，而不是清空。事实来源字段固定为 `sourceEvidenceIds`，证据方法使用受控枚举，使证据等级可重复计算。

运行配置的 Shadow 工具允许列表以插件 `contracts.tools` 为单一能力来源，模板只能添加基础工具，不能静默遗漏插件工具。`doctor` 必须报告缺失工具名称。

## 备选方案

- 每个任务直接写图谱：上下文和权限边界混杂，拒绝。
- 只定时扫描待复核队列：人工输入反馈慢，且容易回到 FIFO 清仓，拒绝。
- 为人工输入和任务结果建立两套维护器：产生重复规则和分支状态，拒绝。
- 自动覆盖同键旧事实：破坏时序和证据审计，拒绝。

## 影响

- 增加 `shadow_knowledge_delta_capture`、两类知识变化和一个稳定维护 workstream。
- 人工输入会立即形成复核事件，不再依赖离线治理脚本补发。
- 人工输入不是机械新增：维护会话先查现有事实，可通过 `supersedesFactId` 取代旧事实，并保留旧事实和旧 Evidence 的历史。
- 任务回答保持轻量，图谱查重和更新延后到独立控制轮。
- 维护会话仍属于同一 OpenClaw 主控，不增加控制器进程。

## 数据迁移

旧人工 Episode 和冷库存保持原样；已有治理脚本仍可为历史待复核项补发事件。新输入从本版本开始即时进入统一链路，不批量重放历史。

## 回退方案

禁用差量工具和知识变化路由即可停止新维护轮；已写 Evidence 继续可检索且不会丢失。不得删除已经创建的证据或事实历史。

## 验证

- 单元测试验证人工输入和任务结果均生成精确复核事件。
- 单元测试验证差量幂等、来源绑定且原任务不直接增加图谱事实。
- 路由测试验证两类变化复用同一稳定维护会话。
- 部署测试验证插件契约工具全部进入生产允许列表，`doctor` 无缺失项。
- 集成测试先证明目标知识未预填，再观察差量事件、维护结果和维护后的召回变化。
